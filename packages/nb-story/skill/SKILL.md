# 用 nbstory 回答小说剧情问题

`nbstory` 是剧情图谱的命令行：书库里每本书是一份自动抽取的小说记忆图（人物、称呼、身份、说法、知情、情节、数值、悬念、时间、原文），所有查询都能按“读到哪里”只给到那个位置为止的内容。

## 怎么跑

装了 npm 包 `@notnotype/nb-story`（要 Bun）后，`nbstory` 就在 PATH 上：

```bash
nbstory <命令> [参数] [选项]
```

从仓库运行时把 `nbstory` 换成 `bun <仓库>/packages/nb-story/src/cli.ts`。

先用 `nbstory books` 确认书库里有哪些书；不止一本时，每条命令都加 `--book <书 id>`。书库不在默认位置时加 `--library <目录>`。要拿结构化结果加 `--json`（输出 `{"ok": true, "data": …}` 或 `{"ok": false, "error": {"code", "message"}}`）。全部命令见 [references/commands.md](references/commands.md)。

## 先问读到哪里

- 用户说了读到哪里，**所有命令都带同一个 `--at`**（`38` 表示读完第 38 章，`38.57` 表示读到第 38 章第 57 段），答案不提及那之后的任何内容。
- 用户没说时，回答前先问一句读到哪里；用户说读完了、或不在乎剧透时，才不带 `--at`。

## 答题步骤

1. **查清对象**：用 `nbstory find <名字>` 查问题里每个人物的全部称呼与“同一身份”（化名、变身后的代号）。名字或称呼对应不止一个对象时，命令会列出候选，改用 id。
2. **按题型找线索**：
   - 谁知道什么、身份有没有暴露：`knows`（秘密矩阵）、`knowledge <对象>`、`relations --perspective <对象>`；
   - 人物之间的关系：`ties <对象>`（他和每个对象的关系一览）、`between <对象> <另一个>`（两人之间的全部说法、一起出场的情节、互相知道的事）、`relations`、`card <对象>`；
   - 数值、任务、道具：`ledger`、`track <名目>`；
   - 悬念与伏笔：`questions`；
   - 先后与时间：`timeline`；
   - 发生了什么：`episodes`、`appearances <对象>`、`chapter <章>`、`arcs`；
   - 找不到入口时：`search <文字>`。
3. **读原文核对**：用 `read <章.段[-段]>` 读相关段落，`para <章.段>` 看引用这一段的记录。命令结果只是线索，结论以原文为准。
4. **引用出处**：答案里每个关键结论都写出“章.段”。

## 知情题的规则

回答“谁知道什么”时：

- 旁白点破、读者读到的内心独白，只说明**读者**知道，不说明书里的角色知道。
- 说一个角色知道，要指出他在场看到、被告知、看到消息或视频，或自己推断的那一段。
- 没有记录写“原文没有表明”，不要当作“不知道”。
- 记录里的“不知道”（`unaware`）只是记录给出的状态：带“推断”标记的是抽取时推出来的，不等于原文明说他不知道。读原文核对；原文没有明说时，答案里标“推断”或“无法确定”，不要写成明确的“不知道”。
- 身份连接分确定与不确定：角色自称、候选的判断不等于事实（命令输出里会标“可能是同一人”“角色的说法”）。
- 用户可能确认、驳回或改过图里的记录（`nbstory revisions list`）：查询结果已经套用了这些修改，记录上带“你确认的”“你加的”的是用户的决定。还待确认的候选仍按“不确定”答。

## 答案格式

- 先给结论。
- “谁知道什么”的题，结论后给一张一行一人的表：

  | 人物 | 知道吗 | 怎么知道的 | 依据 |
  |---|---|---|---|
  | <人物> | 知道 / 不知道 / 原文没有表明 | <在场看到、被告知、推断……> | <章.段> |

  “知道吗”只用三个值：知道、不知道、原文没有表明。完整说明放在表后。
- 概括、关系类的题：结论加分点。
- 每个结论标明是明说、推断还是无法确定。

## 提醒

图是自动抽取的，可能漏记或记错。命令结果与原文不一致时以原文为准，并在答案里说明哪里不一致。
