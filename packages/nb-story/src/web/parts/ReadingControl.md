# 阅读位置

顶栏常驻的“读到哪里”：上一章、下一章、章滑块，旁边的“段”默认收起，打开后多一个段滑块（docs/specs/story/viewer.md 输出 5）。拖动滑块时只改显示的数字，松手才提交，免得每挪一格整页都重取一次。

## 布局

一条横排的胶囊：书签图标、上一章、“读到第 N 章 / 共 M 章”、下一章、章滑块、“段”开关；打开“段”后接着是“第 K 段 / 共 L 段”与段滑块。放不下时换行。`compact` 时章滑块变短（平板）。

## 交互

- 上一章、下一章：直接提交相邻的章；在第一章或最后一章时对应按钮禁用。
- 章滑块：拖动时数字跟着变，提交时发出新位置。精确到段时，换章后落在新章的最后一段。
- “段”开关：打开后提交段滑块的值；关掉时位置回到“读完这一章”。
- 键盘：滑块的方向键步进由 nb-ui 的 Slider 提供。

## 数据

```ts
defineProps<{
    /** 当前阅读位置；只给章表示读完这一章。受控：组件不改它，只发 update:at。 */
    at: {chapter: number; paragraph?: number};
    /** 各章的段数，按章号顺序；长度就是章数。必填。 */
    paragraphs: readonly number[];
    /** 平板宽度下用短滑块，缺省 false。 */
    compact?: boolean;
}>();
defineEmits<{
    /** 用户提交了新位置。 */
    "update:at": [{chapter: number; paragraph?: number}];
}>();
```

没有 slots、expose；attrs 透传到外层。

## 状态

`state:local`：滑块拖动中的草稿值、“段”开关是否打开。`at` 变了草稿跟着变；`at` 带段时“段”自动打开。

## 上游边界

滑块的手势、键盘步进与提交时机来自 nb-ui 的 Slider（Reka UI）。
