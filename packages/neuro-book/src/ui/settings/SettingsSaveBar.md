# SettingsSaveBar

设置页面底部的保存栏（[`settings/settings-window.md`](../../../../../docs/specs/settings/settings-window.md)“给页面用的组件”与输出 23）：左边一段状态文字，右边“放弃更改”“保存”两个按钮。设置文件视图与 page 分区的草稿共用它，两处的按钮长得一样、在同一个位置。组件只管外观与按钮的停用，不记草稿、不知道怎样保存：点了发出 `save`、`discard`，由页面处理。

## 布局

放在内容列的底部。上边一条分隔线（`--divider`）把栏与内容隔成一节，线落在内容列的内边距之内，两端不碰边；栏里没有框和底色。栏内一行，按钮靠右：左边是状态文字（警告色小圆点加 `--text-sm` 的字，占满左边剩下的宽度，放不下时让位给按钮），右边依次是“放弃更改”（`ghost`）与“保存”（主按钮在最右，与页面操作的顺序一致），按钮尺寸 `sm`。栏与上方内容隔 `--space-5`，栏自己上下各 `--space-5`。

## 交互

- 两个按钮一直在，不因状态出现或消失，栏的高度不跳。没有改动（`dirty` 为假）或正在保存（`busy` 为真）时两个按钮都停用；`canSave` 为假时（例如这一层暂时连不上）只停用“保存”，放弃只丢本地草稿，照常可用。
- 点“保存”发 `save`，点“放弃更改”发 `discard`；停用时不发。键盘上是两个顺序相邻的按钮，焦点环同其它按钮。
- 停用的按钮留不住焦点：调用方在保存成功后自己把焦点放回编辑处。
- `Mod+S` 一类的快捷键由页面自己接，栏不监听键盘。

## 数据

```ts
type Props = {
    /** 有没有未保存的改动：没有时两个按钮停用、不写文字。 */
    dirty: boolean;
    /** 正在保存：两个按钮停用。页面里其它让“保存”暂时做不了的原因（例如这一层连不上）也可以经它停用。 */
    busy: boolean;
    canSave?: boolean;      // 缺省 true；为假时只停用“保存”
    /** 栏左侧的状态文字（页面写好、已经是当前语言）；有改动时缺省为“有未保存的更改”，没有改动时不显示。 */
    message?: string;
};

type Emits = {
    (event: "save"): void;
    (event: "discard"): void;
};
```

没有 slots、expose；attrs 落在根 `<footer>` 上。根带 `data-settings-save-bar`（有改动时再带 `data-dirty`），文字带 `data-settings-save-bar-note`，两个按钮带 `data-settings-save-bar-discard`、`data-settings-save-bar-save`。文字是 `role="status"`：有改动时出现、读屏念一次。

## 状态与边界

- 没有改动：不写文字，两个按钮停用（`message` 此时也不显示）。
- 有改动：写 `message` 或缺省的“有未保存的更改”，按钮可用。
- 保存中：文字照旧，按钮停用。
- 文字很长时在左侧换行，按钮不缩。

## 不支持

- 不记草稿、不判断“有没有改动”、不负责保存与放弃的实际动作。
- 不在栏里写失败原因：页面把失败原因放在栏之外（设置文件视图写在窗口标题区右侧）；确要写在栏里时可以经 `message` 传入。
- 没有第三个按钮与插槽。

## 注意事项

- 没有语言属性：“保存”“放弃更改”与缺省的“有未保存的更改”经注入的翻译端口取，随宿主的显示语言切换；页面传入的 `message` 由页面自己负责翻译。
- 样式只用 nb-ui 的 token；小圆点是 6px，与 `SettingsRow` 的“已修改”圆点同一个大小。

## 隐藏通道理由

- `state:inject`：经 `useText()` 取宿主注入的翻译端口，固定文字在 `nbook.settings` 的目录里（`plugins/settings/locales/`；键表见 `ui/settings/text.ts`）；语言随端口切换，不重新挂载，组件没有语言属性。设置窗口里的页面与 SDK 交给第三方插件的设置页都在宿主窗口里，宿主总会登记这份目录。没有宿主注入时得到 nb-ui 的缺省端口，那里没有这份目录，只显示键名，所以测试与 Lab 场景要注入登记了它的宿主引擎端口。
