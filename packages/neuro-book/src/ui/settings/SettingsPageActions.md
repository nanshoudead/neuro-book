# SettingsPageActions

设置窗口里 page 分区的页面级操作（[`settings/settings-window.md`](../../../../../docs/specs/settings/settings-window.md) 输出 3、13）：“添加服务商”“测试连接”这类作用于整个页面、不属于某一行的按钮。页面把它们写在 `SettingsPageActions` 里，窗口把它们画在标题区的右侧，与层的警告并排；页面不用知道标题区在哪。窗口还替页面管着一件事：这一层不能写（层文件有错、连不上）时，这些操作整体停用，层恢复时自动恢复。

## 布局

窗口提供时，内容在标题区右侧（层警告的左边，从右往左排），各个操作之间 `--space-3`；没有窗口提供时（例如 Lab 单独渲染）内容留在原位，同样横排。外面包着一个没有描边与内边距的 `<fieldset>`，只作停用的作用域，布局上不占位置。

## 交互

- 层不能写（`invalid`、`unavailable`）时 `fieldset` 停用，里面的原生按钮（nb-ui 的 `Button`、`IconButton`）随之停用；其它不是原生表单控件的元素不受影响，放进来的要自己是按钮。
- 页面卸载（离开分区、开始搜索、关窗口、重试或重新加载）时内容一起消失；页面不挂的时候标题区右侧没有这一块。
- 键盘顺序与标题区里的位置一致，不与页面里的控件交错。

## 数据

```ts
type Slots = {
    /** 要放进标题区的操作，通常是一两个按钮。 */
    default(): unknown;
};
```

没有属性、没有事件，不暴露内部状态；attrs 落在里面的 `fieldset` 上（根是传送门，接不住透传）。根带 `data-settings-page-actions`。

## 状态

- 能写：按钮照常。
- 不能写：按钮停用（原生 `disabled`，样式同按钮的停用样式）。
- 没有窗口通道：不涉及“层”，不停用。

## 不支持

- 不支持放在标题区以外的位置、不支持多个目标；标题区只有一块。
- 不替页面的控件停用：页面自己的控件按 `SettingsPageContext.writable` 停用。

## 注意事项

- 标题区与页面是窗口同一次渲染里的前后两个子树，标题区的元素要等这次挂载结束才拿得到：页面里的操作先在原位渲染，目标一到就移到标题区，两步在同一个渲染周期里完成，不会被画出来。页面不需要等。
- 内容 Teleport 到窗口之外的位置时，事件仍沿组件树冒泡，页面里的 `@click` 照常工作。
- 窗口通道（`page-chrome.ts`）不是公开接口，这个组件是页面使用它的唯一入口。

## 隐藏通道理由

- `state:inject`：从窗口取标题区的挂载点与这一层能不能写；页面不该为此接线，窗口也不该要求每个页面传 props。
- `env:portal`：内容要画在标题区，不在页面自己的子树里。
