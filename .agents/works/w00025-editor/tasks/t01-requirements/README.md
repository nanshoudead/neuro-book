## 开发者的决定

1. （2026-10-14）主线分两段：先做“像 VS Code 那样按文件类型选编辑器”的基础架构，再深度打磨 Markdown 编辑器（作者最常用的视图）。基础架构的例子：图片能看；文本能按语言高亮；HTML 以文本打开，标题动作里自动多一个“预览”，点开显示 HTML 预览。上面候选表里的其它组暂不排。
2. （2026-10-14）预览两种打开方式都有：“打开预览”默认在当前组打开，另有“在侧边打开预览”。
3. （2026-10-14）HTML 预览运行脚本，关在不同源的沙箱里：拿不到应用的数据与接口，只能读到页面按相对路径引用的文件。
4. （2026-10-14）这期的非文本类型只做常见图片（png、jpg、gif、webp、svg），只看不改；SVG 默认按图片显示，也能用源码编辑器重新打开；PDF、音视频、字体等显示“不能在这里打开”。
5. （2026-10-14）用什么编辑器打开按顺序选：先找声明了这类文件的编辑器（Markdown → Markdown 编辑器，png → 图片查看器），没有就落到默认的文本编辑器；文件不是文本（二进制）又没有编辑器认领时显示不支持。
6. （2026-10-14）语言模式分三层：语言登记（id、别名、扩展名、文件名，纯声明）→ 高亮与编辑规则（按需加载的实现，格式留 Monarch 与 TextMate 两种位置）→ 语言智能（LSP）。这期做前两层且只实现 Monarch，Monaco 自带的语言都经贡献点登记，状态栏显示并可切换语言；TextMate 与一个 Vue 语言插件放进之后的“第三方插件规范与例子”Work 当例子；LSP 暂缓，不做，只保证语言 id 与登记以后能对上。

## 基础架构与现状的差距

从 Spec 与代码读出，未在页面上复核：

- 编辑器种类是封闭的两种（`markdown`、`code`，`workbench/editor.md` 的“边界与兼容”写明第三方编辑器贡献不在本期）；打开时按扩展名二选一。
- 文件读取只接受 UTF-8 文本、经 RPC 单条消息（上限约 1 MiB），图片等读出来是 `not-text`，内容区只显示失败原因（`workspace/files.md` 的读取与保存）。
- 源码编辑器（Monaco）只装了 markdown、json、js、ts、css、html、xml、yaml 八种语言（`editor/web/code/load-monaco.ts`），其余是纯文本。
- 拆分已有：“向右拆分”、`group: "side"`，两组共用一份文档、各有撤销历史（输出 2、35，`editor-area.e2e.ts` 覆盖）；拖标签到边缘拆分还没有。
- 没有预览：标题动作贡献点 `editor.title` 已有（输出 34），可以挂“打开预览”。
