## 重要

### 1. 服务交出的 `PromptEditor` 不再转发模板引用，对话视图的输入框拿不到 `PromptEditorExpose`
- **严重程度**：重要；**类别**：正确性
- **位置**：`packages/neuro-book/src/plugins/markdown/web/plugin.ts:36-57`（`withHost`）、`:78-86`（`hosted(...)`）；`packages/neuro-book/src/plugins/markdown/web/components/MarkdownHosted.vue`；消费方 `packages/nb-agent-ui/src/vue/composer/AgentConversationComposer.vue:33,282`（`ref="editorRef"`）与 `use-editor-handle.ts`
- **现象**：基线里 `PromptEditor` 是 `defineAsyncComponent(...)`，Vue 对异步包装器会把模板 ref 转给内层的真实组件，所以 `editorRef.value` 是 PromptEditor 的实例，`focus`、`addFiles`、`insertText` 等外露方法可用。现在服务交出的是 `withHost` 造的普通组件（`setup` 返回渲染函数、没有 `expose`），里面再套 `MarkdownHosted`（`<script setup>`，没有 `defineExpose`），ref 停在最外层，外露的方法全部缺失。
- **为什么是问题**：Composer 经 `useEditorHandle` 调 `editor.focus()` 等，会得到 `TypeError: ... is not a function` 或静默不做；Spec `ui/prompt-editor` 把 `PromptEditorExpose` 列为命令面。`agent-ports.typecheck.ts` 的注释还写着“包的那一层只转发属性与插槽，不在这里核对”，把 ref 漏在了外面。Lab 的 nb-agent-ui 夹具直接把包里的 `PromptEditor` 当 renderer（`fixtures/nb-agent-ui/host.ts`），e2e 绕过了真实的服务包装，所以抓不到。
- **如何核实**：在 Work worktree 里临时写了一个 dom 测试：父组件 `h(component, {ref: r, ...})`。`defineAsyncComponent(() => import("@notnotype/nb-markdown/prompt").PromptEditor)`（基线形状）得到的 `r.value.focus` 是 function；`MarkdownHosted`（现在的形状，`component: "PromptEditor"`）得到的 `r.value?.focus` 是 undefined。外层 `withHost` 比 `MarkdownHosted` 更不转发，结论只会更差。
- **建议改法**：让包装层转发外露：`MarkdownHosted` 与 `withHost` 都用 `expose` 代理到内层实例（例如拿内层的 ref，`expose(new Proxy({}, {get: (_, key) => inner.value?.[key]}))`），或者换结构，不用中间组件提供宿主（插件在应用层 `provide`、或让 `hosted(...)` 对 PromptEditor 直接返回 `defineAsyncComponent` 加 `provide` 的方式）。再补一例：经服务交出的 `PromptEditor` 上 `ref.value.focus` 是函数（用 `startMarkdownBrowserHost` 起真实插件）。

### 2. 经服务交出的 `MarkdownImage` 丢了“不在作品里，不显示”的说明
- **严重程度**：重要；**类别**：正确性（用户可见文字回归，且与组件文档不符）
- **位置**：`packages/neuro-book/src/plugins/markdown/web/components/MarkdownHosted.vue`（`extra` 只给 InlineChip）；`packages/nb-markdown/src/display/MarkdownImage.vue`（不 inject 宿主，`missing` 缺省“{name}（不显示）”）；`MarkdownHosted.md` 写“诊断落到插件交给它的诊断出口；图片不显示时写明‘不在作品里’”

### 5. 包内显示测试点击引用小块时 happy-dom 会真的去 `fetch("paragraph://41.20")`，每次运行在输出里留一段 `DOMException` 栈
- **严重程度**：建议；**类别**：测试
- **位置**：`packages/nb-markdown/src/display/MarkdownDisplay.dom.test.ts` 第一例（`chip.trigger("click")`）
- **现象**：`bun run test` 的 Vitest 部分输出 `DOMException [NotSupportedError]: Failed to fetch from "paragraph://41.20": URL scheme "paragraph" is not supported.`，测试仍通过。小块的 span 在 `<a>` 里面，happy-dom 在事件冒泡经过 `<a>` 时就执行默认跳转，早于根元素监听器的 `preventDefault()`。真实浏览器的默认动作在全部监听器之后，没有这个问题。
- **为什么是问题**：不是产品缺陷，但常驻的噪声会盖住真正的错误输出，也说明这条测试没有断言“默认跳转被拦住”。

### 6. 包的 `boundary.test.ts` 拦不住“纯 TS 入口引子目录的入口文件”，与它自己的注释相反
- **严重程度**：建议；**类别**：测试
- **位置**：`packages/nb-markdown/src/boundary.test.ts:30-37`；`packages/neuro-book-test-support/src/import-boundary.ts`
- **现象**：第一例想保证 `src/` 根上的纯 TS 文件“只引 entities 与 src 根上的文件”。它的判据是 `within: SOURCE_ROOT`（子目录也在里面）加一条正则 `from "(\.\/[^"]+\/[^"]+)"`（要求路径里至少两段）。`from "./host"` 这类指向目录入口（`host/index.ts`）的写法两条都不命中。
- **如何核实**：变异检查：在 Work worktree 的 `packages/nb-markdown/src/index.ts` 末尾加 `export {useMarkdownHost} from "./host";`，`bun test src/boundary.test.ts` 仍是 2 pass 0 fail；还原。同一个变异下 `tsc --noEmit` 会失败（`chip.ts` 用了 `Document`、`Element`，纯 TS 配置没有 DOM 库），所以 `typecheck` 能兜住带 DOM 类型的情形，但引入 `vue`（`host/index.ts`）本身、或只引不用 DOM 类型的子目录模块（例如 `./language` 的某些文件）不会被拦。
- **建议改法**：核心文件的相对导入用 `excluding`/解析后判定“落在 `src/` 根目录本身而不是子目录”（`dirname(resolve(...)) === SOURCE_ROOT`），不要靠两段路径的正则；`./host`、`./language` 这类目录入口要显式算子目录。

## 建议（代码质量）

### 8. `MarkdownHosted` 每个实例都新建 `defineAsyncComponent`，不再共享已解析的组件
- **严重程度**：建议；**类别**：代码质量（也影响长对话的挂载成本）
- **位置**：`packages/neuro-book/src/plugins/markdown/web/components/MarkdownHosted.vue:50-57`
- **现象**：基线里 `withHost` 只建一次异步包装器，第一次解析后后续实例同步渲染。现在 `defineAsyncComponent(...)` 写在 `<script setup>` 里，每挂一个 `MarkdownDisplay`（长对话里每条消息一个）都新建一个包装器，各自再等一轮 `Promise.all([import, import])`，`onMounted` 晚一个异步周期；`failed` 也变成每实例一份，和 `withHost` 里共享的 `failed` 形成两套不同语义的失败处理，回退的 `<div>` 与插件里的 `fallback` 还各写了一遍。
- **建议改法**：把五个异步组件提到模块级（`const INNER = {MarkdownDisplay: defineAsyncComponent(...), ...}`，`languageOf` 也放模块级，加载完才有值，且只有展示器用），`failed` 用模块级的 ref 或交给 `withHost` 统一；回退文字只留一处。

### 9. 宿主的 `language()` 在“不是展示器”的实例上是个会抛错的陷阱
- **严重程度**：建议；**类别**：代码质量
- **位置**：`MarkdownHosted.vue:28-34`；`packages/nb-markdown/src/host/index.ts`（`language?(): MarkdownLanguage`）
- **现象**：`MarkdownHosted` 给五个组件都提供同一个宿主，但 `language()` 只在 `component === "MarkdownDisplay"` 时才可用，其余实例调用就抛 `MarkdownHosted：只有展示器取语言…`。今天只有 `MarkdownDisplay` 调它，展示器里抛错会被 `onMounted` 的 try/catch 接住，变成“纯文字显示 + 一条 `markdown.display.failed` 诊断”，原因不容易看出。以后包里再有组件用语言（例如 PromptEditor 的内联渲染）就会静默降级。
- **建议改法**：让 `language` 在非展示器实例上给缺省值（`undefined`，组件自己取 `defaultMarkdownLanguage()`），或模块级预加载后所有实例都能用；至少别用 `throw` 表达“当前实例不该调”。

- **建议改法**：以开发服务实测为准改 README（或补 neuro-book 的清单），并写明理由。

### 15. README 里 `provideMarkdownHost({...defaultMarkdownHost, ...})` 的展开是多余的
- **严重程度**：建议；**类别**：文档
- **位置**：`packages/nb-markdown/README.md` 第 3 条示例
- **现象**：`provideMarkdownHost` 接收 `Partial<MarkdownHost>` 并在内部与 `defaultMarkdownHost` 合并，示例先展开一遍再传，读者会以为必须这样写，也会误以为嵌套提供时是在父宿主上叠加（实际是在缺省上叠加，父宿主的 `language` 等会丢）。
- **建议改法**：示例去掉展开，并在 `host/index.ts` 的 `provideMarkdownHost` 注释里写明“嵌套提供不继承父宿主”。

### 16. `PromptEditor.md` 的能力标签写 `[state:local]`，但它的小块分类依赖祖先提供的宿主
- **严重程度**：建议；**类别**：文档
- **位置**：`packages/nb-markdown/src/prompt/PromptEditor.md` 头部；对照 `PromptTokenView.md`（`[state:inject]`）、`PromptTextView.md`（`[state:local, state:inject]`）
- **现象**：`PromptEditor.md` 正文已经写“引用小块的目标分类与文件图标来自祖先提供的宿主”，实测组件级 `provide` 能到达节点视图；按 `docs/standards/code/components.md`，经 provide/inject 取能力的应该标 `state:inject`，调用方才会知道要提供宿主。
- **建议改法**：加上 `state:inject`。

### 17. 更新后的 Spec 里一条链接的显示文字还是旧路径
- **严重程度**：建议；**类别**：文档
- **位置**：`docs.diff` 里 `docs/specs/ui/prompt-editor.md` 的“实现入口”：文字 `shared/link-syntax.ts`，目标已是 `packages/nb-markdown/src/link-syntax.ts`
