### 1. 用正则找 head 会把整套预览保护插进 HTML 注释，默认禁网失效

- **严重程度**：重要；**类别**：安全与性能；
- **位置**：`packages/neuro-book/src/plugins/html-preview/web/compose.ts:57-64`；`packages/neuro-book/src/plugins/html-preview/compose.test.ts:13-20`。
- **现象**：输入 `<!doctype html><!-- <head> --><html><head>…` 时，第一个正则命中注释里的 `<head>`，把 CSP meta、no-referrer meta、令牌 base 和锚点脚本全部插在注释里。真实 head 里没有任何一项保护。文档脚本仍会按 iframe 的 `allow-scripts` 执行；它还能从注释文本中取得刚签发的令牌。
- **为什么是问题**：Spec `workbench/html-preview.md` 输出 5 与信任边界承诺默认不能联网、不能把作品内容发到外网。合法注释就能移除这一层，不需要用户打开“允许联网”。这是本范围新增的拼装函数，base 中没有预览实现。仅测试字符串匹配位置没有验到 HTML 解析语义。
- **如何核实**：已运行 `bun /home/notnotype/CodeRepository/neuro-book/.local/agent/works/w00025-editor/tasks/t02-editor-types/reports/impl-review/lab/compose-probe.ts`，直接调用实际 `composePreview`，输出 `policyInComment: true`、`policyPosition: 26`、`commentEnd: 1409`、`realHeadPosition: 1412`。该实验只验证实际拼装产物，不是浏览器或真实插件宿主验收；浏览器出网结果从 HTML 注释解析规则与现有 iframe 属性推断，未执行。请主 Agent 在现有预览 e2e 中加入“注释含 head、实际页面发外网请求”，断言请求被挡。
- **建议改法**：用能识别注释、raw-text 元素和真实标签的 HTML 解析/插入方式，把保护放到真正会执行的文档前部；不要用三个不感知 HTML 上下文的正则作为安全边界。让同一个插入过程处理 base，避免另起一套扫描。

### 2. 预览跳到另一份 HTML 后不再有禁网 CSP

- **严重程度**：重要；**类别**：安全与性能；
- **位置**：`packages/neuro-book/src/plugins/files/backend/raw-route.ts:210-224`；`packages/neuro-book/src/plugins/html-preview/web/compose.ts:31-46,57-58`。
- **现象**：禁网策略只存在于初始 `srcdoc` 的 meta。Spec 明确允许点击链接跳到另一份 `.html`，这次导航由 preview 路由原样返回 HTML，响应只有 CORS/no-referrer，没有任何 CSP；不会再经过 `composePreview`。新 HTTP 文档不继承前一个 srcdoc 的 meta CSP，iframe 的 sandbox 仍允许脚本执行。第二页可读同令牌下的作品文件并向外网发送；不需要打开联网开关。
- **为什么是问题**：跳页显示磁盘内容是已接受的限制，不等于放弃默认不能联网的安全边界。修好第 1 条的插入位置也不能修复这个独立入口。preview URL 若直接在普通顶层标签中打开，响应连 sandbox 头也没有，会在应用源下运行 HTML；原始字节路由专门用 sandbox 防的路径在这里重新出现。
- **如何核实**：从代码推断，未运行浏览器：`composePreview` 仅拼初始文档；路由 `serveFile(..., {...cors, "Referrer-Policy": "no-referrer"})` 不附 CSP。现有 `e2e/editor-types.e2e.ts:188-263` 只测初始 srcdoc 与 `#` 锚点，没有跨 HTML 导航。请主 Agent 在真实预览里跳到 `next.html`，让第二页 `fetch` 项目 JSON 后用 no-cors 请求外部受控地址，并断言未授权时无外发；另验证直接打开预览 HTML URL 不取得应用源权限。
- **建议改法**：把随令牌生效的安全策略放在 preview HTML 响应的 HTTP CSP 中，至少始终施加 `sandbox allow-scripts`，并让禁网/授权联网策略覆盖导航后的文档；或者将 HTML 导航统一交回受保护的预览拼装入口。保持沙箱 iframe 与令牌方案，不需要另开源；不要只靠初始 srcdoc 的 meta 保护整个导航生命周期。

### 3. 错误代次的请求会清掉正在运行那一代的根身份缓存

- **严重程度**：重要；**类别**：不变量；
- **位置**：`packages/neuro-book/src/plugins/files/backend/raw-route.ts:120-139`，尤其 `124-125`。
- **现象**：缓存按项目 id 存当前根，但“URL 代次不符”分支无条件 `opened.delete(id)`。先成功读取第 3 代，根被替换后第 3 代请求正确得到 `root-gone`；此时发一次 `/raw/project/<id>/2/...`，它虽返回 410，却把第 3 代缓存删了。接着第 3 代请求重新 `openRoot`，若新目录保留同一个 `.nbook/project.json` 的 id，就会服务新目录，而原项目子进程仍拒绝这个根。
- **为什么是问题**：拒绝旧代请求不能撤掉当前代的根身份。违反 `workspace/files.md` 的“根被替换后不重新解析到新目录”及 HTTP 与项目文件服务使用同一代根的约定；一个迟到的旧窗口请求就能触发，不是只能恶意调用内部函数才有的时序。本范围新加缓存，base 没有此入口。
- **如何核实**：从代码推断，未运行产品测试。`opened` 只以 id 为 key；条件把“登记中的项目已结束”和“调用方 URL 写错代次”混成一支。请主 Agent 给 `files/raw-route.test.ts` 补真实目录场景：第 3 代热缓存后移走原目录、复制相同身份到原路径；依次请求第 3、2、3 代，最后一次仍应为 410，不能为 200。
- **建议改法**：仅当实际运行代次结束/改变时撤掉对应缓存；拒绝请求代次不符时保留实际正在运行的根。最好让根缓存直接归代次生命周期所有，而不是用不可信 URL 的匹配结果驱动失效。

### 4. 没有 Host 的真实请求得到 500，不经过约定的 421 拒绝路径

- **严重程度**：建议；**类别**：正确性；
- **位置**：`packages/neuro-book/src/plugins/http/backend/dispatch.ts:75-88`；`packages/neuro-book/src/plugins/http/backend/plugin.ts:80-82`；`packages/neuro-book/src/plugins/http/backend/dispatch.test.ts:61,225-235`。
- **现象**：分发器在读 Host 之前先 `new URL(request.url)`。本机 Bun 对 `GET /api/runtime/health HTTP/1.0` 且没有 Host 的请求交出相对 `request.url: "/api/runtime/health"`，这里抛 `TypeError`，最后由 Bun 的 `error` 回调变成 500 `internal-error`，不是 Host 不被允许时的 421。
- **为什么是问题**：本次新增的“分发前核对 Host”没有覆盖缺头输入；每个这样的请求还会进入内部故障诊断。base 原先也不支持这种相对 URL，本条不把旧行为冒称为新安全漏洞，仅指出新增来源核对合同缺了一条输入边界。现有测试用 `new Request("http://"+host+path)` 模拟 Host，永远构造不出 Bun 实际交出的这种请求。
- **如何核实**：已运行 `bun /home/notnotype/CodeRepository/neuro-book/.local/agent/works/w00025-editor/tasks/t02-editor-types/reports/impl-review/lab/host-probe.ts`，用真实 Bun HTTP 监听和 TCP 请求核对：普通 evil Host 与 absolute-form 都进入 evil URL；大写 `LOCALHOST` 被规范化；缺 Host 的结果为 `{"url":"/api/runtime/health","host":null}`。该探针没加载产品分发器；500 由上述实际源码调用链推断。请主 Agent 在 HTTP 合同测试中加真实监听/原始 TCP 场景。
- **建议改法**：把缺失或不可解析 Host 明确作为边界拒绝，在 URL 构造之前完成；保留统一 421 错误响应，不让不合法请求变成内部异常。

### 7. Monaco 模型序号是组件实例局部变量，拆分后会产生重复 URI

- **现象**：`modelSequence` 定义在 `<script setup>` 中，每个组的 MonacoControl 都从 0 开始。第一个组首次打开 `a.json` 创建 `nbook-model://m1/a.json`；拆分后的第二个控件也第一次创建模型，仍然请求同一个 URI。Monaco 的模型登记是整个页面共享的，第二次 `createModel` 会因 URI 已存在而失败。两组分别打开不同目录下同名文件也会碰撞；布局重挂后局部序号重置，但保留槽里的旧模型还在，后续新文件也可能碰撞。

### 8. 最后一个文本引用在保存途中释放后，迟到保存会把字节条目重新标成 dirty

- **严重程度**：重要；**类别**：不变量；
- **位置**：`packages/neuro-book/src/plugins/editor/web/documents/store.ts:416-427,535-548,675-681`；`packages/neuro-book/src/plugins/editor/web/area.ts:523-542,740-745`。
- **现象**：SVG 同时有源码与图片标签；发起保存并让写入结果在途，关闭最后一个源码标签、选择“不保存”，留下图片。`stopText` 把 `text` 清为 `""`、`saved` 清为 null；原保存返回后 `saveNow` 又把 `saved` 设回保存快照。此时 `text === ""`、`saved === "<svg>…</svg>"`，只剩字节引用的条目变成 dirty。后续离页检查仍遍历字节引用，弹未保存确认；终态抢救还会把空正文当作未保存内容。

- **如何核实**：从代码推断，未运行产品测试。请主 Agent 用现有真实 Files RPC tap 扣住 write，建立源码加字节双引用，启动保存，关闭源码并选 discard，再放行 write；断言字节条目 `text === ""`、dirty 为 false、离页无正文确认、rescue 不出现空稿。这里允许已经发出的保存按实际磁盘结果完成，不要求撤销磁盘提交。
- **建议改法**：文本生命周期结束后，异步保存仍结算调用结果，但不要重新填充字节条目的正文基线/dirty 状态；用文本代次或明确的最后文本引用收口统一隔离读取与保存回执。下一次 acquire 文本必须重新读取磁盘，不能接纳上一段文本生命周期的回执。

### 9. 预览 open 等登记查询时释放门面，迟到结果仍签发无人能撤回的令牌

- **严重程度**：重要；**类别**：不变量；
- **位置**：`packages/neuro-book/src/plugins/files/backend/plugin.ts:164-186`；实际调用链 `packages/nb-runtime/src/remote/node.ts:835-846,935-943,1004-1006`。
- **现象**：`open` 在 `await registry.list()` 让出；窗口此时断开或入口停止，门面的 release 遍历当时的 `mine` 并撤销全部令牌。登记查询随后返回，旧 `open` 不看请求 signal，也没有门面 alive 标记，继续 `tokens.issue()`、`mine.add()`。这个令牌在释放之后才加入；门面已从运行时表中移除，不会再释放一次。客户端迟到结果拿不到时，前端也无法补发 close。
- **为什么是问题**：Spec 要求门面释放后它签发的令牌全部作废；当前代码只有遍历集合，没有关闭签发入口。运行时不会替它保证“先等待读调用，再释放门面”：`handleRelease` 直接调用 release，正在执行的方法只收到中止 signal。每次命中这个窗口会留下 1 个没有 owner 的令牌条目，项目仍运行时它也一直有效。
- **如何核实**：从实际远程运行时调用链推断，未伪造同步释放，也未运行测试。`handleRequest` 将 linked signal 交给方法，但方法只接收第一个参数；`handleRelease` 不等待该方法。请主 Agent 在真实远程门面测试里扣住登记查询，发 open 后断开调用方，再放行查询，核对签发总数/可用令牌为 0；不要仅测试已经返回 token 之后刷新窗口。
- **建议改法**：门面 release 同步标记 closed；open 在查询回来、签发前同时核对门面仍活着与调用 signal 未中止，失效就返回失败。已签发令牌的集合和签发门禁由同一个门面 owner 管，不新增另一套回收器。

### 10. 语言规则的等待、加载与 Monaco 注册没有随贡献结束

- **严重程度**：重要；**类别**：不变量；
- **位置**：`packages/neuro-book/src/plugins/editor/web/code/languages.ts:53-61,70-80,100-118,128-148`；`packages/neuro-book/src/plugins/editor/web/plugin.ts:98-112`。
- **现象**：有 3 条结束路径缺失：①贡献已准备但最终没有发布，内核调用 revoke 时 `#published.get(id) !== handle`，直接返回，已有 `#waiting` 永不 settle；②load 已经发出后撤回，返回的旧 definition 没有再核对句柄，仍被 tokens factory/`setLanguageConfiguration` 接纳；③同 id 再交付只替换 `#published`，`#installed` 阻止再次注册，之前创建的分词支持和已经触发过的 `onLanguageEncountered` 不会换成新规则。另一个 LanguageRegistry/整个编辑器入口停止时也没有 dispose 来结算 waiting 或释放 Monaco 注册。
- **为什么是问题**：等待尚未激活的语言是正常的；确定失败/撤回后继续等待、使用旧代加载结果不是。输出 43 的语言贡献按运行时寿命交付，不能只把静态声明装进页面级 Monaco 后不再管理。现有 `languages.test.ts` 只测声明与生成源字符串，未测任何 LanguageRegistry 的交付或撤回。
- **如何核实**：从代码与 `runtime/plugins.md` 输出 17、24 推断，未运行 Monaco。运行时允许准备后仅 revoke、不 published；这恰好被 `76` 的 guard 丢掉。请主 Agent 用真实插件宿主覆盖：另一接收者 prepare 失败导致这批撤回；load 在途时关闭提供方；拥有者重新建立/贡献重新补交后实际 tokenize 新规则。不要直接手造一个运行时不可能交付的句柄序列来抬高严重程度。
- **建议改法**：让语言注册归激活作用域所有：保存 Monaco 返回的 disposables、停止时撤销并 settle 所有 waiting；对每个 load 的完成结果核对当前句柄/代次仍一致。再交付需要重建该语言的规则工厂与配置，而不是只改一个 Map。prepare/revoke 的失败路径也要有明确的等待结束结果。

### 11. 页面自带的 base 仍被覆盖，上轮确认的处理没有落实

- **严重程度**：建议；**类别**：正确性；
- **位置**：`packages/neuro-book/src/plugins/html-preview/web/compose.ts:57-64`；`docs/specs/workbench/html-preview.md:19`。
- **现象**：拼装函数无条件在 head 的最前面加自己的 base，即使原页面已有带 href 的 base。浏览器使用第一个带 href 的 base，原页面的值不会生效。
- **为什么是问题**：计划第二版第 6 节与 Spec 的已知限制明确是“页面自带 base 时以页面的为准”。上轮 omp 计划审查第 18 条专门要求补检测与插入策略；本次仍是完全相反的实现，使用自带 base 的页面资源路径会被改写。这不是重提已解决的计划问题。
- **如何核实**：已运行前述 `lab/compose-probe.ts`，实际 `composePreview` 对 `<base href="/custom/">` 的结果依次有令牌目录 base、`/custom/` base。浏览器 first-base 规则未在本次重新动态验证。请主 Agent 补真实预览的已有 href base、只有 target 的 base 两种场景。
- **建议改法**：与第 1 条一起用同一个可靠 HTML 解析过程处理：已有有效 href base 就保留它，只有 target 时补目录 href 而保留 target。默认 CSP 仍限制可访问目标；若决定始终覆盖用户 base，应先改明 Spec 的行为取舍，不能把覆盖实现称作“页面优先”。

### 12. 生成器为抽取声明而执行依赖源码，并把格式一致性当成主要测试

- **严重程度**：建议；**类别**：代码质量 / 测试；
- **位置**：`packages/neuro-book/scripts/gen-monaco-languages.ts:32,49-65`；`packages/neuro-book/src/plugins/editor/languages.test.ts:18-21`。
- **现象**：生成器先用精确到单引号和换行的正则删一行 import，再 `new Function` 执行剩下全部 contribution 源码，最后对函数 `toString()` 再用正则改动态 import。首条测试比较整个生成源文件与同一个生成器的输出，另只验数量大于 50 和声明 schema；生成器若错误漏掉/改坏 loader，这条“与 Monaco 一致”测试仍能在重新生成后一同通过。
- **为什么是问题**：当前锁定依赖是受信的，本条不把它夸大成已发现的供应链漏洞；问题是只需读取静态登记，却额外承担执行源码与两轮格式解析的耦合。仅引号或排版变化即可使升级失败，而真正的消费者错误又未被这条测试保护。`--check` 保留为生成物可复现检查有意义，不等于永久行为测试；测试规范明确反对源码/实现快照式断言。
- **如何核实**：静态核对生成脚本及测试；未执行生成器、没有写生成文件。已检查生成结果确实保留 C/C++、SystemVerilog/Verilog、FreeMarker2 的多条登记与变体导出，本条不是说当前已漏这些语言。现有 e2e 只 tokenize Python、HTML 内嵌 JS、Markdown 内嵌 TS，没覆盖 FreeMarker2 的特殊 loader。
- **建议改法**：用仓库已有 TypeScript AST 读取每个 `registerLanguage` 的字面量声明，原样保留并结构化改写 loader 的模块说明符；遇到超出支持的 AST 形状明确失败，不执行依赖的顶层代码。把源文件一致性留给 `--check`，永久测试改为实际登记集合与代表性 loader/tokenize 行为，至少包括一个 FreeMarker2 变体。
