### 1. 移动非活动标签仍撤销源组绑定，会把留在源组的未裁决输入变成无主候选

- **严重程度**：阻断；**类别**：正确性。
- **位置**：plan.md:18–21；`packages/neuro-book/src/plugins/editor/web/area.ts:289–307,467–475,739–742`；`web/components/EditorGroup.vue:77–85`；`web/documents/store.ts:712–740`。
- **现象**：修订后的第 2 步仅在“搬的是源组活动标签”时 `leave(源组)`，第 4 步却无条件删除源组与目标组的绑定。源组活动的是 A、另有非活动标签 B，A 有未裁决输入时，把 B 拖到另一组：源组无需通过 `leave`，A 仍留在原组，却被撤销原 token 并重新绑定。
- **为什么是问题**：未裁决输入按旧 token 留在文档的 candidates 中；detach 只移除 flusher，不清候选。新绑定的 `unresolved()` 只查新 token，组顶部的裁决按钮随之消失，`resolve(组)` 也只能裁决新 token，保存却继续被旧候选阻止。这不是首轮“忘了结算”原句的重复，而是新事务的“有条件结算、无条件撤绑定”引入的具体不一致；源组不换视图就不应换它的绑定。若通过公开控制器入口移动，未交出的缓冲输入还会在旧 `commit` 变成 `stale` 后失去交付通道。
- **如何核实**：主 Agent 用真实两视图制造 A 的未裁决输入，再从 A 所在组拖走非活动 B；核对 A 的原候选仍有裁决入口，采用当前正文/保留本视图都能完成，随后保存真实文件。另从公开移动入口在 A 刚输入时移走 B，验证 A 的输入不丢；不以纯 groups 测试代替控件证据。本轮仅静态核实，未运行。
- **建议改法**：先计算真正会更换活动视图的组集合，仅对这些组结算、检查、失效绑定；源组搬非活动标签且活动项不变时保留原绑定。普通组内排序也不重签未变化视图的 token。若选择统一失效，则必须先结算并拒绝这些组的全部未裁决输入，不能只检查被拖标签。

### 2. 并掉依赖的 closeTab 循环只在“保存”后重验，“不保存”仍使用询问前的共享状态

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:29、133；`packages/neuro-book/src/plugins/editor/web/area.ts:525–549,551–557`。
- **现象**：计划声称等待期间目标关闭或换编辑器，`closeTab` 自己的循环会重新判断；现有代码只有“保存成功”回到循环头。“不保存”分支仍使用 `await ask` 之前捕获的 `shared`、`own` 与 document，直接 `break`。源视图有未裁决输入、共享正文 dirty，目标最初能编辑，等待期间目标被关闭/改成只读，用户再选“不保存”：仍按旧的 `shared=true` 只丢源候选，不执行最后一个可编辑标签的整份正文丢弃规则。
- **为什么是问题**：若仍有预览视图持有文本引用，未保存正文会留在只读视图里，而不是按 editor.md 输出 4 回到磁盘内容；若源标签等待期间换组或换编辑器，捕获的 own token 也未必仍属当前源视图。首轮第 5 条要求的等待重验没有被“复用循环”完全落实，不能把已有循环当作所有回答的事务保证。
- **如何核实**：主 Agent 用真实 area 与 Files 场地建立源可编辑标签、目标同标签及只读预览；源产生未裁决输入后发起并掉，等可观察的询问出现，经公开控制器关闭目标（该关闭因源仍能编辑不会另弹询问），再选“不保存”；核对存活只读视图与磁盘基线一致。另覆盖保存后目标消失、源标签换组/换编辑器；这些是待运行场景，本轮未复现。
- **建议改法**：询问的回答先绑定这一次源视图身份，恢复后统一重验源与目标及当前的可编辑副本；任一回答都不得继续使用询问前的共享状态。身份或丢弃范围变了就重新询问/返回 stale-target；明确 merge 对目标消失后的停止或普通关闭规则，再只关闭并释放源一次。

### 3. 移动保留标签引用，却没有释放旧组的视图状态槽，Monaco 模型会留到窗口关闭

- **严重程度**：重要；**类别**：不变量。
- **位置**：plan.md:16、20–23；`packages/neuro-book/src/plugins/editor/web/area.ts:157,181–207,209–245,262–277,780–787`；`web/components/MonacoControl.vue:101–105,141–148,275–280`。
- **现象**：新设计只撤 `bindings`，并依靠现有 watch 清理被删除组的 `controlSlots`；搬出的标签在目标组新建 `(新组, editor, document)` 槽，旧 `(源组, editor, document)` 槽的归属与释放没有步骤。现有 watch 只销毁控件实例槽，不销毁视图状态槽；后者通常由 `releaseTab` 按原组键释放，或由换绑定的 `retire` 淘汰。移动保留引用且先删 binding，这两条路径都不会替这次移动清理原槽。
- **为什么是问题**：旧槽持有 Markdown 编辑状态或 Monaco ITextModel；Monaco 组件卸载明确不释放模型。目标组以后关闭该标签时 `releaseTab` 只查目标组键，仍释放不到源键。把同一份已载入文档连续移过 N 个新组，按此设计至少留下 N 份没有标签拥有的旧槽/模型，直至 `area.dispose`。源组没被删除也同样会留下不在 recent 队列里的槽；这违反现有“视图状态随标签关闭或受控淘汰”的寿命约定。
- **如何核实**：主 Agent 用真实源码控件反复跨组移动同一文件，再关闭该文件，检查 Monaco 的存活模型集合恢复到操作前的集合；Markdown 同场景核对旧组实例/状态不再被保留。另覆盖源组剩其它标签与源组删除两种；本轮只追踪现有 Map、dropSlot 调用与 dispose 所有权，未运行内存实验。
- **建议改法**：把搬出视图的原组键及清理责任列进事务结果/收尾；先结算并记光标，待原控件完成解绑后销毁不再有标签拥有的源槽，同时清 recent。只迁移标签与文档引用，不让旧槽成为无主缓存；需要保留的槽须有明确拥有者与淘汰入口，不能仅依赖删除组的 controlSlots watch。

### 4. 同标签并掉绕过 moveTab，固定区落点的固定状态与位置被丢掉

- **严重程度**：重要；**类别**：不变量。
- **位置**：plan.md:27、29、40、81、133–134。
- **现象**：普通落点的合同是 `{group, partition, before}`，落到固定区就固定；但目标已有同地址同编辑器标签时完全绕过 `moveTab`，只激活目标并 `closeTab(源)`，没有把分区/插入位置应用到存活目标的步骤。两组都有普通 A，目标另有固定 P，把源 A 拖到 P 前：按第 29 行执行，留下的仍是普通区原位置的 A。
- **为什么是问题**：反馈承诺“进固定区”，实际却只切到一个普通标签；拖入时是否固定取决于目标是否碰巧已经开过该文件。源/目标固定状态如何合成、存活目标是否按 before 重排，不能由模型保证，因为该分支不调用模型移动。首轮已解决“到底关谁与结算顺序”，但这条新分流没有接回固定分区合同。
- **如何核实**：主 Agent 在真实组模型/area 建立上述 P、A 场景，在浏览器拖入固定行不同位置，断言存活目标的标签 id、pinned、完整顺序和源引用释放；另覆盖目标已固定而落普通区，以及关闭取消时不提前改目标分区。本轮未运行。
- **建议改法**：在 merge 的允许提交点把 partition/before 应用到存活目标，并按分区规则重排；询问取消/失败前不改变其固定状态。若产品决定并掉保留目标原位置与固定状态，必须把它写成显式例外，并让落点反馈预先显示实际的“激活已有标签”动作，不能显示固定插入线却执行另一件事。

### 5. 批量关闭只重验存在与所属组，等待期间新固定的候选仍会被关闭

- **严重程度**：重要；**类别**：不变量。
- **位置**：plan.md:44、53–55、135；Task README 决定 4；首轮报告第 4 条。
- **现象**：第 53 行在启动时筛掉固定标签，第 54 行逐项执行前却只检查“仍存在、仍在这一组”。“关闭其他”正在保存前面的 A 时，用户把尚未轮到的 B 固定，B 的 id 仍在冻结列表、也仍在原组，下一步照样调用允许关闭固定标签的 `closeTab(B)`。
- **为什么是问题**：“跳过固定”被明确限定在批量筛选，通用 `closeTab` 不会再保护 B；冻结候选身份不能代替执行时重验保护条件。结果违反已经批准的“关闭其他/关闭右侧不关闭固定标签”，也少了首轮第 4 条建议中明确要求的逐项“未固定”重验。新开的标签不纳入这批、第二批返回 unavailable 的修订已经落实，不在此重复。
- **如何核实**：主 Agent 用真实 Files 请求闸门扣住 A 的保存，询问已收起后从真实入口固定 B，再放行保存；断言 B 保留、其余未固定候选照常关闭、结果数量与实际一致。另覆盖 B 在候选列表形成后换组、先被其它动作关闭；本轮未运行。
- **建议改法**：冻结“最多可以处理哪些 id”，逐项提交前仍按当前状态检查所属组、pinned 及这类批量动作的资格；新固定者跳过，不停止整批。“关闭已保存”同样在执行点结算并重验是否仍无待结算工作，不能因为 id 在旧快照里就升级成普通的交互式关闭。

### 6. “可用性按目标标签算”没有可复用的命令机制，仅增加 tabId 仍会被全局 active 门禁挡住

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:86–88、121、141；`packages/neuro-book/src/plugins/editor/web/commands.ts:83–86`；`plugins/commands/shared/registry.ts:266–270,309–315`；`plugins/commands/shared/menus.ts:163–174,214–222`。
- **现象**：计划补上可选 `{tabId}`，并要求可用性按目标计算、不先激活，但没有选定如何替换现有 `when: nbook.editor/active`。真实命令表的 `isEnabled(id)` 不接 args，`execute` 也在进入命令实现前按全局公开键做 availability；菜单的 `facts.isEnabled(command.id)` 同样没有参数。
- **为什么是问题**：全局活动标签 A 是页面/正在加载/读取失败（没有句柄，active=false），另一组 B 正常可编辑时，右击 B 的关闭/拆分即使带正确 tabId，也会在调用实现前被拒；A 正常而 B 是页面时，拆分又会被错误显示为可用。首轮第 11 条的“参数目标错位”已经修正，但其“可用性不按全局活动控件”的部分仍只是目标描述，依赖的带参数门禁实际上不存在。
- **如何核实**：主 Agent 用真实命令注册表执行 `close/split-*( {tabId: B} )`，分别让全局活动 A 为页面、加载中、读取失败、正常控件；观察命令结果及菜单 disabled 状态，确认不靠激活 B 或改全局公开键通过。补充 B 为页面/已关闭的逆向用例；本轮未运行。
- **建议改法**：在 S1/S3 明确一种接法及合同迁移：最小方案是目标化命令不再用全局 active 作硬门禁，由 editor 按解析出的目标校验并给菜单计算局部可用性；同步明确无参数命令面板的可用规则。若决定扩展命令服务为按 args 求可用性，则必须把 commands 的公开接口、菜单事实、执行重验与相应 Spec/测试一并纳入，不能留给 S3 临时选择；不要用临时激活或篡改全局状态绕过。

### 7. “最多 3 行”仍不是 120px 组的高度预算，面包屑与裁决条出现时正文会归零

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:71、97、138；`packages/neuro-book/src/plugins/editor/web/components/EditorGroup.vue:181–196,243–246`；`packages/nb-ui/themes/nbook/vars.css:78`、`themes/macos/vars.css:40`。
- **现象**：修订给普通标签加 3 行上限，却仍直接承诺 220×120 的组里正文有可用高度，没有扣掉固定首行、面包屑、2px 进度槽和现有不可收缩的状态条，也未规定高度不足时让谁缩。即使把“3 行”解释成包含固定行的总上限，按现有 26px 行高已是 78px；带一个 26px 按钮的状态条加上下 padding 12px、底边 1px，至少 39px，合计 `78 + 39 + 2 = 119px`，只剩 1px，还没有面包屑。若普通区独享 3 行，另加固定行就是 145px，面包屑之前已经超过 120px。
- **为什么是问题**：未裁决输入、磁盘冲突、删除与保存失败都是实际可达状态；状态条在 220px 宽下还能换行，更高。给标签区一个固定行数上限并不能保证正文余量，这一承诺在最小叶尺寸下仍不成立。首轮第 12 条中固定行横向访问和普通区纵向滚动已补上，本条只指出修订后仍缺的总高度分配。
- **如何核实**：主 Agent 在真实 220×120 组中打开足够标签触发上限、加固定行和面包屑，分别制造未裁决输入/保存失败；量正文实际可见高度并操作裁决按钮与 sash。断言正文至少能显示一整行并接受输入，而非仅 `clientHeight > 0`；本轮未运行布局实验，上述数字来自现有样式。
- **建议改法**：先确定正文最小可用高度，再从组的当前内高减去状态/面包屑等实际高度，给标签区动态可用高度（最多 3 行而非始终允许 3 行）；极矮状态下为状态动作与路径保留可访问的收口方式。固定标签仍保持独立一行，不改开发者决定；正文与裁决入口均不能靠组根 overflow-hidden 裁掉。

### 8. 悬停规则把标签关闭按钮从“单标签”扩大到“整组”，与已定注意力排序和第 5 节互相矛盾

- **严重程度**：重要；**类别**：不变量。
- **位置**：plan.md:69、91–93、142；Task README 决定 4；`docs/specs/workbench/views.md` 输出 10。
- **现象**：决定 4 要求关闭按钮只在活动标签或被悬停的那个标签上显示，第 5 节也写“悬停或活动时换成关闭”；第 8 节却把“非活动标签的关闭按钮”和标题动作合并规定为鼠标在整个编辑组上、焦点在组里或任一菜单打开就显示。照第 8 节实现，鼠标仅停在正文或某一个标签上，所有非活动标签的关闭按钮都亮起。
- **为什么是问题**：views 输出 10 的整窗格显隐范围适用于标题工具栏，不会自动覆盖已单独决定的标签状态位规则；第 8 节还说这些按钮“仍能 Tab 到”，而第 5 节“键盘照旧”及现有 TabBar 合同规定关闭按钮不进 Tab 顺序、用 Delete 关闭。S4 照字面有两种不同的合法实现，现有验收 142 只测组级鼠标移入移出，抓不到这次范围扩大。
- **如何核实**：主 Agent 建立至少 3 个普通标签（含未保存的非活动标签），分别悬停正文、其中一个非活动标签、把键盘焦点放入正文、打开标题“⋯”；逐项观察其他非活动标签的状态位及 Tab 顺序。标题动作可以按组显隐，标签关闭按钮不能跟着整组一起出现。本轮未运行浏览器。
- **建议改法**：拆成两条显隐合同：标题动作沿用 views 的组级规则；标签状态位按决定 4 的单标签活动/悬停规则，键盘聚焦该标签时的等价行为明确写出。保留既有 roving tabindex 与 Delete 关闭，除非另有明确的可访问性决定；不能把工具栏“仍能 Tab 到”整段套到每个关闭按钮。

### 9. 新表面 token 只给 nbook 取值，缺少切到 macos 时实际生效的默认值

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:70、107–112、122、137；`docs/specs/theme/system.md:44–46`；`packages/nb-ui/src/theme/theme-loader.ts:99–107,286–300`；`src/theme/tokens.ts:94–109`。
- **现象**：计划把 `--editor-tabs-surface` 指定为新主题 token，唯一具体取值写在 nbook 主题，只要求在 Spec 表登记、其它主题“可以覆盖”；没有选择通用 `tokens.css` 基线，或 `manifest.declares + fallback` 这两种现有注册路径中的任何一种。macos 现有变量里没有这个名字。
- **为什么是问题**：Spec 表登记不会注入 CSS。若只按计划给 nbook 的 vars.css 加值，切到 macos 后 `background: var(--editor-tabs-surface)` 无有效值，标签条回到透明，而不是本主题的正文面/低一档表面。现有 loader 只从 manifest.declares 生成 fallback，不会从别的主题 vars.css 或 Spec 表推导。“其它主题可覆盖”必须先有可覆盖的默认值；首轮第 14 条要求的 token 拥有者已定，但跨主题兜底尚未落实。
- **如何核实**：主 Agent 先激活 macos 再切 nbook、再切回 macos，在明暗两态读取 token 解析值与标签条实际背景；验证不依赖 nbook 曾经是活动主题。保留活动块等于正文面、布局宽度不变的判据；本轮只读了变量登记与 fallback 生成机制，未运行样式检查。
- **建议改法**：在 S1/S4 写明唯一注册路径及 fallback：通用角色就加入 nb-ui 的主题 token 名单与 tokens.css 基线；nbook 扩展就声明 manifest.declares 并给出从公共变量派生的 fallback。其它主题仍可覆盖，不扩成本 Task 的全局表面模型迁移；验收明确覆盖 nbook/macos 的受影响组合。
