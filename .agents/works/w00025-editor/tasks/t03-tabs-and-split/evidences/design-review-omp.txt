# w00025 t03 实施计划只读设计审查

审查对象：主工作区 `.agents/works/w00025-editor/tasks/t03-tabs-and-split/plan.md`。代码依据为 `.worktree/w00025-t03-review` 的 `80d9cdbd5`；以下实现路径均相对该 worktree，计划行号相对主工作区。只读核对合同、实现与既有测试；没有安装依赖，没有运行测试、e2e 或服务。发现中的后果是从现有代码与拟议改动推导的设计缺口，运行场景交主 Agent 验证，不冒充已复现的产品回归。

### 1. 换组没有定义先结算、再失效绑定的事务，标签引用不动不能保证输入安全

- **严重程度**：阻断；**类别**：正确性。
- **位置**：plan.md:16–22、107（组模型换组、控制器与风险）；`packages/neuro-book/src/plugins/editor/web/area.ts:244–246,254–315,466–475`。
- **现象**：计划只规定搬标签及释放被并掉标签的引用，没有要求普通换组和边缘拆组在改模型之前结算源视图、结算即将换下的目标视图、拒绝未裁决输入，并撤销旧组绑定。这里的引用按标签 id 存，绑定却按组存；视图槽按“组 × 编辑器 × 文档”存。`binding.commit` 的有效性只检查 `bindings.get(groupId)`，不检查标签是否仍属于该组。源组被删时，控制器的同步 watch 还会立即销毁该组的 Markdown 实例。
- **为什么是问题**：Markdown 有 150ms 缓冲；控件换绑定/卸载时才补交不能代替控制器在模型变更前结算：目标绑定可能已经被替换，旧提交变成 `stale`；源组最后一个标签被移走时，实例可能先被销毁。已有未裁决输入按旧绑定 token 存在文档里，`attachView` 的 detach 只摘结算函数、不摘该候选（`documents/store.ts:700–741`）；换组产生新 token 后新组的 `unresolved()` 看不到旧候选，保存却仍被它阻止。若源组变空/暂时无可绑定文档，`binding()` 提前返回 null 也不会清掉 Map 中的旧绑定，旧回调仍可被判为 current。以上都与 editor.md 输出 9、13 和“旧绑定不再改变文档”的寿命合同冲突。
- **如何核实**：主 Agent 用真实 Markdown 控件在源组输入后立即拖走，覆盖源组剩其它标签、源组只剩该标签，以及目标组有尚未结算输入的情况；保存后读真实文件核对两边输入。用真实两个视图产生未裁决输入后尝试换组，检查移动被阻止且裁决入口仍在；裁决后能保存。源码控件另测换组后旧绑定不再接受输入、模型不悬挂。纯组模型拖动成功的测试不能覆盖这些 Vue/控件时序。
- **建议改法**：由控制器拥有一次完整移动事务：按当前标签与组身份检查落点，先结算所有将换下的绑定，任一存在未裁决输入就不改模型；在销毁实例前记光标与视图状态，明确失效源/目标旧绑定，再一次性提交组树和标签变化；最后清理源槽、交接焦点。继续写作的 `pendingReveal` 仍按原组身份取消，不把旧定位迁到新组。模型层只做纯结构变更并返回完整结果，不能把“引用不动”当作这次事务的替代。

### 2. 换组未规定 preview 转正，会把两个可替换标签带进同一组

- **严重程度**：重要；**类别**：不变量。
- **位置**：plan.md:14–17、22、41；`packages/neuro-book/src/plugins/editor/web/groups/groups.ts:214–230`、`packages/neuro-book/src/plugins/editor/web/area.ts:568–575`。
- **现象**：源组有 preview A、目标组有 preview B，按计划把 A 拖到目标组普通区，既不是同地址同编辑器合并，也没有任何规则让 A 或 B 转正；模型只被要求保留标签 id、位置和落点的 pinned 状态。
- **为什么是问题**：现有 preview 替换及 `keepUnsettledPreview` 都只用 `find(tab.preview)` 找一个标签。同组出现 2 个 preview 后，下一次单击打开只保护或替换其中第一个，另一个仍呈现“临时、可替换”状态却不按同一规则被替换；会话记录也能把这个状态保存下来。`pinned` 与 `preview` 是两个不同维度，“跨固定区时固定/取消固定”不能覆盖普通区换组。
- **如何核实**：主 Agent 用真实组模型与浏览器分别在两组单击打开不同文件，再拖到同一组，随后单击第三个文件；检查每一步该组最多 1 个 preview、脏文档仍可结算且刷新结果一致。另测组内拖动 preview、拖到新组、拖到已有同标签的组。
- **建议改法**：在合同里明确拖动是否把被拖标签转为 permanent；最简单是所有实际移动都先转正，原位无动作则不改。若保留 preview，必须定义目标已有 preview 的处理及未保存保护，并让模型、控制器和会话恢复共享“每组最多 1 个 preview、固定标签不能是 preview”的不变量。

### 3. 固定状态与既有改标签入口没有闭合，按列出的切片改会丢固定或打乱固定区

- **严重程度**：重要；**类别**：不变量。
- **位置**：plan.md:14–18、77、88；`packages/neuro-book/src/plugins/editor/web/groups/groups.ts:181–186,233–238,296–315,262–277,397–415`。
- **现象**：计划宣告“所有改顺序的操作都维持固定区在前”，但只给新增固定、拖动和批量关闭定义了规则。现有 `insert` 在活动标签之后插入：固定区有 P1、P2，活动的是 P1 时，普通文件或页面会插在 P1 与 P2 之间；现有 Alt+方向键直接交换相邻位置；`setEditor` 用字段白名单重建标签，会丢新增的 pinned；`split` 同样重建标签，却没有约定复制出来的标签带不带固定。
- **为什么是问题**：这些都是继续保留的公开用户入口，不是新增拖动入口的内部细节。只改 `setPinned`、`moveTab` 及文案中的批量关闭，用户打开文件、打开欢迎页、键盘排序或换编辑器就能破坏“固定区在前”或丢掉固定。恢复会话还必须同时接受缺少 pinned 的旧值、保住活动标签身份；当前记录 schema 的 `additionalProperties: false` 也要求同步补字段（`web/session-record.ts:27–43`），不能只改快照类型。
- **如何核实**：主 Agent 在真实组模型覆盖 P1/P2 中间打开普通文件和页面、Alt+方向键跨区、固定文件换编辑器及换到已有同地址编辑器、固定文件拆分；真实删除流程确认 `closeWithin` 仍强制关闭已删除的固定标签，改名后固定状态保留；用旧记录和含固定标签的新记录各恢复一次并确认活动项没有因分区归整错位。现有验收表只有“固定后排序、批量关闭跳过、刷新保留”，覆盖不到上述入口。
- **建议改法**：补一张固定状态转换表并落实到既有入口：普通插入夹到普通区、键盘跨区明确禁止或转固定状态；换编辑器保留固定；拆分复制规则明确；同标签合并时保留哪一份固定状态明确。模型集中维护分区插入规则，序列化/schema/恢复同步更新。资源删除与普通批量关闭分开，不能把“跳过固定”下沉到通用 `close` 或 `closeWithin`。

### 4. 批量关闭只规定逐个 await，没有冻结目标与关闭事务的并发语义

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:23、88–91；`packages/neuro-book/src/plugins/editor/web/area.ts:510–561,671–677`。
- **现象**：计划规定用户取消时停止、不回滚已关闭项，但没有规定保存失败是否停止、关闭期间新打开/移动/固定的标签是否属于这批，以及另一项关闭或合并操作同时到来时怎么办。现有 `ask` 每次先取消上一个询问；`closeTab` 的 `cancelled` 同时表示用户取消、标签已不存在、保存失败。现有 `closeOthers` 只在开始时取得一次 `found.group.tabs`，然后按旧对象逐项关闭。
- **为什么是问题**：一批内部顺序 await 不能保证全局只有一批关闭。保存等待中可继续操作，另一项关闭到达会换掉对话框、让前一批停下；反过来若实现动态重取“右侧/已保存”集合，会把发起以后新开的标签也关掉。旧 id 列表里的标签被其它操作先关掉会返回 `cancelled`，导致剩余独立项意外不再关闭；被换组的标签则可能在新的组里被旧批次关掉。“关闭已保存”还不能只看 dirty：Markdown 缓冲未交出、未裁决输入、在途保存都是不同状态。
- **如何核实**：主 Agent 用真实文件服务的可控请求闸门扣住保存，期间打开新标签、把待关闭标签换组、再执行一次关闭命令；检查对话框归属、已关/剩余集合、失败结果和焦点。另在 Markdown 输入后立即执行关闭已保存，确认没有把尚未结算的输入当成已保存。用可观察的请求到达和对话框状态同步，不用固定等待。
- **建议改法**：明确一次批量关闭冻结的标签 id、所属组和筛选时刻，新开的不纳入；执行前逐项重验已存在、仍属目标组、未固定及“已保存”条件。定义关闭事务单飞或明确的替换策略，让 `ask` 归属某个事务；保存失败与用户取消各有结果，命令不把部分完成报成全成功。已被其它操作关闭的项跳过，不能与用户取消混为一个结果。为“关闭已保存”先结算输入，再按合同决定跳过有未保存/未裁决/在途保存的标签。

### 5. 同标签合并的模型先删、控制器后结算顺序互相冲突

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:16、22、91；`packages/neuro-book/src/plugins/editor/web/area.ts:521–556`。
- **现象**：第 1 节把“激活目标标签、关掉源标签、返回消失标签”定义成模型 `moveTab` 的行为，第 2 节又要求需要结算的源标签先按 `closeTab` 询问。`closeTab` 首先用 `groups.find(tabId)` 定位；源标签已经被模型删掉时直接返回 `cancelled`，不会结算或询问。
- **为什么是问题**：目标同地址同编辑器仍是能编辑的标签时，共享文档 dirty 本身按现有合同不询问；真正必须问的是源视图自己的未裁决输入。它只能在源绑定和源标签仍存在时裁决。先删再释放会把候选留在文档里却撤掉其裁决入口；先调用完整 `closeTab` 则已经删掉源，不能再用原 `moveTab` 请求移动它。计划既没区分两条提交路径，也没有约定等待用户选择期间目标标签被关掉/换编辑器时重验。
- **如何核实**：主 Agent 用两个真实组打开同一文件，在源视图产生未裁决输入，拖到目标同标签；分别取消、不保存、保存，核对源标签是否保留、共享正文和保存是否正确。保存等待期间关掉目标同标签，再完成保存，确认不会依旧按旧的“已有可编辑副本”条件销毁源。这里不能只写“脏标签被合并会询问”的测试：共享 dirty 的正确行为恰好是不问。
- **建议改法**：普通搬移与同标签合并分流：普通搬移按第 1 条先结算并拒绝未裁决输入；合并在模型变更之前走关闭源视图的结算路径，得到允许后重验源、目标和同标签身份，再激活存活目标并关闭源一次。取消或失败保持原结构；返回结果明确列出被关闭的源标签及原组，控制器只释放一次。把验收 91 改为共享 dirty 与源视图未裁决输入两种不同判据。

### 6. 拖动没有定义结构失效和几何重验，“最后显示的动作”不能直接拿来提交

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:40–43、89–90；`packages/neuro-book/src/plugins/explorer/web/tree-drag.ts:7–8,246–269,290–308`；旧参照 `packages/neuro-book-legacy/app/components/editor-workbench/useEditorTabDrag.ts:98–116,174–180,208`。
- **现象**：计划只列 Escape、失焦和 pointercancel 取消，并说放下按最后显示的动作提交；没有规定拿起时冻结源标签/组身份和结构代次，或在组关闭、标签重排、固定状态改变、wrap 切换、容器 resize/滚动后作废旧反馈。文件树手势的 `invalidate` 需要调用方接线，不是照着门槛实现就自动获得的保证；旧标签实现也另有结构 watch、ResizeObserver 和释放时重新求值。
- **为什么是问题**：标签条换行、目标组被关或固定区改变后，旧 before 锚点或 pinned 落点已经不是指针下那个位置。直接提交旧动作会移动到用户没看到的位置；只检查“动作还可提交”也不等于“与当前命中一致”。若模型沿普通 open 的模式把不存在的组回退到第一组，失效投递还会改到别组。反过来只重新计算并立即提交，会提交从未显示的动作。
- **如何核实**：主 Agent 在真实浏览器起拖后保持指针不动，分别改变窗口宽度使标签换行、滚动标签条、关闭目标组、切换 wrap 或固定状态，然后松手；检查旧反馈及时撤回，且不会提交新出现但未显示的落点。补 lostpointercapture、页面隐藏、组件销毁取消，不只测 Escape。
- **建议改法**：明确语义结构基线与几何失效两类规则：组/标签/分区身份变化取消整场；仅几何变化重新测量并撤回或重新显示反馈。释放时以当前坐标重算，逐字段比较最后实际发布过的动作，且再次验证源组、目标组、before 锚点及分区；不相等或目标不存在就不写。先结束拖动会话再提交，避免提交同步关闭源组时旧监听继续工作。

### 7. 多行选行后还缺行尾到完整分区的锚点转换，照字面会插到整组末尾

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:16、35、41；`packages/nb-ui/src/components/layout/grid-drop.ts:251–329`；旧参照 `packages/neuro-book-legacy/app/components/editor-workbench/editor-tab-drop.ts:70–89`。
- **现象**：计划只写多行按纵向距离选行，再调用 `resolveListInsertion`。共享算法返回的 `beforeId: null` 仅表示超过传入成员的最后一个可见项，不知道这只是整组的某一行，也不知道固定/普通分区。比如第一行 A、B，第二行 C、D，在 B 后放下会得到 null；直接交给 `moveTab(...before: null)` 就变成 D 后面。
- **为什么是问题**：这不是几何原语已经封装的能力。旧实现特意在行尾取完整分区中最后可见项的后继，并把换行边界指示线归一到下一行首项前；还处理 `before` 正好是被拖标签本身的情况。计划把这些步骤缩成“先选行，同旧应用”，没有规定行尾、裁剪尾部、跨固定区边界及空固定区分别怎么映射。S5 与验收 89 只写普通排序，无法防止多行中的错误顺序。
- **如何核实**：主 Agent 在真实浏览器排出至少 2 行普通标签，分别投到第一行尾、第二行首、横向滚动的可见尾部和被拖标签自己的前后半；再加入固定行与没有固定标签的空分区，核对插入线与最终完整标签顺序。需要真实几何，不在 happy-dom 里伪造尺寸证明它正确。
- **建议改法**：把落点合同写成“目标组 + 目标分区 + 完整顺序中的 before 标签 id”，选行只决定几何候选；共享算法求值后必须映射到完整分区的后继，归一换行边界指示线，再按移除源后的顺序判断原位。明确定义空固定区是否接收拖入，以及正文中央追加是否保留被拖标签的固定状态。

### 8. 文件树手势不能原样用于标签按钮，起拖区域与 sash 优先级缺少合同

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:38–43；`packages/neuro-book/src/plugins/explorer/web/tree-drag.ts:71–72,217–225`；`packages/neuro-book/src/plugins/editor/web/components/EditorTabBar.vue:95–120`；`packages/nb-ui/src/composables/useSashGesture.ts:326–352,536–541`。
- **现象**：参照的文件树手势用 `button` 整体作阻止起拖的区域，而现有标签本身就是 `button[role=tab]`；若沿用这条判定，拖文件名不会起拖。反过来整体放开 button，又会让关闭、取消固定及标题动作成为拖动源。计划也没有说新会话的 pointerdown 装在哪一层、是否在 grid 的捕获仲裁之后才拿到按下。
- **为什么是问题**：sash 在 fine/coarse 的 5/15px 热区内于捕获阶段执行 `stopPropagation`、`stopImmediatePropagation` 并立即捕获指针；标签拖动若在更外层捕获阶段先登记 pending，之后移动仍可能起第二场手势。若在标签条冒泡阶段拿起则已有 sash 优先级自然成立。只抄 6px/200ms 门槛没有定义这两个关键差别。用户点击关闭/图钉、标签点击和拖动末尾 click 也必须各有归属。
- **如何核实**：主 Agent 在真实浏览器分别从标签文字、文件图标、关闭按钮、图钉、标题动作、离 sash 4px/6px 的位置起拖；确认每个按下最多一场手势，动作按钮不拖、正常标签能拖、sash 优先且拖标签经过热区不改成 resize。保留文件树拖到整组打开的回归场景，确认新反馈层不截获其命中。
- **建议改法**：定义标签专用 source 与 blocker 标记：标签主体可拖，关闭/图钉/标题动作明确排除；会话在 grid 仲裁之后的标签条或编辑区冒泡阶段接按下，不能抢先登记。每份编辑区只持有一场标签拖动，不复用外壳的视图拖动标记；保留 `data-editor-group` 给资源管理器识别。补这些真实指针验收，不把 tree-drag 的门槛相同当作集成证明。

### 9. 面包屑的大纲不是现成句柄能力，缺少按绑定失效的读取与跳转合同

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:57–59、81、96；`packages/neuro-book/src/plugins/editor/shared/contracts.ts:269–289`、`web/area.ts:416–420,753–761`、`web/components/MarkdownControl.vue:139–185,201–208,247–269`。
- **现象**：计划只给句柄增加可选的 `outline`，却同时依赖“大纲、当前标题、跳到标题”3 种能力，没有定义字段形状、标题身份、定位参数或失败结果。现有句柄只提供行号导航与末尾定位，Markdown 两者中的行号导航根本不提供。句柄按“组 × 编辑器”存活，同一个 Markdown 句柄会跨 A→B 绑定切换；`status`、`language` 并不是给一份静态数据就会自动按文档换代的设施。控制器对外也只有全局 `activeHandle`，每个组自己的面包屑拿不到该组句柄。

### 10. 面包屑目录下拉把列目录与打开文件混成一步，缺少异步结果和非文件项的处理合同

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:57–60、81、96；`packages/neuro-book/src/plugins/files/shared/contracts.ts:50–85,294–301,326–328`、`plugins/explorer/web/tree/rows.ts:144–180`、`plugins/editor/web/area.ts:577–601`。
- **现象**：计划只有“list 子项，选中即普通 open”，没有区分目录与可打开文件，也没定义加载、空目录、失败、重试及旧请求失效。`list` 返回的不全是文件：还有 directory、link、other、missing；内容树的目录可能带 `body`，实际正文是目录下的 `index.md`。普通 `open` 只按传入地址建文件标签，不承担目录导航或内容节点正文解析。
- **为什么是问题**：按字面把子项地址全部交给 `open`，目录会变成读失败的编辑器标签，内容节点也不会自然打开正文。目录 A 的读取比目录 B 晚返回、菜单关闭后返回、活动文件改名/换组后返回，都需要调用方丢弃结果；菜单浮层和文件服务不会替这个新组件选择请求归属。把失败当空数组还会把权限、断线与空目录混在一起。只测“一次 list 成功后选文件”覆盖不到这些路径。
- **如何核实**：主 Agent 在真实文件场景建立普通子目录、内容节点及无正文节点，验证每种菜单项的打开或下钻行为；用现有请求闸门扣住 A 的 list，再切到 B/关菜单/改名后释放 A，检查不会替换新菜单、重开旧菜单或把文件打开到后来活动的其它组。读取失败要看到原因并能重试，空目录要是独立空态。浏览器只等请求和可见状态，不用固定等待。
- **建议改法**：在 S1 为目录下拉补上逐类选择规则：普通目录继续浏览，文件按捕获的组 id 打开，内容节点明确是否沿用资源管理器的正文规则，link/other/missing 不冒充普通文件。以“菜单会话 + 组/标签/地址 + 当前段 + 请求代次”归属 list，关闭、切段、换绑定与卸载时取消并失效；迟到结果不落地。读取错误保留 FilesResult 的码与详情，给出原位重试；打开失败沿编辑器现有提示通道返回。
- **建议改法**：在 S1 先写清公开控件合同：按当前绑定发布的只读大纲、当前标题及定位能力，带可核对的绑定/文档身份，定位返回成功或过期/不可用；重名标题不用标题文字作唯一 id。每组经控制器取得本组当前句柄，换绑定、null binding、卸载时同步撤回。菜单捕获文档与大纲版本，变化时关闭或拒绝旧选择。同步更新控件合同、MarkdownControl.md 与面包屑组件合同，不能只在 S5b 临时补一个可选字段。

报告编排说明：紧接第 10 条之后、以“在 S1 先写清公开控件合同”开头的上一段建议属于第 9 条；第 10 条的建议是其前一段“在 S1 为目录下拉补上逐类选择规则”。追加时锚点误在第 9 条末段之前，按只追加约束保留原文并在此补明归属。

### 11. 标签右键菜单与拟复用命令的目标参数不匹配，会关闭或复制其它位置的资源

- **严重程度**：重要；**类别**：正确性。
- **位置**：plan.md:47–49、78、93；`packages/neuro-book/src/plugins/editor/web/commands.ts:83–86,142–154`、`plugins/explorer/web/commands.ts:46–58,81–82,146–147`、`plugins/explorer/web/controller.ts:786–811`、`docs/specs/workbench/menus.md:56,77,90`。
- **现象**：计划只给 4 条新命令定义 `{tabId?}`，但菜单里的既有关闭、关闭其他、拆分命令当前只接受 `{}`、始终读活动标签；公共 `resource` 上下文只提供 `{address}`，也不足以确定同地址不同编辑器的那个标签。两个复制路径命令同样只接受 `{}`，实现固定读取资源管理器选择，与右键标签无关；把 `{address}` 传给它们会被参数校验拒绝。
- **为什么是问题**：活动标签是 A、右键 B、资源管理器选着 C 时，直接复用这些命令会关/拆 A、复制 C，或得到 invalid-args；“执行时带被右击标签”不是现有命令已有的能力。先激活 B 再执行也不能作为隐含前提：切换可能因 A 的未裁决输入失败，菜单本身不应借选择副作用偷偷改变资源管理器选择。既有命令的 `when: active` 又按全局活动控件求值，无法准确表达页面、加载失败标签或非活动组里被右键目标的可用性。
- **如何核实**：主 Agent 在真实命令注册表及浏览器中同时建立 A/B/C 三个不同目标，在非活动组、非活动标签上右键 B；逐项验证关闭、关闭其他、拆分、复制绝对/相对路径与 reveal 的实际对象。再覆盖活动视图有未裁决输入、资源管理器无选择/未建控制器、页面标签，以及菜单打开后 B 被关闭、换编辑器或换组；旧菜单不能回退去作用于后来活动的标签。
- **建议改法**：在 S1/S3 明确两种上下文：编辑器自己的操作捕获并验证 tabId、组及所需的标签身份，既有关闭/拆分命令也补全可选目标与针对目标的可用性规则；贡献项的 `resource` 则冻结该菜单对应的文件地址，目标失效时关闭菜单或返回 stale-target。复制路径要提供明确的资源参数入口或由编辑器拥有复制动作，不能调用只认资源管理器选择的实现；绝对路径仍经 files.realPath，剪贴板不可用/拒绝和文件服务失败保留现有失败通道。同步更新命令表、菜单位置寿命合同及验证场景。

### 12. 默认多行没有纵向溢出规则，标签和面包屑会吃掉可缩到 120px 的编辑组

### 15. 同名提示只靠上级目录不能区分全部合法标签，缺少根与编辑器相同路径的终止规则

## 对待确认项及“不做与风险”的判断

按计划末尾原项逐一判断，不把以下范围决定重新提交开发者选择。

- **拖动时按 Ctrl 复制标签**：可以不做，Ctrl 不应隐式变成复制或产生第二个标签，仍按本次既定移动语义处理。
- **把标签拖出窗口**：可以不做，指针离开有效投递面或窗口失焦时必须撤反馈、取消会话且不改模型。
- **资源管理器拖到编辑区边缘拆分**：可以不做，继续按既有 `data-editor-group` 打开到目标组，不能由标签拖动层误接成拆分。
- **固定标签的紧凑样式**：可以不做，保持开发者已定的完整标签及独立首行，但该行的超宽访问仍需第 12 条的规则。
- **标签条的滚动按钮**：可以不做，前提是触控板、滚轮/触摸及键盘揭示仍能访问全部标签，不能以“不做按钮”免除溢出可达性。
- **换组的视图与撤销历史风险**：不能仅记为实施时再看，组依赖已由槽键和控件实例代码证实，须在 S1 先补第 1 条的结算/失效/释放及光标、滚动、撤销历史归属，再实现普通移动和合并。
- **Markdown 换组后撤销历史从空开始**：可作为明确且一致的产品取舍，不要求搬运撤销栈，但目标组曾打开过同文档时也必须规定是否重用旧槽，不能只声称“重挂”就保证从空开始。
- **发现控件依赖组 id 才停下补 Spec**：这个触发条件现在已经成立，不能留作未来发现；应在 S1 补合同，而不是到 S2/S5 写出结构变更后才暂停。
- **触摸拖动不在真机测试**（plan.md:102 的未验证边界）：可明确保留为未验证边界，但不能把沿用 tree-drag 门槛写成已验证，尤其 coarse sash 的 15px 热区、长按取消与动作按钮排除仍需代码核对和可行的浏览器覆盖。
