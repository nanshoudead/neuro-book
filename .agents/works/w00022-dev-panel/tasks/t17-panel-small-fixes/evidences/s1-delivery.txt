偏离与理由
A. 夹具条件与计划/审查第 10 条不同（重要，请主会话判断是否回写计划）：
   计划写“格子、列表、label 三层都不能是定位上下文”。按这个条件搭的夹具在组件未修时用例就通过了（实测 1 passed）：
   三层都不定位时 input 的包含块越过格子落到更外层（ICB），格子不在包含块链上，聚焦不会滚它。
   面板里真实的结构是 Splitter 的格子：nb-ui Splitter.vue:592 的 `nb-grid-panel relative min-h-0 min-w-0 overflow-hidden`，格子本身是定位上下文。
   按简报“不失败就调整夹具，不改断言”，把夹具的格子改为 `position: relative; overflow: hidden`（与 Splitter 格子一致），列表与 label 不定位，
   于是组件未修时稳定复现（格子 scrollTop 280），修后通过。用例开头的前提断言相应写成：格子 position 为 relative、列表为 static、格子 overflow-y 为 hidden。
   计划里的四步断言（列表 scrollTop>0、静态位置在可见区外、点击与 Tab 后格子 scrollTop 为 0、勾选框仍在视野内）都保留，未放宽。
B. “input 的静态位置在格子可见区之外”的写法：审查建议用 input 的 getBoundingClientRect 判断，但修好后 input 跟着 label 走、矩形会落在格子内，
   这条前提会在改后失败。改为与组件修没修无关的量：label 在列表内容里的偏移（rect.top - list.top + list.scrollTop）大于格子 clientHeight，
   即勾选框在列表没滚动时的位置落在格子可见区下方。
C. “一直是 0”：在格子上挂 scroll 监听记录出现过的最大 scrollTop，读之前等两帧 requestAnimationFrame（等滚动事件派发，不是固定时长）。
D. Tab 聚焦的做法：点击后 Shift+Tab 离开，再 Tab 回到 input，并断言聚焦状态。
E. 运行方式（未解决，需要主会话决定）：本机 ~/.cache/ms-playwright 不存在，没有 Playwright 自带浏览器；
   packages/nb-ui/playwright.config.ts 用 devices["Desktop Chrome"] 且没写 channel，所以简报里的 `bun run test:e2e -- form-checkbox`
   直接报 “Executable doesn't exist ... chrome-headless-shell”。docs/testing/README.md 规定用本机 Chrome（channel: "chrome"）、不下载自带浏览器，
   nb-ui 的配置与此不一致。我没有改包内配置（范围外），而是用 /dev/shm/t17s1-tmp 里的临时配置跑：import 包内配置，只覆盖
   projects[].use.channel = "chrome"、testDir/webServer.cwd 改为绝对路径、outputDir 放 /dev/shm、失败时截图。临时配置内容：
     import base from "<worktree>/packages/nb-ui/playwright.config.ts";
     const pkg = "<worktree>/packages/nb-ui";
     export default {...base, testDir: `${pkg}/e2e`, outputDir: "/dev/shm/t17s1-tmp/test-results",
       use: {...base.use, screenshot: "only-on-failure"},
       projects: base.projects!.map((p) => ({...p, use: {...p.use, channel: "chrome"}})),
       webServer: {...base.webServer, cwd: pkg}};
   建议另开一处小改动给 nb-ui 的 playwright.config.ts 加 channel: "chrome"（与仓库测试规范一致），之后 `bun run test:e2e` 可直接跑。
