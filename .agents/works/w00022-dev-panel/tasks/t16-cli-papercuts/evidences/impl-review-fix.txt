各条怎么改的
1. 脚本 import（references.ts）：删掉 STATIC_IMPORT、DYNAMIC_IMPORT 两条正则，换成 JsLexer 分词器加 TokenStream 上的识别器。
   - 分词器跳过 // 与块注释、开头的 #!；字符串（遇到没转义的换行就当没闭合，换行之后照常分词）；模板字符串（用括号栈处理 ${ } 嵌套，插值里的记号照常输出，所以 `${import("./x.js")}` 也算）；正则字面量（按前一个记号区分正则与除号：`)`、`]`、词、字面量之后是除号，return/typeof 等关键字之后是正则）。
   - 识别器认 import "x"、import 子句 from "x"、export * / export {…} from "x"、import("x") 与不带插值的 import(`x`)（第二个参数可有可无）。前一个记号是 `.` 时不算（foo.import(...)），import.meta 不算。记号之间的注释自然跳过。子句遇到不认识的记号就放弃，且不取走那个记号，所以每个记号只看一次。子句里遇到 import/export 立刻放弃，这样没写分号时 `export {a}` 不会吞掉下一行的 import。
   - 仍然只留 ./、../、/ 开头的与带协议的地址。
2. CSS（references.ts）：删掉 blankComments 与 CSS_URL/CSS_IMPORT 正则，改成一遍按 CSS Syntax 3 分词的扫描：注释、字符串、名字（整个名字一起读，所以 my-url( 不算）、url( 记号、@import。不带引号的 url 与带引号的字符串都按 CSS 转义解码（十六进制转义加一个可选空白，单字符转义，字符串里反斜杠加换行是续行）。坏的 url(（地址中间有空白、引号、左括号、控制字符）按规范吞掉剩下的部分，不算引用。字符串里的 url(...) 不算。
3. template 与 noscript（questions.ts）：找题的遍历（walk）不再收资源；新增 collectResources 做资源遍历，在整个文档上单独跑一遍。template 进入 content.childNodes；noscript 在 parse5 默认按开着脚本解析时内容是一段文字，就用 parseFragment 再解析一遍（带位置信息），行号按文字开头的行数平移。两种都只收资源、不登记题；scriptMarkers 与 questions_in_script 的判定没变（template、noscript 里写标记照样报警告、不登记题）。

已知的局限（写在注释里，不影响验收）
- JS 用前一个记号区分正则与除号，`a++ /re/` 这样的少见写法会认错；为保持线性，同一行里先认错一次之后，那一段里的 `/` 都当除号。最坏的后果是正则里的引号被当成字符串的开头，那一行剩下的 import 漏掉，漏掉的文件会出现在 unreferenced_files_not_committed 里。
