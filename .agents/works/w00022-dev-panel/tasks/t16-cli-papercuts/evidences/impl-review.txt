### 1. 脚本 import 正则会自动提交注释和字符串里的文件，也会漏交合法的带注释 import

- **严重程度**：重要；**类别**：正确性。
- **位置**：`packages/dev-panel/src/core/references.ts:77-94`；`packages/dev-panel/src/core/artifacts.ts:710-719`。
- **现象**：入口引用 `app.js`，脚本中只有 `// import "./shot.png";` 与 ``const sample = `import "./notes.txt"`;``，真实发布退出 0、无警告，`shot.png` 与 `notes.txt` 都进入提交与版本 `files`。相反，合法的 `import /* webpackChunkName: "real" */ "./lib.js";` 不匹配，`lib.js` 留在工作区，被列为 `unreferenced_files_not_committed`，发布仍退出 0。
- **为什么是问题**：交付报告“注释里的 import 至多多一条 missing_reference”不成立：目标存在时会实际提交文件，且一旦进入 `files`，以后都作为种子保留。它重新把检查截图、本地草稿自动入库，违反此次只提交真实引用的目标；反向漏报又让干净 checkout 缺模块。基线没有脚本引用扫描，全部候选直接提交，因此漏模块是本次回归；基线提交截图是本 Task 本来要修的旧行为，本报告不把相同截图症状冒充新回归，而指出新白名单实现没有修掉这类输入。
- **如何核实**：`TMPDIR=/dev/shm/review-t16-impl-lab/tmp bun /dev/shm/review-t16-impl-lab/probes.ts` 的 `false-import`、`comment-import` 两组，各运行 HEAD 与 base。HEAD 第一组提交 5 个产物文件（含版本、2 个伪依赖），第二组只提交版本、入口、app.js 共 3 个，排除 lib.js；base 第二组提交 4 个（含 lib.js）。脚本内容与 Git 索引、提交文件列表均已核对，不用内部函数替代 CLI。
- **建议改法**：用轻量 JavaScript 词法扫描或已有解析器识别真正的 import/export；跳过注释、普通字符串和模板正文，接受 token 之间的注释。补真实 CLI 的正反例，同时断言误依赖不提交、合法模块提交；不能只测不存在的注释路径。

### 2. CSS 注释清理会删除字符串之间的真实规则，转义 URL 也会漏交资源

- **严重程度**：重要；**类别**：正确性。
- **位置**：`packages/dev-panel/src/core/references.ts:55-73`。
- **现象**：有效样式 `.a::before {content:"/*";}
.a {background:url(real.png)}
.b::before {content:"*/";}` 被 `blankComments` 从第一个字符串中的 `/*` 一直删到第二个字符串中的 `*/`，真实的 `url(real.png)` 消失。另一组有效的 `url(pic\ name.png)` 也完全匹配不到；加引号的 CSS 转义路径同样没有解码逻辑。
- **为什么是问题**：文件确实存在、被样式引用，但 HEAD 发布只提交入口、style.css 与版本共 3 个文件，图像作为“未引用文件”排除；base 两组都提交 4 个（含图）。发布退出 0，没有 missing_reference，干净 checkout 才缺图。这里不是脚本里动态拼地址的既定不支持项，而是普通 CSS 字符串与 URL 词法。
- **如何核实**：同一真实 CLI 实验的 `css-comment-in-string` 和 `css-escape` 组。HEAD 各给 1 个 `unreferenced_files_not_committed`，分别为 real.png、pic name.png，Git 索引不含它们；base 索引包含它们。全部样式和资源均由实验在独立仓库写入，没有替换依赖。
- **建议改法**：CSS 注释与字符串应在同一次词法扫描中识别，不能先全局正则删除；URL token 按 CSS 转义解码。补“字符串里含注释界符”和带空格转义路径的真实发布用例，断言引用资源进入提交。若决定不支持 CSS 转义，应明确错误或限制，不能把标准静态引用宣称为未引用。

### 3. 把模板的资源遍历与题目遍历一起跳过，会漏交明确写在 HTML 中的图片

- **严重程度**：重要；**类别**：正确性。
- **位置**：`packages/dev-panel/src/core/questions.ts:254-259`；`packages/dev-panel/docs/file-formats.md:219-227`。
- **现象**：页面含 `<template id="card"><img src="card.png"></template>`，普通脚本把 `template.content.cloneNode(true)` 加入 body。HEAD 发布退出 0，只提交入口与版本 2 个文件，card.png 被当作未引用排除；base 提交 3 个（含 card.png）。不含题目属性时也没有 questions_in_script 警告。
- **为什么是问题**：跳过模板里的提问标记是既有合同，但不等于资源不存在；静态写出的 src 无需分析脚本就能找到。原来全目录提交掩盖的解析缺口，在本次切换到引用白名单后变成了实际漏交。交付报告和新文档已经声明这项限制，因此不是“实现没照计划”；它是已接受偏离中实际破坏干净 checkout 的产品行为，unreferenced 提醒不能替代正确闭包。
- **如何核实**：真实 CLI 实验 `template` 的 HEAD/base 对照；核对入库文件列表与本地仍存在的 card.png。未启动浏览器，未声称观察到浏览器破图；cloneNode 的执行代码与遗漏的 Git 文件集都是真实输入与已观察结果。noscript 子节点同样被跳过，属于相同资源遍历设计，但本条运行证据仅覆盖 template。
- **建议改法**：把资源遍历和题目遍历分开。对 template.content 内节点只收集资源、禁止登记题目；对 noscript 内容根据 HTML 解析模式单独收资源。保留 questions_in_script 的题目提示，不能因为不登记题目而跳过资源。补模板依赖的 CLI 发布验收。

### 4. CSS 引用扫描有两处平方级路径，128 KB 异常输入就占住发布锁近 7 秒

- **严重程度**：重要；**类别**：安全与性能／不变量。
- **位置**：`packages/dev-panel/src/core/references.ts:13-16,60,73`；调用处 `packages/dev-panel/src/core/artifacts.ts:709`；锁范围 `packages/dev-panel/src/core/transaction.ts:375-376,464,515-519`。
- **现象**：每个引用的行号都从全文开头重新数换行。真实 CLI 发布含 5,000／10,000／20,000／40,000 行 `url(data:,x)` 的 CSS，HEAD 分别耗时 360／910／2,847／11,477 毫秒，base 为 154／138／142／163 毫秒。40,000 行仅 1,160,000 字节，data URL 最后虽不进图，前面仍全部计算行号。另一条独立慢路径是 CSS_URL 的相邻 `\s*` 在缺失右括号时回溯：`url(` 后只有 32,000／64,000／128,000 个空格，文件仅 32,019／64,019／128,019 字节，HEAD 耗时 514／1,630／6,795 毫秒，base 为 148／143／198 毫秒。
- **为什么是问题**：这不是循环引用不收敛，而是有限输入的平方级计算。发布在全仓记录锁内同步解析，其他 Work/Task/答复写入都被阻塞；面板每次重算 currentContentHash 也走相同解析，同步 CPU 工作还会阻塞服务事件循环。没有文件尺寸或引用数上限。基线只读取并摘要 CSS，没有这两条扫描，因此是本次新增的退化。
- **如何核实**：`TMPDIR=/dev/shm/review-t16-impl-lab/tmp bun /dev/shm/review-t16-impl-lab/performance.ts`；14 次真实 CLI 子进程、14 个独立 Git 仓库，全部退出 0，逐组对照 HEAD/base。没有直接调用内部解析器作为严重程度依据，没有 fake timer。以上数字是一轮实际测量，不声称精确基准或并发锁超时已经运行。
- **建议改法**：线性词法扫描同时维护行号与 URL token，或预建换行索引再单调推进；删掉可回溯的 URL 正则路径。用无右括号、长空白与大量 data 引用作为解析边界；可加有明确信息的资源上限，但不靠提高超时解决算法退化。
