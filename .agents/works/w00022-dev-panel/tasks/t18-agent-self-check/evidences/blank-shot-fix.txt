一、空白的根因
原来的 page:shot 认为两件事成立就算就绪：一是 `[data-window-state="ready"]` 出现，二是之后 DOM 连续 N ms 没有变化。
但窗口根是 PageOutlet 渲染的页面根，页面根挂上时，工作台页面的两块首屏内容还没出来：文档根的设置
（WorkbenchDocument）和外壳（WorkbenchShell）都是 defineAsyncComponent，开着之前只留一个注释占位。
Vite 开发模式逐个模块走 HTTP，冷启动时还要转译，所以动态 import 链里两次请求之间常常隔得比静默阈值还久。
DOM 在这段时间里一动不动，page:shot 就把空白的页面根截了下来。
复现：fix-before-1 是重启后的第一次截图，全白；fix-before-2 和 fix-before-3 是热的，有内容。
即使外壳出来了，编辑区、编辑器页面和欢迎页还有第二层按需加载（编辑区组件、页面实现模块、欢迎页的数据请求）。
只等外壳会截到半成品，第一轮修正时实测确实如此。

二、改法（改成用应用自己可观察的信号）
1. 页面标记 data-page-rendered（合同写在 src/web/PageOutlet.md 的“页面合同”一节，并登记到 browser-host Spec 的标记列表）
   - 工作台的 `/` 和 `/workbench` 页面（plugins/workbench/web/home-page.ts）由页面自己加载两块首屏
     （WorkbenchPagePart：load 与 props），不再交给 defineAsyncComponent。
     两块各自的 vnode 都挂上之后才在根上标 data-page-rendered。主体在首页与外壳之间切换时，等新主体挂上再标。
     不用 defineAsyncComponent 的原因：它会把包装组件的 vnode props 复制给内层组件，
     onVnodeMounted 会触发两次，判断不了内层什么时候挂上。
   - 加载状态由两页共用。页面再次挂载时同步渲染，不会空一帧。
     加载失败时用 reportPart 记一条 workbench.page error 诊断，页面根不标记，下次挂载时重试。
   - NotFoundPage 的主体是同步渲染的，根上直接写 data-page-rendered。
2. 加载中的区域标 aria-busy="true"
   - WorkbenchShell 的编辑区：defineAsyncComponent 设 loadingComponent，delay 为 0。
     占位带 aria-busy 与 data-workbench-editor-loading。已写进 WorkbenchShell.md 和 Spec ui/workbench-shell。
   - 编辑器页面（plugins/editor/web/pages.ts）：页面实现加载时占位带 aria-busy 与 data-editor-page-loading。
     已写进 Spec workbench/editor 输出 33。
   - 欢迎页（plugins/projects/web/welcome.ts）：有项目时，在数据请求完成之前根上带 aria-busy。
     已写进 Spec workbench/bookshelf 输出 20。
3. scripts/page-shot.ts
   - 去掉 DOM 静默启发式（READY_SELECTOR、QUIET_MS、SETTLE_LIMIT_MS、MutationObserver）。
   - waitRendered：等待 `[data-window-state="ready"][data-rpc-state="online"][data-page-rendered]`，
     或者宿主页的状态离开 loading、idle、starting（失败页本身也是要截的内容，报告里写 hostStatus）。
     超时（按 Playwright errors.TimeoutError 判断）时按缺的是哪个信号报出具体原因：
     a. RPC 不在线；
     b. 根已就绪但缺 data-page-rendered（提示看 PageOutlet.md，Lab 改用 lab:shot）；
     c. 宿主页仍在加载；
     d. 根和宿主页都没有。
     原因写进报告的 error，并以非零退出。
   - settle：用 rAF 逐帧检查，没有以下活动的帧连续数满 IDLE_FRAMES=2 才算稳定：
     a. 进行中或待开始的动画（document.getAnimations，覆盖骨架屏、spinner、进度条）；
     b. 可见的 [aria-busy="true"]；
     c. 视口内未加载完的图片。
     之后再等 document.fonts.ready。
     超过 --timeout 就报“画面 N 秒内没有稳定下来”，列出最多 8 项活动，并以非零退出。
   - 截图流程：goto → waitRendered → settle → steps →（有步骤时再 settle 一次）→ screenshot。
     CLI 在停在宿主页时打印“窗口没有就绪，页面停在宿主页：<status>”。

五、偏离与理由
  1. 不只在工作台页面根上加标记，还在编辑器插件（pages.ts）和 projects 插件（welcome.ts）加了 aria-busy。
     理由：只等页面根时仍会截到编辑区或欢迎页的半成品，实测出现过。要用应用自己的信号，就要由加载中的区域自己声明。
     这几处都已写进对应的 Spec 和组件 .md。
  2. 失败页（缺失项目、页面不存在）照常截图，以 0 退出，报告带 hostStatus。
     理由：失败页本身就是 Agent 要自检的画面，“截不了”只指画面没有就绪。
  3. /lab 不支持 page:shot（没有 data-page-rendered），会以非零退出，并提示改用 lab:shot。
  4. WorkbenchPageParts 的合同变了：renderDocument 和 renderShell 换成 document、shell（WorkbenchPagePart），另加 reportPart。
     调用方只有 plugins/workbench/web/plugin.ts 和 DOM 测试，两处都已改。
  5. 文档根设置和外壳加载失败时，现在记一条 workbench.page error 诊断。原来由 defineAsyncComponent 吞在 Vue 的错误处理里。
  6. 没有跑 e2e。
  7. settle 超时那条路径（动画一直不停）没有在真实运行时触发过，因为目前没有页面带常驻动画。只从代码推断它会生效。
