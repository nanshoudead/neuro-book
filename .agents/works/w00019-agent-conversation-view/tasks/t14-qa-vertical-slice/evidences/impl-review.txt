## 1. `markdownPreviewLine`：`****` 之后的全部正文被丢弃，并留下落单的 `*`

- **严重程度**：建议（偏重要）；**类别**：正确性
- **位置**：`packages/nb-agent-ui/src/format.ts` 的 `cut` 一段（约 85 到 90 行）
- **现象**：为了处理“首尾相接的粗体小标题”，只要正文里出现 `****` 就把这一段在 `****` 处截断并丢掉其后所有内容。打码文字、掩码、乘方记法里的 `****` 都中招。实测：
  - `"卡号 **** **** 1234 后四位"` -> `"卡号 *"`
  - `"密码是 ****** 请保密"` -> `"密码是 *"`
  - `"key=**** 然后继续读第三章"` -> `"key="`
  - `"A****B"` -> `"A"`
- **为什么是问题**：折叠行里露出的是半截句子加一个孤零零的 `*`，违反 Spec 验收 30 与 `markdownPreviewLine` 注释自己写的“不误伤正文、预览里不出现标记符号”；而且这是静默丢内容，读者看不出被截了。真实场景：Agent 讲到 API key、密码、打码账号时的思考与提醒。
- **如何核实**：`bun /tmp/claude-1000/review-t14-impl/probe2.ts`（前四行）。
- **建议改法**：只在 `****` 两侧都是“粗体收尾紧接粗体开头”的形状时截断，即 `\*\*(?=\S)[^*]+?\S\*\*\*\*(?=\S)`（前面有开启的 `**`、后面紧跟非空白非星号）；单独的 `****`、`*****` 当普通文字。并把“卡号 **** 1234”加进 format.test.ts 的“不误伤”表。

## 2. `markdownPreviewLine`：行首的 `__` 与路径里的 `_x_` 被当成强调，标识符被改写

- **严重程度**：重要；**类别**：正确性
- **位置**：`format.ts` 的 `stripInline`：行首 `^(\*{2,3}|__)(?=\S)` 一条，以及 `(^|[\s\p{P}\p{S}])(__|_|\*)…\2(?=$|[\s\p{P}\p{S}])` 一条
- **现象**（实测）：
  - `"__init__.py 要改"` -> `"init__.py 要改"`（行首 `__` 无条件去掉，后面的 `__` 却留着，两头都不对）
  - `"改 `a.ts` 与 __init__.py"` -> `"改 a.ts 与 init.py"`
  - `"读 tests/__fixtures__/a.json"` -> `"读 tests/fixtures/a.json"`
  - `"读取 chapters/_draft_/01.md"` -> `"读取 chapters/draft/01.md"`
  - `"https://example.com/__init__.py"` -> `"https://example.com/init.py"`
  - `"__init__ 与 __main__"` -> `"init__ 与 main"`
- **为什么是问题**：Spec 验收 30 要求 `snake_case`、`读取_章节_摘要` 保留，同类的文件路径、dunder 名与 URL 却被改写，预览里显示的是一个不存在的路径。`/` 被 `\p{P}` 当成“标点边界”是原因：路径分隔符后的 `_x_` 满足“外侧是标点”。“行首落单的 `**`/`__`”那条规则写在配对规则之后，却不看后面有没有配对的收尾，所以会把已经成对、只是紧贴文字的 `__init__` 切成一半。
- **如何核实**：`bun /tmp/claude-1000/review-t14-impl/probe1.ts` 与 `probe2.ts`。
- **建议改法**：单个 `_`、`__` 强调的外侧边界不把 `/`、`.`、`:`、`\` 算进去（只认空白、行首行尾和 `()[]{}"'“”‘’，。！？；：、` 这类括号引号与句读）；落单标记规则只在整行里确实没有成对的收尾时才去（先数一次）。同时加路径与 dunder 的反例。

## 3. `markdownPreviewLine`：行内代码把相邻的强调与链接切断，标记原样留在预览里

- **严重程度**：建议；**类别**：正确性
- **位置**：`format.ts` 里按行内代码把正文切成 `pieces` 再逐段 `stripInline` 的那段
- **现象**（实测）：
  - `"[`foo.ts`](src/foo.ts) 要改"` -> `"[foo.ts](src/foo.ts) 要改"`（模型写“带代码的链接”很常见，链接语法整个留下）
  - `"前 **bold `x`** 后"` -> `"前 **bold x** 后"`
  - `"**`a`**"` -> `"*a*"`（还多出一对被半去掉的星号）
  - `"[a](http://x.com/a(b))"` -> `"a)"`（URL 里带括号）
- **为什么是问题**：函数注释和 Spec 都把“预览行里不出现 `**` 之类的符号”当目标，这几种在模型输出里并不罕见（加粗的工具名、带文件名的链接）。切段后每一段单独处理，成对规则必然够不着跨代码的配对。
- **如何核实**：`bun probe2.ts`。
- **建议改法**：行内代码不切段，而是和转义一样先换成占位符、去完标记后再还原（占位符里不含 `*`、`_`、`[`、`]`），这样强调与链接规则可以跨过代码；链接 URL 部分允许一层括号。

## 4. `markdownPreviewLine`：第一行去标记后为空时不往下找，折叠行变成空白

- **严重程度**：建议；**类别**：正确性
- **位置**：`format.ts` 的 `escaped.split("\n").find(...)`：先按原文选定“第一行非空正文”，再去标记，去完为空就直接返回空串
- **现象**（实测）：
  - `"<system-reminder>\n记得保存\n</system-reminder>"` -> `""`
  - `"![](x.png)\n说明文字"`、`"<br>\n正文"`、`"# \n正文"`、`"> \n> 引用正文"`、`"- \n- 项"` -> `""`
  - `"**\n正文"` -> `"*"`（只剩一个星号）
- **为什么是问题**：改动前折叠行至少露出原文第一行；现在整行只有标签与空白，用户看不出这条提醒是什么，也看不出能点开。信息条目（提醒、自定义系统消息）正是宿主任意写的文字，以 `<系统标签>` 或图片开头并不罕见。
- **如何核实**：`bun /tmp/claude-1000/review-t14-impl/probe5.ts`。
- **建议改法**：对候选行逐行去标记，取第一个去完仍非空的；都为空再返回空串。

## 5. `markdownPreviewLine`：每次渲染对整段思考文字做全量正则，单行很长且标记多时是平方级

- **严重程度**：建议（不改也可，列出数字供取舍）；**类别**：代码质量
- **位置**：`format.ts` 的 `markdownPreviewLine`、`stripInline`；调用点 `AgentTextStepRow.vue` 的 `renderers.markdownPreview(props.text)`（思考流式生成时每个 token 都重算）
- **现象**：函数只要第一行，却先对整段文字做转义替换，再对整条首行跑带 `[^]*?` 的惰性正则。实测一行里重复 ` **a`：8000 字符 62 ms，32000 字符 1.0 s，128000 字符 16.7 s；` *a`、` _a`、` ~~a` 同形，32000 字符 0.2 到 0.3 s。常见的几百到几千字符的首行没有问题；真实风险是模型把整段思考写成不分行的一大段并带很多未闭合的标记，在流式期间每个 token 重算一次。
- **如何核实**：`bun /tmp/claude-1000/review-t14-impl/probe4.ts`。
- **建议改法**：预览只会显示一行（CSS 还会截断），选定首行后先截到固定长度（例如 400 字符）再去标记；截断可能把标记截成半截，本函数已经处理“落单的标记”，不新增问题。

## 6. 单个 `*` 强调紧贴汉字时原样保留，行尾时又只去掉一半

- **严重程度**：建议；**类别**：正确性 / 测试
- **位置**：`format.ts` 的单个 `*`、`_` 规则与行尾“落单强调符号”规则；`format.test.ts` 的 `"1) 第一步：*读*目录"` 用例
- **现象**（实测）：
  - `"他的*钥匙*在哪"`、`"中文*斜体*中文"`、`"*斜体*文字"` -> 星号原样保留（CommonMark 里这些都是斜体）
  - `"中*注*"` -> `"中*注"`（行尾规则去掉最后一个 `*`，前一个留着，既不是原文也不是去标记后的结果）
  - `"**"` -> `"*"`，`"** A **"` -> `"* A *"`（流式刚输出开头的 `**` 时露出一个星号，下一个 token 又消失，折叠行会闪一下）
  - 测试里把 `*读*` 残留写成了期望值（`["1) 第一步：*读*目录", "第一步：*读*目录"]`），把“为了不误伤 `2 * 3 * 4` 而放弃汉字旁的斜体”固化成了合同。
- **为什么是问题**：这是有意的取舍（`2*3*4` 与汉字旁的斜体在字符上分不开），但行尾半去与流式闪烁不是取舍的结果，是规则互相叠出来的。中文正文里用 `*` 强调很常见，预览里留星号与注释“预览里不出现 `**` 之类符号”的说法不一致。
- **如何核实**：`bun probe1.ts`、`probe2.ts`。
- **建议改法**：区分“两侧都是数字或拉丁字母/数字的 `*`”（乘号，不动）与“至少一侧是汉字或标点”（强调，去掉）；行尾规则只处理与前面某个开启标记成对的情形。如果决定保留现状，把 `*读*` 那行从期望里拿掉，改写进“已知不处理”的说明，别让它看上去像被验证过的行为。

## 7. `markdownPreviewLine` 把没加反引号的泛型与比较式当 HTML 标签删掉

- **严重程度**：建议；**类别**：正确性
- **位置**：`format.ts` 的 `.replace(/<\/?[A-Za-z][A-Za-z0-9-]*(?:\s[^<>]*)?>/gu, "")`
- **现象**（实测）：`"Promise<void> 返回"` -> `"Promise 返回"`，`"List<String> x"` -> `"List x"`，`"if a<b>c"` -> `"if ac"`；`"Map<string, number>"` 因为带逗号后的空格形状不同而幸存。
- **为什么是问题**：写代码类任务时思考里不加反引号的类型名很常见；预览里的类型被改成另一个类型。HTML 标签预览的价值（`<mark>`、`<b>`）与它相比小得多。
- **建议改法**：只去已知的几个行内标签（`mark`、`b`、`i`、`u`、`strong`、`em`、`br`、`code`、`span`、`sub`、`sup`、`del`、`s`），其余原样。

## 8. 没有文字的助手消息的附注块（`annotations`）整条渲染路径没有任何测试

## 13. 宿主注入的 `markdownPreview` 没有像其他宿主回调那样套保护

- **严重程度**：建议；**类别**：不变量（失败与恢复）
- **位置**：`packages/nb-agent-ui/src/vue/host.ts` 的 `markdownPreview: given.markdownPreview ?? markdownPreviewLine`；调用点 `AgentTextStepRow.vue`、`AgentTurnBlock.vue` 的模板
- **现象**：工具渲染器的 `summary`、`effects`、`diff`、`groupPhrase` 都由 `guardTool` 包了 try/catch 并回退，Spec“失败与恢复”写了“回调抛错时该项按通用写法显示”。`markdownPreview` 是同一类宿主回调，却直接在模板里调用；它抛错时这一步的组件渲染失败（开发环境下 Vue 只打 console.error，该行消失）。另外端口要求“只返回一行”，返回含换行的串或非字符串时也没有规整。
- **为什么是问题**：与同一包里其他宿主回调的失败策略不一致；宿主按自己的方言写的解析器恰恰比包内缺省更容易在没见过的输入上抛错。
- **如何核实**：从代码推断（没有在运行时复现）。
- **建议改法**：在 `useAgentRenderers` 里把宿主函数包成 `(text) => { try { return firstLine(given(text)) } catch (error) { 诊断; return markdownPreviewLine(text) } }`，与 `guarded` 同一写法，并补一个注入抛错函数的 DOM 用例。

## 14. 会话列表：读屏重复、被截断的标题没有完整文字、浮层里高亮材质

- **严重程度**：建议；**类别**：代码质量（UI）
- **位置**：`packages/nb-agent-ui/src/vue/AgentSessionList.vue`
- **现象**（均从代码推断，没有在浏览器里看）：
  1. 运行中的行里 `<Spinner :label="运行中">` 渲染成 `role="status" aria-label="运行中"`，旁边又有可见文字“运行中”。整行是一个 `<button>`，按钮的可访问名称由内容拼出，会读成“……运行中 运行中”。
  2. 标题与说明都是单行省略，行上没有 `title`，长标题（Lab 场景里“南嘉鱼知道心月狐就是苏天晴吗？其他魔法少女呢？”在 280 宽下就被截断）看得见的人读不到全文；读屏用户不受影响。
  3. 组件的设计用法之一是放进下拉（`header: false`）。nb-ui 规范“开发后自检”要求玻璃浮层里的项高亮用 `--overlay-item-active`，不用实色 `--bg-hover`；这里 hover 用 `--bg-hover`、选中用 `--accent-bg`，放进下拉时的材质没有人看过（计划与 Lab 都只在 280 宽的实底方框里）。
  4. `updatedAt` 不是有限数（宿主漏填的 `NaN`）时，`new Date(item.updatedAt).toISOString()` 与 `formatListTime` 都抛 `RangeError`，一行坏数据让整个列表渲染失败。这条属于过度防御的边缘，列出供取舍。
- **建议改法**：1 把 Spinner 包进 `aria-hidden` 或不给 `label`；2 行或标题上加 `:title`；3 下拉形态用 Lab 场景在浮层里看一眼，必要时给列表一个 `surface` 属性切换高亮 token；4 视取舍。

## 15. `EntryRendererEntry` 现在允许既没有 `messageKind` 也没有 `customType` 的条目

- **严重程度**：建议；**类别**：代码质量（类型）
- **位置**：`packages/nb-agent-ui/src/registry.ts` 的 `EntryRendererEntry`
- **现象**：`messageKind` 改成可选、`customType` 可选，`{id, component}` 两样都不写也能通过类型检查，登记了却永远不会被任何消息用到，`checkEntryTypes` 也不会提示。注释自己承认“按消息类型匹配的那一半还没有消费者”。

## 16. 结果工具“运行结束时还没有结果”的处理依赖适配器把状态改成出错，视图自己没有兜底

- **严重程度**：建议；**类别**：正确性（文档与实现对不上）
- **位置**：`conversation-turns.ts` 第 383 到 386 行的注释“被退回（出错、参数无效，或运行结束时还没有结果）”与 `rejectedOutcome` 的判断；Spec 验收 29 末句“运行结束时仍没有结果的结果调用同样是一行”
- **现象**：`rejectedOutcome` 只看 `toolCallPhase(call.status) === "error"`。`createHarnessTranscript` 的 `applyRunEnd` 会把没等到结果的调用改成 `error`，所以经它接入的宿主是对的；不经它的宿主（或消息已 `stopped`/`interrupted` 却仍把调用留在 `running`/`streaming`）得到的仍是 `node`。实测：`[user, assistant(status: "stopped", toolCalls: [answer(streaming)])]` 得到块 `[node]`，且这一块被收进过程（`outcomeStart` 等于块数、可收起），整轮收起后什么都看不到，展开后看到的是一张永远“在写”的宿主节点卡片。

- **如何核实**：`bun /tmp/claude-1000/review-t14-impl/probe6.ts` 的 S11 一行。
- **建议改法**：二选一：把 `finished && phase === "running"` 也算作被退回（与注释和 Spec 一致，改一行），并在测试里把 `status: "stopped"` 加上 `running` 状态的用例；或者把注释与 Spec 改成“适配器负责把结束时没有结果的调用标为出错”。
