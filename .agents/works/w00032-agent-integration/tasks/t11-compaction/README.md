# 上下文压缩

## 目标与范围

定上下文压缩的触发（手动、溢出、阈值）、摘要模型、压缩条目与恢复。

来源：清单外第 1 项（[报告](../t01-survey/artifacts/report/index.html)）。

合同：本 Task 只做设计讨论，行为合同未变；定稿后在计划里写明改哪些 Spec。

## 要讨论的问题

- 触发：手动 `/compact`、溢出后、一轮结束超过阈值。
- 摘要用哪个模型（角色，t09）；压缩条目的形状与恢复。
- 与会话树（在某个分支上压缩）、工具发现的缓存边界的关系。
- 插件贡献压缩方法。

## 讨论进展（2026-10-28）

事实见[外部参照](../../../../../docs/research/agent-runtime-references.md)“上下文压缩”一节（omp、Claude Code 的源码与提示词）。

开发者第一轮意见：

- 固定 80% 不行（1M 与 256K 窗口的 80% 差别很大），参考 omp。
- 分清“就地压缩”（用原模型、吃得到缓存）与“摘要模型压缩”（上下文交给摘要模型），后者可以先 shake 再交摘要模型；摘要模型单独一个角色，缺省为 fast。
- 要调研摘要的输出格式与压缩提示词（Claude Code、omp、phistory）。
- 压缩块要能点开看详细。

调研纠正一处：omp 里吃得到缓存的是 handoff（原样上下文加一条请求），不是 soft；soft 把对话序列化成文字、换摘要系统提示词，即使同一个模型也吃不到缓存。Claude Code 的压缩是就地的。
