== 重要 ==

F01 SuggestionMenu 外框里没挡 mousedown 的区域会夺走宿主焦点。
  位置：SuggestionMenu.vue 外框（内边距 4px）与 header 容器；PromptEditor.vue 的 menuOpen、onContentFocusOut、历史菜单 header。
  现象：mousedown.prevent 只在列表视口与加载行上。reka PopoverContent 外包的 FocusScope 给内容加了 tabindex="-1"，
  点内边距或标题行时焦点进了外框：@ / $ 菜单因正文失焦而关掉；输入历史的焦点离开搜索框，方向键、回车、Escape 失效。
  静态页在 Chrome 核实了前提（tabindex=-1 容器里点内边距与静态文字会夺焦点）。
  建议：外框统一加 mousedown，目标不是可聚焦元素时 preventDefault；补 e2e。

F02 Menubar 的级联面板：悬停把焦点带进面板，面板却没有键盘处理。
  位置：Menubar.vue 的 MenuLevelPanel 没有 keydown；MenuNodes.vue 的 onButtonPointermove。
  现象：base 悬停时焦点留在 reka 内容里；现在焦点进了子菜单按钮，上下、Home、End、左右键都不处理，只有 Escape 能关。
  建议：Menubar 接和 DropdownMenu 同一套级联键盘，最好抽进 useMenuCascade 三处共用；补 e2e。

F03 同级子菜单换内容时，复用的级联视口保留上一份内容的 scrollTop。
  位置：useMenuCascade 同级替换；DropdownMenu 的 :key="depth"；usePopupScroll 不重置 scrollTop。
  现象：长子菜单 A 滚过后切到同样长的同级 B，B 打开就是滚下去的。popup-scroll 的用例是长换短，碰不到。
  建议：换内容时视口回到顶部；补长换长的 e2e。

== 建议 ==

F04 Menubar 多组菜单共用一份滚动状态，退场中的旧菜单会套上新菜单的截断高度、内边距与渐隐。
  建议：每组菜单各自持有 usePopupScroll。
F05 reka 主层级（DropdownMenu 与 Menubar 一级、Select）的键盘导航用原生 focus，越界时把项滚到中间；
  静态实验：238px 视口里一步滚 133px。级联层用 focusPopupItem 只滚最少距离，两者不一致，文档的“滚最少的距离”只对后者成立。
  建议：主层级也调 revealPopupItem，或文档只承诺级联层。
F06 revealPopupItem 不留边距，滚进来的项正好落在 22px 的渐隐里。建议：让开渐隐高度。
F07 普通按钮项（右键菜单、手工级联）指针离开后高亮不清（没有 pointerleave），与 reka 项不一致。
  建议：pointerleave 时把焦点交给所在层级的容器。
F08 拖动滑块中视口被卸载（按住时按 Escape），endDrag 不会被调，下次打开滑块仍是“拖动中”。
  建议：setViewport 换视口时调 endDrag。
F09 SuggestionMenu 根是 role="dialog"，带指向不存在的触发器的 aria-labelledby（reka Popover 写死，宿主覆盖不了）。
F10 Select.md 残留旧实现：窗口监听 mousemove/mouseup、useDropdownFloating、env:global 标签。
F11 测试：
  - suggestion-menu.spec.ts“关闭后不再逐帧读锚点”替换 requestAnimationFrame 计数并固定等 300ms，属于 spy 加固定等待；
  - 计划映射里“追加候选后滑块与渐隐跟着变”“窗口缩放、输入框内滚动后重新定位”“DropdownMenu 与 Select 的键盘移到看不见的项”没有用例；
  - Menubar 悬停后的键盘（F02）、长换长（F03）、点外框内边距（F01）没有用例；
  - lab-markdown 输入历史用例的 startsWith(chosen.slice(0, 6)) 太弱；
  - measurePopupTruncation、revealPopupItem 没有单元测试。
F12 边界与小问题：
  a. measurePopupTruncation 对没有布局的视口返回 0，得到 maxHeight: 0px，靠后续观察器自愈；
  b. measureCascadePanel：项不超过 8 个但窗口矮到被夹紧时宽度没算滑块槽，内容右侧被裁 6px；
  c. MutationObserver 回调里只 observe 不 unobserve，被替换的子元素一直被观察；
  d. ContextMenu 打开时的夹紧按没加滑块槽的宽度量，可滚动后右边距从 8px 缩到约 2px。

参照（旧应用 ReferenceSelectorPopover）有、计划与实现没有的：项的第二行说明（新实现映射成右侧 hint，放不下先截）；
最小宽度不低于锚点矩形宽度（对 0 宽的光标锚点无影响）；前缀标记的标题栏。均为已知取舍，审查者只做标注。

未发现问题的方面：collapseBelow 与 truncate；新结构下的外部点击判定；高亮不会同时亮两项；选项 id 的累计；
toGroups 与旧分组等价；compact、menuMaxHeight、active 的调用方已迁完；ColorSwatches 内边距不变；trackSide 的启停；
.nb-ui-menu-surface 写出 padding 后没有别的使用方受影响。
