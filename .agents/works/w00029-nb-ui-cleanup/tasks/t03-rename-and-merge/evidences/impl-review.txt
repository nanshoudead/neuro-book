# w00029 t03 实现审查报告（只追加）

## 1. [重要] 正确性 / 不变量：Banner 动作区 `shrink-0` 使 220px 编辑组里按钮溢出，换行形同虚设
- 位置：`packages/nb-ui/src/components/feedback/Banner.vue:56`（`<span v-if="$slots.actions" class="flex shrink-0 flex-wrap ...">`），用于 `packages/neuro-book/src/plugins/editor/web/components/EditorGroup.vue:304-308`
- 现象：动作区自己是 `flex-wrap`，但又 `shrink-0`，宽度被固定为全部按钮并排的 max-content，不会收窄到父级宽度，里面的 `flex-wrap` 不起作用。组件文档说“动作区整组换到下一行”，只对“按钮并排宽度不超过一行”成立；超过时按钮直接冲出横幅右边。旧实现（按钮直接是外层 `flex-wrap` 的子项）会逐个换行。
- 核实：用 `/opt/google/chrome/chrome --headless=new --screenshot` 加载真实 `dist/nb-ui.css`、按 Banner 模板手写的静态页（`/tmp/w29t03/review/exp/t.html`，截图 `t.png`），容器 220px（box-sizing: border-box，与 `docs/specs/workbench/editor.md` 编辑组最小 220px 一致）：
  - zh-CN 冲突条两个按钮“重新载入磁盘版本 / 覆盖磁盘版本”并排 212px，可用宽度 196px，右按钮右沿超出容器右边 4px（含内边距）；
  - en-US（`messages.ts:48-49` 的 “Reload Disk Version / Overwrite Disk Version”）并排 273px，右按钮右沿超出容器右边 65px，会被编辑组的 overflow 裁掉或造成横向滚动。
  - 把 `shrink-0` 换成 `max-w-full`（`t2.html`、`t2.png`）后两个按钮各占一行，全部可见可点。
- 为什么是问题：违反 `editor.md` 输出 54“编辑组最小（220×120）时……提示条的按钮……都仍能用”；这是本次改动引入的回归（旧手写状态条按钮可单个换行）。
- 建议改法：动作区去掉 `shrink-0`，改 `max-w-full min-w-0`（保留 `flex-wrap`）。补一个 dom 或 e2e 用例：Banner 放进 220px 宽容器，两个长按钮的 `getBoundingClientRect().right` 不超过容器右边（jsdom 不排版，需浏览器用例，由主 Agent 跑）。Lab 场景“带两个动作”目前在 `max-w-[640px]` 下，看不出这个问题，可再加一个 220px 宽的场景。

## 2. [重要] 正确性 / 可访问性：`SegmentedControl` 在 `modelValue` 没有匹配项（`null`）时没有任何 Tab 停靠点，键盘用户进不去
- 位置：`packages/nb-ui/src/components/controls/SegmentedControl.vue` 的按钮 `:tabindex="isSelected(option) ? 0 : -1"`；调用处 `packages/neuro-book/src/plugins/lab/web/LabShell.vue:208-219`（`activePreset` 在手动拖出尺寸时返回 `null`）和 `LabShell.vue:759-768`
- 现象：本次让“画布宽度”预设条在手动拖出尺寸时传 `null`（意图是“一个都不选中”），而该组件的 roving tabindex 只给选中项 0，其余全是 -1。此时三个按钮都 `tabindex=-1`，Tab 键跳过整个控件，只能用鼠标回到某个预设。
- 同一路径的第二个小问题：`handleKeydown` 里 `currentIdx` 为 -1 时，ArrowLeft/ArrowUp 算出 `(−1 −1 + n) % n = n−2`（3 个选项时落在第 2 项，不是最后一项）；ArrowRight 落在第 1 项，两个方向不对称。
- 文档层面：`SegmentedControl.md`（状态节）写“没有匹配项时不显示选中项或指示块”，但没写键盘怎么进入；本次新写的分工段还说它“始终选中一个”，与 LabShell 的用法自相矛盾。
- 如何核实：从代码推断（未跑浏览器）。可在 `components.test.ts` 里挂载 `modelValue: null`，断言至少一个按钮 `tabindex="0"`；主 Agent 可在 Lab 拖一下画布边缘后按 Tab 验证。
- 建议改法：二选一。（a）组件里没有选中项时让第一个启用项 `tabindex=0`（并把 `currentIdx<0` 时 ArrowLeft 定到末项）；（b）LabShell 不传 `null`，找不到预设时给一个“自定义”选项或用 `disabled` 的占位项。选 (a) 要同步写进 `SegmentedControl.md` 的交互与状态节，并补单测；`SegmentedControl.md` 的“始终选中一个”改成“通常有一个选中”。
