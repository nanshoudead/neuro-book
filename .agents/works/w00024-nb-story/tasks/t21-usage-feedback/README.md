## 反馈清单

1. **GitHub 上已有 issue 与 PR**：开发者已在 GitHub 开了一些，先读远端（只读不需授权），对照下面几条合并去重。
2. **图结构分级（先记录，后续优化方向）**：很多记录记得太细，多半是作者随手写的、后面用不到。图里不止“记录”这一处可以用分级：抽取时让模型给每条（说法、对象、情节等）标一个重要程度，查询与问答默认只用高等级，需要时再展开。要定：分几级、标在哪些对象上、模型标得稳不稳（要真实模型评测）、对已有书库的兼容。
3. **关系图操作**：
   - 搜索不好用，且不能按别名查；
   - 右键点节点后移动鼠标，节点跟着动，此时上下文菜单还开着；
   - 没有任何提示告诉用户“双击节点打开节点详情”。
4. **设置与命令行**：
   - `nbstory import`（导入）为什么要带 library 参数：不好用，要重新看参数设计；
   - 大部分命令行功能都要能在网页上用；
   - 书架页与设置页没有主题调节，书页没有设置入口。
5. **问答**：
   - 点“图当目录”时要弹出提示，写明它的优点与弊端；
   - 问答页要显示整个会话的缓存等状态，旧代码已实现过，要去找；
   - “新对话”现在按当前位置（例如第 59 回）回答，要改成：允许用户自己调整章节，调整后给 Agent 发一条 system-reminder（随下一次用户提问一起发）；书还没抽完时，允许 Agent 读后续章节原文，但图工具不可用。

6. **中转站脱敏（开发者 2026-10-27）**：issue 和文档里不写中转站的域名与服务商名，用中性占位。2026-10-27 扫描：仓库里约 130 处、30 来个文件含旧写法，分布在 Task 记录与脚本（t03 到 t20）、`docs/proposals/nb-harness-profile-and-tools.md`、nb-story 的配置校验与设置页示例（`config-schema.ts`、`ProviderDialog.vue`）及测试、`e2e/qa.e2e.ts`、Lab 场景；远端 #256 到 #259 的正文也有。已进入 Git 历史的不改写历史；远端 issue 的编辑属远端写入，要先问；环境变量名（`JIJI_*`）在开发者本机 `.env` 里，改名会让本机配置失效，要先问。
7. **nb-story 与 omp 完全独立（开发者 2026-10-27）**：不读 `~/.omp` 下任何配置。#256 因此只改报错与 README。
