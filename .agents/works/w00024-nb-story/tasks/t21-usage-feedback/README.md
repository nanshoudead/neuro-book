## 《老师，男生也能报考魔女学院吗？》的图质量反馈（2026-10-27，开发者经 ssh 给出数据）

数据：pc-notype 的 `AppData\Local\nbstory\book-8080e749\graph-164.json`（164 章、281 个对象、2,638 条说法），已拷到本机 `/tmp/t31/`（不入库）。开发者提的六点与我的核实：

1. **银色闪光就是银空，没有归并**。核实：`e18-1`（第 18 章茶会账号“银色闪光”，persona）与 `e19-1`（第 19 章出场的银发魔女“银空”）之间没有任何 `identity` 说法；但第 25 章有一条说法 `s25-1`“银空说……”的 `about` 挂在 `e18-1` 上，说明抽取时模型其实把它们当成了同一个人，只是没写连接。属抽取遗漏：规则要求“马甲和本人用一条 identity 说法连起来”，没做到。
2. **洛萱为什么是星瑕的亲属**。核实：两人之间没有任何 kinship 说法。关系图的边词“亲属”来自关系词推断：星瑕这个点的成员有 `e24-2`（菲娅，与星瑕同一个人，已归并），而 `s51-5`“洛萱认为菲娅算是自己的直系后辈”被模型标成 kinship。这是魔女“师承辈分”，不是血亲；程序在亲属说法里找不到亲属词时仍写成“亲属”（`relationWord` 的兜底）。两层问题：抽取把辈分标成 kinship；程序对没有亲属词的 kinship 兜底成“亲属”。
3. **泛指当成人物**。核实：52 个 person 加 19 个 persona 里，有大量只有泛称的对象：`e76-5` 名字是“那个学生、男生、新生、小伙”（540 次出场）、`e4-1` 学姐/志愿者（524）、`e70-2` 新生（281）、`e16-1` 女人/小姨（30）、`e81-1` 学生会的学姐、6 个“学姐”对象等，还有名字为空的人。名字里的“学姐、新生、老师、少女、女人、男生”这类泛称被当作称呼登记，段落扫描把每处出现都记成这个对象的出场，所以出场数被严重虚高，也污染了同场、关系图的权重。规则里“身份不明的人先建一个对象、以后点明再连”与“泛称不登记”互相打架。开发者说 V7 设计里解决过又被否决，我在 w00005 的任务目录里没有找到这一条的记录，需要他提示在哪个 Task。
4. **关系图的过滤控件刷新就重置**：要进浏览器偏好（`host/prefs.ts`）。
5. **同心图半径偏小**。
6. **有没有把线条也考虑进去的布局（少交叉、少重叠）**：需要设计：候选有 ELK（elkjs 的 layered、stress、force）、Kamada-Kawai/stress majorization、圆环排序减交叉；要出对比图让开发者选。
