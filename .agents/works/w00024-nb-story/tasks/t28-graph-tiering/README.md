# 图结构分级的小实验

## 目标与范围

[t21](../t21-usage-feedback/README.md) 反馈 2：很多记录记得太细，抽取时让模型给每条记录标一个重要程度，查询与问答默认只用高等级。开发者 2026-10-27 批准先做小实验再决定是否进管线，预算约 ¥5，真实模型调用。

只回答一个问题：**模型事后给已有图的记录标重要程度，标得稳不稳、有没有用**。不改管线、不改查询。

## 结果（2026-10-27）

模型 gpt-6-luna（密钥来自仓库根 `.env` 的 `JIJI_LUNA_*`，脚本经环境变量读，没有写进任何文件），样例书前 20 章，427 条（对象 54、说法 323、情节 50），两遍独立标注，每遍 20 批。费用：两遍合计输入 47.5K、输出 17.1K token，按 deepseek-flash 低谷价折算约 ¥0.12。原始标注见 [第一遍](evidences/tiers-run-1.json)、[第二遍](evidences/tiers-run-2.json)。

| 指标 | 结果 |
|---|---|
| 分布 1/2/3（第一遍 / 第二遍） | 133/229/62；133/216/75 |
| 两遍完全一致 | 68.2%；加权 κ 0.546（中等） |
| 按种类的一致率 | 对象 61%，说法 68%，情节 80% |
| 两遍都不是 3 级的占比 | 89.6%（只留 1、2 级几乎不减少记录） |
| 对象：出场次数与重要度的 Spearman | 0.37（弱正相关，n=54） |
| 说法按类别的平均级别 | 身份 1.20、规则 1.73、目标 1.72、事件 1.82 最重要；态度 2.18、地点 2.40 最次 |

结论：**不建议把“模型给每条记录标重要程度”放进管线**。
- 稳定性中等：三成多的记录两遍给了不同级别；
- 区分度低：提示词要求“1 级应当是少数”，模型仍把 31% 标成 1 级，只有约 16% 标成琐碎，默认只用高等级也只能省掉一成多的记录；
- 与结构信号只有弱相关，说明标的不完全是随机的，但也没有比出场次数这类免费的信号更好。

按类别的差别是一条可用的线索：身份、规则、目标类说法普遍更重要，态度、地点类更次要。如果以后确实要分级，更便宜也更稳的做法是不让模型逐条标，而由程序按“类别、出场次数、被后面章节引用的次数”算一个等级；要验证它，需要另一轮真实问答实验（比较只用高等级的记录时问答正确率是否下降），不在本 Task 内。

脚本：[scripts/tier-label.ts](scripts/tier-label.ts)（`--dry`、`--run N`、`--analyze`）。对象相关性与按类别的统计是另写的一次性代码，没有入库。

## 追加：程序算的等级（2026-10-27，开发者要求先做 a）

[`scripts/program-tier.ts`](scripts/program-tier.ts)，不调用模型。信号：类别先验、除主角外涉及对象的后文出场次数、被引用次数（被确认、被秘密收录、被别的角色知情）、涉及对象多少；每种记录内按分位定级（前 25% 为 1、接着 40% 为 2、其余为 3）。页面（nbdev 产物 `program`）有和模型的对照与西游记 100 回上的实际样子。

对照样例书前 20 章的模型两遍标注：

| 记录 | 条数 | 程序分与模型平均级别 Spearman | 模型两遍之间 | 程序 3 级里模型两遍都没标 1 级的 | 程序 1 级里模型两遍都没标 3 级的 |
|---|---|---|---|---|---|
| 说法 | 320 | 0.45 | 0.61 | 97% | 98% |
| 对象 | 54 | 0.38 | 0.61 | 83% | 85% |
| 情节 | 50 | 0.35 | 0.59 | 55% | 100% |

- 第一版把主角也算进“后文活跃度”，涉及主角的说法后文出场都上千，没有区分度（说法 0.35）；排除出场最多的三个主角后升到 0.45；
- 两端比中间准：要隐藏的程序 3 级说法里，模型两遍都当主线必需的只有 3%；
- 情节最弱（只靠参与者热度与所属主线大小），需要别的信号；
- 程序等级用的是整本抽完后的信息，新增章后要重算；模型在抽取当时拿不到这些。

### 程序版的修正与“先验加后验”（开发者 2026-10-27 反馈）

开发者指出“南小风的父亲在南小风和花铃回家后叫她们吃饭”被程序标成 1 级，肯定错了。原因：涉及对象“南小风”后文出场 405 次，对象热度把一条日常小事拉高。对象热度回答的是“这个人重要吗”，不是“这件事重要吗”。修正：

- 对象热度的权重降低，加一个说法本身的后验信号“事件词组的后文回响”：说法里不含对象名的 4 字词组，出现在 2 到 12 个章（太常见的不算）且在本章之后的章里再次出现；“叫她们吃饭”回响 0 个，“强化药A”“每日任务”这类设定会反复回响。说法的 Spearman 从 0.45 升到 0.48；
- 这条说法从 1 级降到 2 级；程序只靠排名分级时无证据的说法停在中间档，仍不是 3 级，所以真正的修正是下面的合并。

开发者的方案（先验加后验，两者共存）：模型在抽取当时给先验（黑盒、一般准），程序事后给后验证据（透明、可核对、不一定准）。合并规则可写出来（`program-tier.ts` 的 `combine`）：证据强（被引用，或回响 3 个以上）则升，先验 3 级的升到 2（伏笔候选）；无证据的先验 1 级降到 2（待证实）；其余沿用先验。这条说法先验 3、无证据，合并后是 3 级。
