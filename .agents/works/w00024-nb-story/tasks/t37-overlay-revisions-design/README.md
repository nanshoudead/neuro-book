## 决定（2026-10-28，开发者答复 `20261028T123143979Z-930ded64`）

1. **确认放哪（`confirm-place`）**：C，待确认页汇总加人物卡就地确认，两处是同一份数据与动作。
2. **范围（`edit-scope`）**：B，第一版做身份连接（确认、驳回、手动连）、改对象种类、挪称呼；合并对象、改说法类别与挂靠不做，用过之后再定。
3. **事后扫描（`scan-product`）**：覆盖层先做，扫描另起 Task，作为覆盖层的第三个来源。
4. **规则（`rules`）**：确认，按评审板上的六条写 Spec：修订从依据段起生效；只改显示不改抽取数据，接着抽与追加新章时保留；待确认的不生效，驳回的不再被同一来源重复提出；后文明说自动关闭；每条可撤销；重抽后按“对象加原文位置”对应，对不上的转“待重新确认”。
5. **备注里的问题**：马甲核对与事后扫描是程序自己发现的，能不能抽取时自动、做成可选的自动确认、不确认就停止抽取。照推荐处理（待开发者追认，已记入待确认清单）：
   - 马甲核对本来就在抽取时自动运行（t35）；它的结果进待确认，是因为一句“可能是”写成“确定”后会合并出场、知情等派生数据，错了用户看不出来。第一版不做自动确认，也不让抽取停下等人：抽取要跑几小时，停在人这里会整夜卡住，而候选不确认也只是显示“可能是”，不会错并。
   - 修订记录的状态里留出“自动采纳”这一档（与“你确认”分开显示、同样可撤销），以后若实测核对的准确度够高，给马甲核对加一个“结果直接采纳”的开关，不用改数据格式。事后扫描不适用：它的真问题只占约三分之一，只能人工过目。
   - 抽完后在进度与命令行汇总里写“N 条待确认”，让用户知道有东西要看。
