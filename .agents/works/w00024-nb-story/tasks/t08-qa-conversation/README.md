## 要先定的事（2026-10-16 会话里列出，待设计时给开发者）

1. **对话与记录的关系**：倾向新增“对话”，含若干轮，每轮仍是一条记录，沿用 `qa/` 存储，记录加对话 id。技术上 nb-harness 创建时会读已有会话日志里的消息接着跑（`packages/nb-harness/src/harness.ts` 约 115 行），从代码推断可行，未试过。
2. **阅读位置**：对话内 P 只允许不变或往后；往回拨必须开新对话，否则前面轮次读过、写过的后文剧情留在上下文里，防剧透失效。
3. **20 章上限**：倾向按轮算，已读章在对话内保留、同一章不重复计数。
4. **全读**：原文在第一条消息里，P 不变可复用，但上下文逐轮变大，需要上限和提示。
5. **回归**：现有 232 份回归是单问的，对话模式要自己的评测，至少覆盖指代追问（“他后来呢”）和防剧透。
6. **延迟**：luna xhigh 单问中位数 129 到 388 秒，最长约 28 分钟；网页连续对话需要流式进度和可取消。
