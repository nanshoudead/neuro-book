# 程序找出没连上的马甲、模型答窄问题的实验

## 目标与范围

程序圈出没有确定身份连接的马甲，按章问模型“这个马甲是不是已有的哪个人、或者根本不是马甲”；在魔女学院与样例书上量召回、提前下结论的比例与费用，决定是否接进抽取管线

只做实验，行为合同未变：不改产品代码、提示词与 Spec。来源：[t33](../t33-graph-issue-reports/README.md) 的建议。计划见 [plan.md](plan.md)。

## 当前状态

2026-10-28 经 nbdev 新建；开发者同意按 t33 的建议用 autonomous-delivery 推进，这是第一步。计划已写，交 omp 做计划审查。

## 计划审查（2026-10-28）

omp（默认模型）审第 1 版：[报告](evidences/design-review.txt)，阻断 3、重要 6、建议 2，都成立，计划改成第 2 版。

| 条 | 问题 | 处理 |
|---|---|---|
| 1 | 遮掉身份说法后原文与标签仍直接给出答案 | 部分接受：原文明说正是“漏写了但原文写着”的场景，不删；跑前按程序规则把用例分成原文明说、标签泄漏、需推断三层，分层报告 |
| 2 | 闭包含物品边；只有候选边的马甲没处理 | 有效边只认两端都是 person 或 persona；候选用例单列；马甲链上任一成员都算对；金标跑前冻结 |
| 3 | 只问揭示章前后 3 章，答不了“最早”与“提前” | 从马甲出现到书末按触发规则问；答出确定的 same 后停（产品语义） |
| 4 | 触发规则作用域不清，可能漏揭示章 | 写死为“称呼出现在本章，或本章新建任意人物或马甲”；干跑列出揭示章是否被触发，漏的单独报告 |
| 5 | 材料可能不含揭示段；12 段口径不清 | 加入第 k 章原文全文；命中段加邻段合并后取最近 12 段 |
| 6 | 揭示前答对怎么判没冻结 | 写成程序规则：原文同段出现双方称呼与身份词判“原文已明说”，否则按 certainty 判提前确定或提前猜 |
| 7 | 对照几乎没有观测 | 改用全书触发；未触发记“未观测” |
| 8 | 记录键会冲突 | 键含用例名与章，启动时断言唯一 |
| 9 | 预算常量沿用 t33 的 19 | t34 自己的检查，硬停止 ¥10 |
| 10 | `truncate` 不递归截断嵌套位置 | 只投影选定字段，干跑递归检查位置不晚于第 k 章 |
| 11 | 费用与字节只有局部数字 | 干跑给全部请求的字节数与费用估算；超出目标时第 2 遍缩小范围并写明 |

第 2 轮（同一会话续审第 2 版）：[报告](evidences/design-review-2.txt)。上一轮 11 条到位 7 条；新增阻断 2、重要 3，都成立，计划改成第 3 版（见 plan.md“第 3 版的改动”）：
