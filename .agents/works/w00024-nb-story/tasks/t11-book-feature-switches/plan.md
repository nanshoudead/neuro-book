# t11 实施计划：按书关闭数值与秘密

## Context

开发者 2026-10-20 在 t10 讨论里定：数值（状态变动 `ledger`）与秘密要能按书关闭，默认都开。很多小说用不上数值，游戏文才要；没有身份秘密的书，秘密那一套也是空转。关掉以后抽取不写这类记录，“已有记录”不列，查看器不显示对应页面，问答不提供对应查询。

依据：[`story.ingest`](../../../../../docs/specs/story/ingest.md)、[`story.queries`](../../../../../docs/specs/story/queries.md)、[`story.viewer`](../../../../../docs/specs/story/viewer.md)、[`story.qa`](../../../../../docs/specs/story/qa.md)；t10 README 的决定 3（数值、秘密按书开关，默认开，另立 t11）。

约束：两项都开时（默认），发给模型的每个请求与 t10 合入时逐字相同，已验证过的质量不受影响（`chapter.test.ts` 对照录下的请求）。

## 关键设计

### 开关是什么、存在哪里

- `BookFeatures = {ledger: boolean; secrets: boolean}`，缺省都为 `true`。
- **新建时定，之后不改。** 原因是数据里已经存在或缺少的记录无法补救：关掉的书从来没抽过这类记录，事后打开只能从当前章往后有；开着的书事后关掉，只是隐藏已有的数据。这两种情况都要另写“从第几章起”的规则，这次不做。要换设置就删书重抽。
- 存两处：
  - 抽取记录的 `source.json` 多一个 `features` 字段，接着抽、追加时读它。旧记录没有这个字段，按都开处理。
  - 书的数据里 `book.features` 是可选字段，由 compile 从抽取记录带入，查询从这里取。导入的 V9 数据文件可以带这个字段，不带就按都开处理。数据格式只加了一个可选字段，旧文件照常读。

### 发起：`src/cli/ingest.ts`、`src/server/ingest-service.ts`、`src/ingest/runner.ts`

- 命令行：`nbstory ingest <文件> --no-ledger --no-secrets`。网页：`ingest.start` 多一个可选参数 `features`。
- 只有新建（`new`）时可以设。接着抽、追加或已抽完的书带了与保存值不同的开关时，返回 `invalid_params`（命令行退出码 2），写明“开关只能在新建时设，要换请删除后重抽”，什么都不改。带了相同的值则照常进行。
- `ingest.preview` 与 `ingest.status` 的结果多一个 `features` 字段：新书给出将要使用的值，已有记录给出保存的值。导入页靠它显示。

### 抽取：`src/ingest/prompts.ts`、`context.ts`、`reconcile.ts`、`chapter.ts`

- **系统提示词不变**，规则全文和示例照旧。这样所有书共用同一个前缀缓存，验证过的文字也不动。要改的只有每次请求末尾的【任务】段：
  - `draftTask`：输出字段清单里去掉关掉的那几项。“写之前逐项对照”与“自查”里只讲数值的条目（当前状态、账本、任务进度）去掉；只讲秘密的条目（秘密清单，新的秘密）去掉，讲知情的条目保留。末尾加一句：“这本书不记数值（ledger）和秘密（secrets）：不要写这两部分，说法也不写 secret 字段。”
  - `reviewTask`：`replace` 里去掉关掉的那几项，“对账”与“身份”两条处理原则里提到数值、秘密的部分随之去掉。
  - 两项都开时，函数输出与现在逐字相同，用一个参数切换，不另外复制一份文字。
- **已有记录**（`renderContext`）：关掉秘密时不出“秘密与知情”一节；关掉数值时不出“当前状态”一节。整理用的全量已有记录也按这条处理。
- **核对清单**（`buildChecklist`）：关掉数值时不开“对账”“任务”“工具”三类条目。“身份”一条照开，它要的是 identity 说法，与秘密开关无关。
- **模型仍然写了关掉的记录时**，在编译之前去掉。“编译之前”包括草稿刚写好时和每次修复之后。要去掉的是：
  - 关掉数值时：`ledger`；
  - 关掉秘密时：`secrets`、说法的 `secret` 字段，以及 `about` 指向秘密的知情记录。

  这样去掉的条数记成这一章的一条问题说明，例如“按书的设置去掉 3 条数值记录”，**不计入**输出 13 的丢弃数：丢弃数反映的是抽取质量，这些记录本身没有错。
- **关掉秘密时，知情还记。** 知情记录指向说法的那部分照常抽取，也照常由程序生成：样例书 337 条模型写的知情里，有 112 条指向说法；另有 1019 条由程序从心理活动和听众生成。人物卡里“他知道的事”、视角合并、问答的“谁知道什么”都靠这些记录。

### 查询：`src/core/dataset.ts`、`src/contract/contract.ts`、`src/core/queries/books.ts`

- `books.list` 的每本书与 `book.info` 都多一个 `features` 字段。
- 其余查询方法不改。关掉的书里本来就没有这类记录，`secrets.matrix`、`ledger.*` 自然返回空结果，人物卡的秘密格与情节摘要里的揭晓秘密、数值变动也都是空的。

### 查看器：`src/web/shell/BookFrame.vue`、`OverviewPage.vue`、`DrawerCard.vue`、`BookGraphPage.vue`、`ImportPage.vue`

- 导航里隐藏关掉的页（秘密、数值）。地址直接指向这两页时，改为打开全书总览，并提示“这本书没有记录数值”或“这本书没有记录秘密”。地址仍是公开接口，旧链接不会报错。
- 全书总览：关掉的项不显示对应的数字块与“秘密矩阵（精简）”一块，“这一章发生了什么”里也不出对应的行。人物卡不显示秘密一节。全书图的类型开关里不出“秘密”。
- 导入页：新书在“开始抽取”上方放两个开关：“记录数值（钱、道具、任务进度）”和“记录秘密（身份秘密与谁知道）”，默认都开。接着抽或追加时，只用一行字写明这本书保存的设置。
- 进度页不改。

### 问答：`src/qa/tools.ts`、`src/qa/engine.ts`

关掉数值时，查询命令里没有 `ledger`、`track`；关掉秘密时没有 `knows`。命令表和发给模型的说明都按书生成。

## Spec 与文档改动

- `ingest.md`：
  - 命令表加 `--no-ledger`、`--no-secrets`；网页方法表的 `ingest.start` 加 `features`，`ingest.preview` 与 `ingest.status` 的结果加 `features`。
  - 新增一条输出：开关的含义、只在新建时设、违反时报什么错；输出 4 加一句“关掉的那类不列”；输出 13 写明按设置去掉的记录不计入丢弃数。
  - “副作用与数据”写 `features` 存在哪里。
- `queries.md`：`books.list`、`book.info` 加 `features`；“边界与兼容”写明 `book.features` 是可选字段，缺省都开。
- `viewer.md`：导航与地址的规则（输出 2 与“边界与兼容”）、全书总览（输出 8）、人物卡（输出 10）、全书图（输出 31）、导入页（输出 37）。
- `qa.md`：查询命令按书的设置提供。
- 包内 `AGENTS.md`：都开时请求必须逐字不变这条约束已经有了，不另加。

## 切片

1. **数据与发起**：`features` 的类型、存储，`ingest.preview`、`ingest.start`、`ingest.status`，命令行参数，只在新建时设的检查，`books.list`、`book.info`。同时提交 Spec 的 ingest、queries 部分。
2. **抽取**：任务文字、已有记录、核对清单、编译前去掉关掉的记录、问题说明。
3. **查看器与问答**：导航、地址回退、全书总览、人物卡、全书图、导入页的开关、问答命令。同时提交 viewer、qa 部分的 Spec。
4. **评测**（要开发者批准花费，见“验证”）。

每片自跑 `bun run typecheck` 和受影响的测试；第 3 片另跑查看器 e2e。

## 验证

- 确定性：受影响的单元测试、类型检查、查看器 e2e。
- 真实模型（**要开发者批准**）：用 gpt-6-luna 把样例书前 20 章抽一次，两项都关，约 1.5 元、20 分钟。看三件事：
  - 每章都能提交，数据里没有数值与秘密；
  - 53 条关键记录的尺子，去掉秘密、数值两类后的得分，和 t10 三次回归里同一部分的得分相比；
  - 每章的输入、输出 token 和费用，与 t10 回归相比。

  这一项不设门槛，只是确认关掉以后其余记录的质量没有变差，并给出省了多少。
- 两项都开的路径与 t10 逐字相同，不重跑回归。

## 不做与风险

- 不做事后改开关，也不做“从第几章起”的规则。
- 系统提示词里仍有数值、秘密两节规则和示例，模型偶尔还会写出这两类记录，由编译前去掉兜底。这一点与“自然不写”的效果差多少，靠上面的真实模型评测来看。
- 开关只省抽取的输出 token，以及已有记录里的两节，省不了系统提示词。系统提示词在各章之间不变，本来就走前缀缓存。
