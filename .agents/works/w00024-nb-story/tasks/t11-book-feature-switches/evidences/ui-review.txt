### 1. 全书图自带图例在关掉秘密的书里仍列“秘密”
- 严重程度：建议
- 类别：与 Spec 邻近条款不一致 / 残留
- 位置：packages/nb-story/src/web/graph/StoryNetwork.vue:630-635（`legend`，data 模式）
- 现象：BookGraphPage 只改了类型开关（chip）一行，StoryNetwork 的 data 模式图例是写死的七项，只按 `hiddenTypes` 去掉“悬念”。关掉秘密的书里，图例仍有一个红色“秘密”色块，图里却永远没有这类点。
- 为什么是问题：输出 31 要求“没有秘密这类点，类型开关里也没有它”，图例是同一页上对这一类的第二处展示；用户会找图上那个红点。
- 如何核实：新建关秘密的书，打开全书图“按关联”，看图例。
- 建议改法：给 StoryNetwork 的 data 模式一个可去掉的类型入参（或把 BookGraphPage 里算出的可用类型传进去），图例和 chip 共用同一份清单；顺手把 BookGraphPage 模板里那一长串内联 filter 提成 computed。

### 2. e2e 只测“两项全关”，且若干分支与断言空转
- 严重程度：建议
- 类别：测试覆盖
- 位置：packages/nb-story/e2e/ingest.e2e.ts:163-230；packages/nb-story/src/web/host/book.ts:255-264
- 现象与依据：
  1. 只有“数值、秘密都关”一种组合。混合情况（只关秘密、只关数值）没有覆盖，而 StatsPage 的 `closedKeys`、ChapterBars 的 `hidden`、总览数字块只在单关时才分得清谁该留谁该去（例如只关秘密时数值块、数值图例必须还在）。
  2. `router.afterEach` 里“当前页已是总览时直接 `syncRoute()`”这一支没有被走到：用例是在 stats 页上手改到 secrets，走的是 `page.value = "overview"` 那一支。这一支是在 afterEach 钩子里调 `router.replace`，时序最特别，只有它没被测。
  3. 手机“更多”导航单（BookFrame.vue:317-324 的 `nav`）没有 390px 下的断言，只测了宽屏 `nav[aria-label="页面"]`。
  4. 统计页的断言全是 `not.toContainText`，没有正向断言（例如图例里还有“说法”“知情”“情节”，表里还有“说法”行）。图没渲染出来时这几条同样通过；总览也没有断言数值数字块已消失（“身份秘密”“秘密矩阵”有，“数值”没有）。
  5. 用例里的 `reading.set` 轮询等待靠的是“库里 view.page 变成 overview”，这在该书从未保存过时成立（本用例就是这种情况），可是写法依赖这个前提，没有注释。
- 为什么是问题：回退链有三条入口、两个分支，本次变更的主要风险点正在这些边上。
- 如何核实：读用例；在 afterEach 的 `page.value === "overview"` 分支加一次 `throw`，用例仍通过。
- 建议改法：加一个“只关秘密”的用例（或把现有用例参数化为两种组合），补手机宽度的“更多”断言、总览已在总览时手改 `/secrets` 一次、统计图例与表的正向断言。

### 3. 总览数字块只剩两三块时，auto-fit 网格把块拉得很宽（未目测）
- 严重程度：建议
- 类别：版式
- 位置：packages/nb-story/src/web/pages/OverviewPage.vue:144-148（`.tiles`，`repeat(auto-fit, minmax(150px, 1fr))`）
- 现象：auto-fit 会把空列折叠，剩余块平分整行。两项全关时只剩“人物与事物”“未解悬念”两块，在宽屏主区各占约半行；390px 下三块（关一项）排成 2+1，最后一块只占半行。四块时原本的外观不变，所以这是新出现的状态。
- 为什么是问题：宽屏下数字块与下面的两栏区块宽度关系被打乱；`design-language.md` 自检清单要求宽度随内容的元素不拉满整行（SKILL 三、1）。
- 如何核实：新建关两项的书，在 ≥1400px 和 390px 各看一次总览（我没有跑，从样式推断）。
- 建议改法：给 `.tiles` 的块设最大宽度（例如 `minmax(150px, 240px)` 加 `justify-content: start`），或四块以内改固定列数。

### 4. 同样的提示在 8 秒内重复出现时，后一次会被前一次的计时提前清掉
- 严重程度：建议
- 类别：状态一致
- 位置：packages/nb-story/src/web/host/book.ts:257-259（`notice.value = ...`）与 packages/nb-story/src/web/shell/BookFrame.vue:201-205（`watch(notice)`）
- 现象：同一本书里 8 秒内两次手改地址到关掉的页，第二次给 `notice.value` 赋同一串文字，值没变，`watch` 不触发，计时不重置；第一次的计时到点就清掉它，第二次提示只剩残余时间。
- 为什么是问题：用户第二次操作后提示可能一闪而过。影响很小，只在手改地址时出现。
- 如何核实：在 afterEach 里连续两次进入关掉的页，看 `data-testid="notice"` 的存留时间。
- 建议改法：可以不改（过度防御）；若要改，让提示带递增序号，watch 序号。

### 5. 可读性：ChapterBars 里 `series` 重名，`.md` 描述未提隐藏
- 严重程度：建议
- 类别：可维护性 / 文档
- 位置：packages/nb-story/src/web/parts/ChapterBars.vue:16-27、packages/nb-story/src/web/parts/ChapterBars.md:7
- 现象：模块级 computed 叫 `series`，`geometry` 里又有局部常量 `SERIES`（大写像常量其实是 `series.value`）和回调参数 `series`，三个同名不同物。`.md` 的描述段仍写“按说法、知情、情节、数值四类堆起来”，只在数据块里加了 `hidden`；`hidden` 也与 HTML 全局属性同名，读的人容易当成属性。
- 为什么是问题：同名遮蔽使这次改动难审（例如 `reduce((sum, series) => ...)` 读起来像在用 computed）。
- 如何核实：读文件。
- 建议改法：computed 改叫 `shownSeries`，回调参数改 `item`；`.md` 描述段补一句“可用 `hidden` 去掉某类”；prop 可改名 `omit`。
