## F1 导航角标按全书算，不按阅读位置：数目与页面对不上，还泄漏后文
- 严重程度：重要　类别：正确性（防剧透）
- 位置：`src/web/shell/BookFrame.vue:49`（`revisionBadge`）、`src/web/host/book.ts:176`（`book.info` 不带 `at`）；Spec `viewer.md` 输出 58、`revisions.md` 第 49 行
- 现象：`revisionBadge = book.info.revisions.pending + stale`，而 `book.info` 是 `client.call("book.info", {book})`，没有 `at`，服务端补成 `extractedThrough`（`core/api.ts:179`），所以角标是全书的待确认数。待确认页、人物卡候选块却按阅读位置取。实测（样例书，`nbstory revisions list --at N --json`）：at=10、at=29 时列表 `counts.pending=0`，at=30.61 与 at=100 时为 1；而角标在任何阅读位置都显示 1。读到第 10 章的人：导航写“待确认 1”，点进去页签写“待确认”、卡片区写“没有需要确认的”。
- 为什么是问题：Spec `revisions.md` 第 49 行明写“`book.info` 另给 revisions，按阅读位置算（与列表一致），供导航的角标用”；viewer 输出 6 的防剧透原则也不允许页面泄漏阅读位置之后的信息，角标数目告诉读者“后文有一条身份候选”。`contract.ts:79` 的字段注释同样写“按阅读位置算”，BookFrame.vue:48 的注释却写“按全书算”，实现与合同相反。另外 `book.info` 只在 `refresh()` 时重取，换阅读位置不会重取，就算服务端改成按位置算，角标也不会随位置变。
- 如何核实：`cd packages/nb-story && bun src/cli.ts import <sample.json> --id fox --library <tmp>`，再 `bun src/cli.ts revisions list --library <tmp> --book fox --at 29 --json` 看 `counts`；对照 `core/api.ts:179` 与 `book.ts:176`。e2e 里角标只在 at=30.61 断言，样例书又只有一条待确认，所以看不出差别。
- 建议改法：角标不要读 `book.info.revisions`，由 BookFrame 用 `useStoryQuery("revisions.list", () => ({limit: 1}))` 取 `counts`（带阅读位置与数据版本，自然随位置与写入重取）；或让 `book.info` 在每次换位置后带 `at` 重取。e2e 补一条：at 在 30.61 之前时无角标、之后出现。

## F2 修订对话框的“每次打开重置”是死代码，改种类与挪称呼的默认值是错的
- 严重程度：重要　类别：正确性
- 位置：`src/web/shell/ReviseDialog.vue:21-41`（`watch(() => props.open, …)`）、`src/web/shell/DrawerCard.vue` 的 `<ReviseDialog v-if="reviseMode" …>`
- 现象：DrawerCard 用 `v-if="reviseMode"` 挂载对话框，每次打开都是新实例，`open` 一开始就是 true；`watch` 默认不是 immediate，不会触发，所以重置逻辑从不执行，各 ref 保持声明处的初值：`newKind = "person"`，`name = ""`。后果：
  1. 对一个本来就是“人物”的对象点“改对象种类”：`newKind` 是 `"person"`，但 `SegmentedControl` 的选项已排除当前种类，界面上没有任何一项被选中，而选了依据段后“改种类”按钮可点；提交的就是 `kind: "person"`，服务端回 `revision_conflict`（`ops.ts:127` “已经是这个种类”）。用户什么也没选却得到一条莫名其妙的错误。
  2. 挪称呼：本意是默认选第一个称呼（`names[0]`），实际 `name=""`，没有选中项，用户必须先点一个称呼；依据段列表也是在不带 `text` 过滤的状态下列全部段落。
  3. 注释“每次打开重新开始，不带上次的选择”描述的行为实际由 v-if 重建实例提供，这段 watch 既无用又会误导后来者。
- 为什么是问题：e2e 的改种类用例用的是 `e3-2`（样例书里 kind 是 persona），默认值 `person` 恰好不同，所以用例碰巧通过；遇到人物就是上面 1。`newKind.value as "person"`（第 79 行）这个类型断言把 `string` 硬转成 `"person"`，正好掩盖了“初值和选项集不一致”的问题（`KINDS` 的 `value` 没有用 `EntityKind` 类型，类型检查帮不上）。
- 如何核实：`ls /tmp/review-t38-impl/exp-web/watch.ts`（用 Vue 的 `createSSRApp` 复现同构的“open 初值为 true 的组件里非 immediate 的 watch 不执行”，输出 `<div>person</div> []`）；样例书 `e30-1` 是 persona，`e1-1` 等人物对象可直接试。从代码推断，浏览器里没点过。
- 建议改法：去掉 watch，直接在 setup 里按 props 初始化（`newKind` 取第一个不等于当前种类的种类，`name = names[0]`），或给 watch 加 `{immediate: true}`；把 `KINDS` 写成 `Record<EntityKind, string>` 或复用 `host/kinds.ts` 的 `KIND_LABEL`，去掉 `as "person"`；`ready` 里加 `props.mode !== "kind" || newKind.value !== props.kind`。e2e 补一条在人物对象上改种类的用例。

## F3 手写“章.段”没有按阅读位置限制，Spec 要求“晚于阅读位置的段不能选”
- 严重程度：重要　类别：正确性
- 位置：`src/web/shell/ReviseDialog.vue:48-49`（`chosenEvidence`、`ready`），`submit` 第 71-83 行
- 现象：依据段列表由 `revisions.evidence` 按阅读位置给，没问题；但“或直接写章.段”的输入框只判断非空，不看是否晚于 `book.at`。写入类方法没有 `at` 参数（`WriteBook`），服务端 `ops.ts:46-49` 只校验“章.段”存在且是已抽取的段（`evidence_invalid`），所以在阅读位置第 3 章时输入 `80.5` 会成功写入。写入成功后，因为依据在阅读位置之后，当前页面“看不到变化”，用户得到的是一次无声的成功（待确认页与卡片都按阅读位置过滤，也看不到这条修订）；而用户等于凭手输入选了一个后文的依据，违背 viewer 输出 60“晚于阅读位置的段不能选”。
- 为什么是问题：Spec 把限制放在界面（因为写入方法没有阅读位置）；实现只在列表里满足，手写路径绕开了。e2e 的“失败写在对话框里”只测了 `999.1`（不存在的章），没测“存在但晚于阅读位置”。
- 如何核实：`ops.ts` 里 `evidence_invalid` 只有三种（格式、章不存在、段超范围）；ReviseDialog 全文没有引用 `book.at`。
- 建议改法：在对话框里解析 `typed`，晚于 `book.at`（用 `host/book.ts` 已有的位置比较）时 `ready` 为 false 并在 typed 输入旁写原因（不要在字段下加行：见 F9，写进 Dialog 的 `status`）；格式不对也提前判断，而不是等服务端。

## F7 待确认页：来源筛选后列表空白且不写“没有需要确认的”；“已处理”靠前端过滤状态
- 严重程度：重要　类别：正确性
- 位置：`src/web/pages/RevisionsPage.vue:31`（`total`）、`:24-27`（`done`/`processed`）、`:92-98`（`PagedList` 的 `total`、`empty-text`）；`src/web/parts/PagedList.vue:45`
- 现象：
  1. 待确认页签的 `total` 取 `counts.pending + counts.stale`，而 `counts` 是服务端“全书的，不受筛选影响”的计数（`revisions.md` 第 40 行）。`PagedList` 只在 `total === 0` 时显示 `emptyText`。所以在有待确认项的书里点来源筛选“我的”（用户自己的修订不会是待确认，这个组合永远为空）、或点与现有项不同的来源，列表是空白的，没有“没有需要确认的”，`total` 却是 1。样例书（一条 `extraction`/`persona-check` 待确认）上点“我的”必现。
  2. “已处理”页签的 `done` 查询不带 `state`（服务端只支持单个 state），结果按依据位置混着 pending、stale 排列（`items.ts:109`），前端再 `filter` 掉未处理的；`total` 用的是过滤后已加载的条数。若前面各页全是待确认项（真实长书里待确认可以很多），第一页 100 条里一条已处理都没有，`total=0` 而 `hasMore` 为真：会先写“还没有处理过的”再翻页；翻页要靠 `PagedList` 的哨兵逐页取，等于把全部待确认项读一遍才找得到已处理的。页签上的数字（adopted+rejected+closed）与实际列出的也可能不一致（见 `STATE_WORDS.withdrawn`，列表其实不返回 withdrawn，是死分支）。
- 为什么是问题：1 是默认界面上点一下就能见到的空白；2 在条数少的样例书上看不出来（样例书只有 3 条），e2e 覆盖不到。
- 如何核实：样例书导入后 `nbstory revisions list --source user --json` 得 `items:[]`、`counts.pending:1`；对照 `RevisionsPage.vue` 的 `total` 与 `PagedList` 的空态条件。2 从代码推断。
- 建议改法：空态按“已加载完且列表为空”判断，或 `total` 用本次查询的 `total`（`stale.total + pending.total`，`usePagedQuery` 已暴露）；“已处理”用服务端的 state 组合（三次查询或给 `revisions.list` 加 `state: "done"`），去掉前端过滤与 `withdrawn` 死分支。

## F8 修订对话框没有把 `busy` 交给 `Dialog`：写入期间能取消或按 Esc 关掉，结果无处可显示
- 严重程度：重要　类别：不变量 / 界面规范
- 位置：`src/web/shell/ReviseDialog.vue:94`（`<Dialog …>` 没传 `:busy`）、页脚取消按钮 `:123`
- 现象：nb-ui `Dialog` 有 `busy` 属性：“busy 时遮罩、取消按钮、关闭按钮与 Escape 都不生效，页脚按钮与关闭按钮禁用”（`Dialog.md` 的“交互”）。ReviseDialog 自己有 `busy`，只用来禁用“提交”按钮，没传给 `Dialog`，也没禁用“取消”。请求在途时用户点“取消”、点遮罩或按 Esc，对话框关闭（`update:open=false`，DrawerCard 里 `v-if` 把组件卸载），而请求照常写入服务端：用户以为取消了，数据已改；失败时错误信息随组件消失，没有任何反馈。
- 为什么是问题：写入不可撤回地改了图（虽然能在已处理里撤销），“取消”应当意味着没写。Spec 输出 62 要求“请求期间禁用对应按钮”，Dialog 提供了现成的整套禁用。
- 如何核实：读 `ReviseDialog.vue` 的 `<Dialog>` 属性；`Dialog.vue:66,257,263,387,400` 处理 `busy`。从代码推断，没在浏览器复现。
- 建议改法：`<Dialog :busy="busy" …>`，取消按钮 `:disabled="busy"`。

## F9 修订对话框违反 UI 规范第 5 节：错误写在正文里、选择列表没有角色与状态、`<label>` 不关联控件
- 严重程度：建议（界面规范）　类别：界面规范
- 位置：`src/web/shell/ReviseDialog.vue:105-116`（`.lab` 的 `<label>`、`.list`/`.row` 的按钮列表）、`:113`（错误 `<p>`）
- 现象与依据（`packages/nb-ui/docs/ui-development-spec.md` 第 5 节）：
  1. 第 8 条：“提交之后才知道的错……对话框里是页脚左侧的状态行（Dialog 的 `status`），一次只写一条”，且“出错时不在字段下插入文字”。实现把 `revise-error` 作为正文里的 `<p>` 插进内容，出错时正文变高、依据段列表与按钮被推动。应传 `:status="error ?? ''"`。
  2. 第 5 条：复合选择控件必须暴露正确的角色和状态。对象搜索结果与依据段两个列表是 `ul > li > button.row`，选中只靠 `.on` 的底色，没有 `aria-pressed`/`aria-selected`/`role`，读屏用户听不到哪项被选。nb-ui 已有 `SearchSelect`（combobox，带键盘与 aria）与 `RadioGroup`，计划里也写了“对象搜索沿用 SearchBox.vue”，实现却手写。
  3. 五个 `<label class="lab">` 没有 `for`，也不包裹控件，是装饰性标题却占了 label 语义；应是 `<p>`/`<span>` 并用 `aria-labelledby` 指向列表，或用 `Field`。
  4. 对象搜索没有“没有找到”的空态，也没有输入防抖（`SearchBox.vue` 用 250ms 防抖，这里每个按键发一次 `entities.list`）。
- 为什么是问题：这些是 nb-ui 规范明写的规则；第 1 点还会造成布局位移，第 2 点是键盘与读屏无法完成“选对象”。
- 如何核实：读代码对照规范第 5 节。从代码推断，没有用读屏或键盘实测。
- 建议改法：见各点。

## F10 修订对话框的选择项显示原始种类代码，种类名与全站不一致，称呼只能选前 8 个
- 严重程度：建议　类别：界面规范 / 正确性
- 位置：`src/web/shell/ReviseDialog.vue:12-21`（`KINDS`）、`:100`（`{{ item.kind }} · 出场 …`）、`:103`（`names.slice(0, 8)`）
- 现象：

## F11 隐藏通道声明不准：`.md` 的标签与理由与实现不符，ReviseDialog.md 还写了一个不成立的保证
- 严重程度：重要　类别：不变量（组件文档规范）
- 位置：`src/web/shell/ReviseDialog.md`、`parts/CandidateBlock.md`、`parts/RevisionCard.md`、`pages/RevisionsPage.md`
- 现象：`docs/standards/code/components.md`“声明是对实现的如实描述……实现用了某条通道而未声明，以实现为准，整份声明不予采信”；“任何 `io:` 标签：为什么该请求不能由宿主发起并把结果传入”。对照同包既有声明：

## F13 写入流程里的几处时序与状态问题
- 严重程度：建议　类别：正确性
- 位置：`src/web/host/revise.ts:20-37`（`run`）、`RevisionsPage.vue:41-61`、`CandidateBlock.vue:10-20`
- 现象：
  1. `run` 在写成功后 `await book.refresh()`，但忽略它的返回值：`refresh()` 失败时不 reject、只写 `notice` 并返回 false（`book.ts:361-376`），这时 `run` 仍返回成功，页面照旧显示未处理的卡片与可点的按钮，`last` 里还写着“已确认”；再点一次得到 `revision_conflict`。
  2. 成功后 `busy` 在 `refresh()` 一完成就变回 false，但各列表的重取要等 `dataVersion` 变化触发后再发请求（`query.ts` 的“版本变了留着旧数据”）。这段时间（一个往返）里旧卡片与可点的“确认”还在，快速再点会得到冲突错误。
  3. 失败时只显示错误、不重取：`revision_conflict`（别处已处理，例如命令行 `nbstory revisions confirm`）、`revision_target_not_found` 说明页面数据已过期，但界面一直停在旧数据上，错误会重复出现；Spec 输出 62 只说“数据不变”，但对这几个码刷新一次更合理（可用 `book.refresh()`）。
  4. 页面卡片、人物卡候选块、对话框各自 `useRevise()`，`busy` 互不通：在人物卡里确认的同时，待确认页同一条的“确认”没被禁用，两处并发写同一条。
- 如何核实：读 `revise.ts` 与 `book.ts:361`；并发与时序从代码推断，没有在浏览器复现。
- 建议改法：`run` 检查 `refresh()` 的结果；`busy` 放进 `book` 级共享状态或模块级 ref；失败码为冲突类时触发一次 refresh。
