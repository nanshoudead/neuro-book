3. markdown/web/host.ts 的 `NBOOK_IMAGE_MISSING`（1 条双语：`{name}（不在作品里，不显示）` / `{name} (not in the work, not shown)`）：它是交给 nb-markdown 包的 `MarkdownText`（包的类型只认 zh-CN/en-US 两键的对象，包内用 `say(text, locale)` 取），属于包的接口；包自己的目录迁移（计划里 nb-markdown 自带目录）那一片再处理，这里没法单独改成目录键。Lab 的 MarkdownImageFixture.vue 也在引用它。MarkdownControl 的 `locale` 属性同理，是传给包的。
4. markdown 里 syntax-catalog.ts、language-registry.ts、shared/dialects.ts、web/plugin.ts、MarkdownHosted.vue、MarkdownControl.vue 的中文：诊断消息、校验原因、`throw new Error` 的开发者消息，不是界面文字。
5. files 全部：backend 的 `detail`、`rejected(...)`、`fail(...)` 文案（entry-ops、rooted、operations、raw-route、manifest-edit、folder-kinds、batch、commit、manifests、files-service、plugin.ts），shared/resource.ts、shared/names.ts（“第N”规范化、路径校验原因），web/client.ts 里浏览器侧拼的 `detail`（“没有给出任何地址”“一次最多 N 项”“的正文超过上限”等）：都是服务端或合同层产出的失败详情字符串，随失败结果交给调用方（资源管理器等）当原文显示，服务端也不翻译 TextRef；没有界面组件。不属于本片。资源管理器怎么显示这些 `detail` 在 explorer 那一片已处理。

## 没把握的 / 给主会话的决定点
1. HtmlPreview 的 `locale` 属性删除后，控件合同 EditorControlProps 仍要求编辑器区传 `locale`；我在插件入口的 HtmlPreviewHost 包装组件里声明了 `locale` 属性接下它（不使用），否则它会进 attrs 落到根 div。这是一个小的不对称：合同属性是控件“可以不用”的。若主会话想让合同去掉 `locale`（只给分语言的控件如 Markdown、Monaco），那是编辑器合同的变化，另议。
2. ImageViewer 的 `locale` 属性保留（`Intl.NumberFormat` 的大小格式）。与试点决定点 3 同类：端口有 `locale`，改读 `useText().locale` 就能删掉这个属性。是否统一处理，请定。
3. 失败说明（`problem`）是失败那一刻翻成的字符串快照，切换语言后不更新（迁移前同样如此）。已在两份 .md 里写明。与试点决定点 6 同类。
4. commands 的 REASONS、markdown 的 NBOOK_IMAGE_MISSING 没迁，原因见“没有迁的”第 1、3 条；后者要等 nb-markdown 的目录化那一片。
5. HtmlPreview 的失败分支新增了 `DENIAL_KEYS` 表（原来直接拿 denial 当 TEXT 键）；行为不变。
6. Lab：HtmlPreview 的 `denied` 场景原来是英文，现在 `denied` 为中文、新增 `denied-english`（场景 id 约定）；截图基线若按场景 id 对照，需要更新。截图对照我没做。
