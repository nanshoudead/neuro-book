码的来源（查证）
- corrupt / unsupported-version：不是存储失败码，是记录状态；layout-store.ts 的 problems 把 base.status 直接当 code（kind: unread）。
- provider-stopped：订阅结束原因（storage/backend/owner.ts），经 PersistedFieldState 的 failure 传来。
- 同一条路径还有 released（facade）、disconnected / server-restarted / project-gone（nb-runtime remote）、provider-error（peer.ts）；另有 change-threw（persisted.ts 修改函数抛错，保存失败码）。这些我都补了中英文案。
- 订阅结束原因是开放字符串（node.ts 还会把重建订阅失败的 outcome.code 当 reason），所以 StatusBarProblem.code 保持 string，兜底保留。

断言判据
- 具体码：用户可见整句文本全等（too-large 中文、busy 英文、server-restarted 中文、unsupported-version 英文）。

- 兜底：brand-new-code 与 constructor 原样显示。
