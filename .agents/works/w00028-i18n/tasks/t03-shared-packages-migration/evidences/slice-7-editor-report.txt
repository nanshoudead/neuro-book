== 没迁移的（列给主会话）==
1. 单语中文的运行期文字（不是双语表，也没有取文字函数，原来就只有中文）：
   - web/area.ts：area.notice 文字（上次编辑的片段已不在原处、有未裁决的输入、写不回 Markdown 的两句，显示在编辑器区顶部提示条）、
     refusal() 与各动作返回的 CommandResult.reason（约 40 处，如“编辑器已关闭”“标签已关闭”）；
   - web/commands.ts：各命令的 unavailable/reason（约 25 处）；web/editors.ts 的 editorRefusal；web/plugin.ts 的 area.notify
     （继续写作只能打开项目里的文件）；web/documents/store.ts 的 LOST_FORMAT（格式丢了的提示）；MonacoControl.vue 的两条 reason。
   这些要让 area（纯 TS、被很多测试直接创建）和命令工厂收 TextResolver，范围和风险都大于“按键迁字面量”，且原文无英文版，
   需要开发者决定要不要做、英文怎么写。notice 是用户能看到的文字，建议优先。
2. 诊断与校验文字（diagnostics.record 的 message、shared/contracts.ts 的 validate 返回的拒绝原因、languages.ts 的 throw Error）：开发者向的诊断，不是界面文字。
3. shared/settings.ts 的 ui.unit {"zh-CN": "像素", "en-US": "px"}：设置窗口把 ui 提示原样交给 nb-form，FormText 装不下 TextRef，保持双语字面量
   （试点 settings 的 choices.ts 同样处理）；已在代码旁写了原因。
4. 旧表中的死条目未迁移：messages.close（关闭）、messages.preview（预览）从未被引用，没有迁。
5. src/ui、src/shared 里没有属于 editor 的文字，未动。

== 给主会话的决定点 / 没把握的 ==
1. 数字格式：旧代码用 Intl.NumberFormat(locale) 先格式化再填（1,234）。迁移后目录里写 {{count, number}}、{{line, number}}，宿主引擎（i18next）
   按语言格式化，locales.test.ts 验证 1,234,567 字 / 1,234,567 words。但 nb-ui 的 createMinimalTranslator（无宿主时的缺省端口）只认
   {{name}}，不认 {{name, number}}，会原样显示占位符；与 Spec i18n 输出 9“宿主引擎与最小翻译器对同一目录结果相同”有出入。生产窗口总有宿主引擎，
   只有没引擎的测试场地会碰到（那里本来就没有目录，只显示键名）。是否让 nb-ui 的最小翻译器也支持 number，或目录改用普通 {{count}}
   放弃千分位，需开发者决定（动 nb-ui 属共享代码，我没改）。
2. 控件合同的 locale：docs/specs/workbench/editor.md 第 89 行写控件属性为 {binding, host, readonly, visible, label, locale}，“locale 是界面语言，
   控件自己显示的说明按它取”。我保留了这个属性（别的插件的控件在用），Spec 没有过时，所以没有改 docs/specs。
3. 约定键强制命令、状态栏条目、编辑器各一份键；同一个旧字面量在多处出现时共用一键或各一键，键数为 153，和旧字面量表一一对应。
   tab 菜单的“关闭/复制路径”等与命令标题是两份键（同 explorer 的做法）。
4. banner.unrepresentable 与 banner.unrepresentableExcerpt 的 {excerpt} 是把后者翻译结果当参数传入（与旧实现一致）。
5. Lab 的 EditorArea 场景：去掉 locale 后组件在注册表里没有可登记的 JSON 输入，index.dom.test 的“每个场景登记 input”会报“input 不能是空对象”。
   我让夹具把多行标签 wrapTabs（EditorArea 本来就有的属性，缺省 true）从输入转给 EditorArea，场景输入写 {props: {wrapTabs: true}}，行为不变。
   另一种做法是给 EditorArea 声明 noInput，但类型上要求组件没有 JSON 数据属性，EditorArea 有 wrapTabs/breadcrumbs/workTitle，通不过。
6. tab-menu.test.ts 里“（禁用）”后缀是测试自己的 labels() 辅助写的，不是产品文字。title-actions.test.ts 里的命令标题（向右拆分等）是测试里自建命令的
   声明，不是产品文字，保持字面量。
7. 没发现旧文字的错字。
8. 区别于 explorer：这里 plugin.ts 只建一个端口（windowTextPort）分给命令、状态栏、标签菜单与标题动作，没有为组件另建。
