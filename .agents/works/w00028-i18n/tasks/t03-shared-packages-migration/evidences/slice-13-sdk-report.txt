== 两个入口的最终形态与理由 ==

`@notnotype/nb-plugin-sdk/text`（server: true，不连带 Vue，surface.test 闭包只有 shared/plugin-text.ts）
- 类型：Text、TextRef、LocaleMap、TextParams（nb-ui ./text）、CatalogKey
- 值：pluginText

`@notnotype/nb-plugin-sdk/text/browser`（server: false）
- 值：useText（nb-ui ./text-port）、usePluginText
- 类型：TextPort、BoundText

宿主那一份：两端宿主模块表各登记，浏览器表的 `/text/browser` 是 `nbook/sdk/text-browser` 本身，再导出宿主 nb-ui 的 useText；plugin-modules.dom.test.ts 按身份核对（`table["…/text/browser"].useText === useText`），并用真实引擎验证插件组件经表里的 usePluginText 取到窗口根注入的端口、切换语言跟着换。第三方产物经 require 取这两个子路径（验收测试与 pack.test 的 required 名单都核对），不打进自己。TEXT_PORT_KEY 本身是 Symbol.for，即使多一份 nb-ui 也是同一个键；模块表给宿主那一份是第一道保证。

为什么保留 pluginText 而不是“激活适配层绑定的 text()”：pluginText<typeof 源语言目录>(插件 id) 键写错编译不过，在声明（模块顶层，服务端也执行）里就能用，不需要激活上下文与额外的运行时适配；代价是作者要传一次 plugin.id。激活绑定的 text() 只在 activate 里可用，声明里的 description 用不上，也没有键类型。所以把 pluginText 从根入口移到 `/text`，根入口不再导出，不在两处各导出一份。提案第 209 行附近写的“加 text()”与现状不一致，提案不在本片改动范围，留给主会话决定是否改提案。

== 与计划不同之处 ==

1. 文字构造函数用 pluginText（理由见上），没有做激活绑定的 text()。
2. 验收测试放在 Vitest（happy-dom）里：Bun 没有 DOM，组件要真实渲染与切换语言。生成 SDK 包与构建用子进程跑 Bun（与 e2e/plugin-authoring.e2e.ts 同一写法）。沿用 testing/author.ts 的 authorDirectory、cliOf，testing/browser-artifact.ts 的 registeredFactory、runFactory（加了可选的模块表参数，传窗口真正用的 hostModules()，组件与注入键都是宿主那一份）。目录按产物清单的 l10n 与 dist/locales 登记进宿主引擎，没有走真实服务端的目录端点（那条路径由 window-catalogs.test.ts 负责）。
3. testing/author.ts 的 `new URL("../../../../node_modules/", import.meta.url)` 改为 `join(dirname(fileURLToPath(import.meta.url)), …)`：Vitest 在 happy-dom 环境里把 `new URL(字面量, import.meta.url)` 当静态资源改写成 http 地址，fileURLToPath 报 “The URL must be of scheme file”。行为不变，Bun 与 Playwright 用法不受影响。
4. 目录检查脚本（scripts/ci/message-catalogs.ts）原来要求 package.json 的 l10n 同时写 source 与 locales，而构建预设要求作者的 package.json 只写 source（写 locales 构建失败）。示例插件第一次带目录就撞上这条矛盾。改为：没写 locales 时按 locales/ 里的文件查（与构建预设同一规则），写了的仍按列出的查；形状不对的报一条（文案改为“l10n 要写 source；写了 locales 时要是语言标签的数组”）。模板的清单是 `_package.json`，把 template/locales 登记进 CATALOG_DIRECTORIES。补了一条测试，Spec i18n.md 的“目录检查”同步。
5. 示例的约定键原来没有任何检查覆盖（声明测试只查内置插件），在 convention-keys.test.ts 的声明测试里加了一例覆盖 counter、focus、snippets；做过变异核对（把 focus 目录的 views、groups 改名，报出两条 missing-key，已还原）。
6. snippets 页面的失败提示原来存拼好的字符串，改为存失败本身（码与详情），模板里按当前语言拼：切换语言后还在的提示也跟着换。SnippetsPage.dom.test.ts 第一例补了切换语言后的断言（状态行、添加按钮、下移按钮的读屏名称）。
7. 模板的显示名从 _package.json 移进源语言目录的 manifest.displayName（构建预设规定有目录时只能写在那里）；template.test 断言的清单显示名 “Hello World” 与说明 null 不变。模板 tsconfig 加 resolveJsonModule（`typeof import("../locales/zh-CN.json")` 需要）。
8. 示例场地的工作台替身（plugin-sdk/examples/testing/workbench.ts）改为直接用产品的 viewsPoint、statusbarItemsPoint。这是本片自己引入的回归，不是负载问题：focus 的视图、状态栏条目去掉 title 之后，07-focus 场景两例稳定失败。原因是替身原来自己拼贡献点，只带 validate，没有真实工作台的 complete（补约定键）和 idPrefix，于是把不写 title 的声明拒了。改后替身补约定键、做校验都和真实工作台一样，没有放宽任何断言。替身的文件头注释与 examples/README.md 第 156 行同步。另外确认了脚手架 create-plugin 的 fill 作用于模板里每个文件，locales/en-US.json 里的 __DISPLAY_NAME__ 同样被替换。
