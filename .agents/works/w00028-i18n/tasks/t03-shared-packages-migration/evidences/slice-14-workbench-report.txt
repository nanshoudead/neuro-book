== reason / label 类型变化与理由 ==
1. CommandResult.reason 与 CommandFailure.reason 从 string 改为 Text
   - 理由：命令在执行时不一定知道显示语言（例如 appCommands 原来要注入 TextResolver，现在已去掉）。返回文字引用后，菜单、按钮提示、通知在显示时翻译，切换语言后已显示的通知随之更新（通知服务输出 9 已支持文字值）。
   - 显示方：
     - 按语言翻译的有 arrangeMenu、titlebar-source、WorkbenchShell frameActions、editor tab-menu/title-actions、explorer、projects。
     - failureNotice 把原因原样作为通知正文交出，由视口翻译。
     - 诊断用 diagnosticText。
   - registry 规范化命令返回的值：是文字值就原样交出，其他值用 String() 转换。之前是一律 String()，语言映射与文字引用会变成 [object Object]。
2. 登记结果 RegistrationResult：reason 保持 string
   - 理由：登记被拒的原因是命令表自己写的诊断，调用方会把它直接塞进 Error 或日志。分开定义类型，可以避免改动其他插件的测试。
3. 远程合同 nbook.commands/remote 不升版本
   - 理由：原因主要给 Agent 读，服务端没有窗口的目录，翻不了文字引用。所以在窗口一侧 remoteCommands 的出口按窗口此刻的显示语言翻成字符串，线上仍是 Type.String()。
   - 没有翻译端口时写成键名，与 i18n 输出 4 里缺键时的显示一致。
4. QuickPickResult 的 unavailable reason 改为 DisplayText，因为命令面板缺席时给的是同一个文字引用 palette.unavailable。
5. MenuItemDeclaration.label：之前的片已经是 DisplayText 加 TextSchema，menus.md 写的也是 label?: Text，本片只把 menu-items.ts 的 4 项改走目录。
6. commands 插件的 when 原因 REASONS（undeclared、notBoolean、notTrue）没有迁
   - 它们已经是中英两份的语言映射，按显示语言解析，英文界面不会出现中文。
   - 内容是写给作者与开发者的，会点出内部键名，例如“上下文键 x 没有登记”。
   - 服务端也会对它们求值，而服务端没有翻译端口；commands 插件本身也没有目录。
   - 所以保持现状。
