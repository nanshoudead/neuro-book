# i18n 需求与结构设计

## 目标与范围

确定 i18n 作为前端底座的结构，并写成分阶段计划。开发者 2026-10-17 明确本 Task 现在不开工，只保留目标与已知输入。

要回答的结构问题：

1. 消息目录形态：延续内联 `LocalizedText`，还是集中目录（按插件分区的扁平键）；插件的文案如何随插件包分发，内置与第三方插件是否同一形态。
2. 语言集合与回退：继续只有 `zh-CN`／`en-US`，还是开放任意 BCP 47 语言并规定回退链；`nbook.settings/locale` 的选项如何生成。
3. 格式化：复数、数字／日期／相对时间用 `Intl`，参数插值的类型与转义规则（现有 `formatText` 只有 `{name}` 替换）。
4. 消费方式：注入的 i18n 上下文（与主题一样从文档根／宿主注入）替代逐层传 `locale` prop；Vue 组件与纯 TS 模块各自的取值入口。
5. 插件贡献：命令标题、菜单项、设置项标题等声明式文本已有内联两份；插件是否还能提供自己的消息目录，贡献点在哪个插件。
6. nb-ui：组件默认文案（`aria-label`、placeholder）由谁提供，宿主缺失译文时如何回退；第三方插件复用 nb-ui 时文案语言从哪来。
7. 交付前检查：缺失文案、未使用文案、两种语言键不一致、硬编码中文的静态检查，以及 `docs:check`／测试中的落点。

非目标（除非开发者另定）：界面文案的翻译流程与外包；除界面外的内容（作品正文、Agent 输出）的本地化；服务端诊断文本的翻译。
