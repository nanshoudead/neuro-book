## 关键设计（提案的方案部分）

### 1. 目录与清单

- 插件目录下 `locales/<语言>.json`，每个插件一个命名空间（插件 id）。清单加 `l10n: {source, locales}`：源语言与已有的语言列表；文件路径按约定，不另写。
- 登记时：文件存在、能解析成对象、源语言目录在。目录坏了**不阻止插件登记**（文字不是功能），该插件的文字退到键名并记诊断；内置插件由检查保证齐全。
- 清单的 `displayName`、`description` 照旧写源语言字符串；其它语言在目录里写 `manifest.displayName`、`manifest.description`，插件页读目录，不执行插件代码。
- 语言包插件（给别的插件贡献译文）现在不做，格式不堵它：以后加一个贡献点即可。
- ADR 0033 的构建产物：插件目录整体复制，`locales/` 随之进包。

### 2. 键与声明

- 声明里需要显示的文字，类型是 `string | {key: string; params?: Params}`：字符串是不翻译的字面文字（路径、项目名、第三方只写一种语言时）；对象是本插件命名空间里的键，宿主补上命名空间，插件不能引用别的命名空间的键。
- 跨插件传递的运行期文字（状态栏条目、公开状态的原因、快速选择项）同样用 `{key, params}`，由宿主按贡献者补命名空间，接收方不需要知道是谁的。
- 键用 `.` 分层；命名空间分隔符 `:`；键与错误码都不许含 `:`。
- 要改的 Spec：`workbench/menus.md`、`workbench/views.md`、`settings/settings-window.md`、`workbench/editor.md`、`workbench/commands.md` 的标题字段（命令 `description` 不变）。

### 3. 跨运行实例与语言切换

- 只有浏览器实例渲染文字。服务端只按清单把各插件的目录文件经 HTTP 发给浏览器，不自己翻译。
- 浏览器在插件登记时一次取齐该插件**所有语言**的目录（全部内置文字压缩后约 34 KB 以内），在显示任何文字之前完成。这样切换语言是同步的，没有乱序响应和闪出键名；设置搜索照旧比对多种语言。
- 插件热卸载时注销它的命名空间。
- 失败页：引导完成前就可能出现，用宿主自带的一小份目录，语言取浏览器本地记下的上次界面语言（照 `web/host/appearance-hint.ts` 的做法），读不到用 zh-CN（w00031 第 8 条）。

### 4. 消费方式与语言集合

- 宿主给每个浏览器实例建一个 i18next 实例，经 Vue 的 provide/inject 交出 `useText()`（含当前语言的 `shallowRef` 与 `t`）；纯 TS 模块由调用方传入 `t`，不引全局。逐层传 `locale` 属性的写法逐步退役。
- 界面语言集合是宿主内置目录有的语言（现在 zh-CN、en-US）；`nbook.settings/locale` 的选项由它生成。第三方插件不能新增界面语言（等语言包）。
- 回退链：当前语言 → 插件的源语言 → en-US → 键名。内置插件 zh-CN、en-US 都要齐；第三方只要求源语言。

### 5. 共享包

- nb-ui 提供注入键与 `useText()` 的接口（四个共享包都已依赖 nb-ui），以及一份几十行、只支持原生格式子集的最小实现；宿主没提供时，组件用包自带的目录与最小实现。
- 每个共享包自带 `locales/`，命名空间是包名。核心层（纯 TS）只产出 `{key, params}` 或 `{code, params}`，由 Vue 层翻译。
- 已发布的 `locale` 属性保留：没有注入 `t` 时它决定用哪份默认目录。nb-story 查看器不注入，照旧单语中文（w00031 第 9 条）。
- nb-ui 写死的中文默认文案（`Editable`、`Switch`、`Toolbar` 等）进 nb-ui 自己的目录。
- nb-form 的 `FormText` 是开放语言集合的公开类型：保留它作为“字面文字”的一种，新增 `{key, params}` 形式。

### 6. 失败文字的共用件

- **失败值**：`{code: string; params?: Record<string, string | number>}`，在 nb-runtime 给出 TypeBox schema 与参数整理函数（键只许字母数字，至多 8 个，字符串截到 200 字，丢掉其它类型）。各错误域在自己合同里嵌入它，不新增全局错误对象。
- **消息键**：`<拥有者命名空间>:errors.<code>`；码是 kebab-case。
- **码表穷举**：每个错误域导出码的常量数组；目录检查脚本核对拥有者源语言目录的 `errors` 覆盖全部码，类型上用 `satisfies Record<Code, string>` 约束导入的 JSON（以 t02 原型结论为准）。
- **未知码的兜底**：宿主目录里一条中性文案，只陈述“收到一个不认识的结果码”并附码，不说“失败”“未保存”。
- **四类读者**：开发诊断（英文，进详情）；给用户看的失败说明（按码本地化）；**用户或插件作者要照着改的校验原因**（设置文件解析错误、插件声明问题）也按码本地化，参数带位置与路径，是主文案而不是详情；给模型的文字按 ADR 0034 决策 4。
- **“详情”载体**：nb-ui 新增一个可展开、可复制的详情组件；`Notification` 加可选 `detail`，带详情的通知不自动消失；状态栏、编辑器横幅、资源管理器结果区等单行位置用同一个组件的折叠形态。

### 7. 检查

- 编译期：键与参数名（`keyof typeof`）。
- 目录检查脚本（进 `governance:check`）：缺键、多余键、两种语言占位符集合一致、复数形式齐、错误码表穷举、键不含 `:`。
- lint：Vue 模板与 TS 里新增的界面字面文字（先告警）。
- 测试环境缺键直接抛错；Lab 的伪语言放到 t03 以后。
