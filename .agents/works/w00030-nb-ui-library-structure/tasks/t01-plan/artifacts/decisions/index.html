1. 原子类怎么和宿主隔开 待定

现在 nb-ui 的产物带着约 450 条无层的原子类（.flex、.text-sm……），宿主的 UnoCSS 也产出同名类：IconButton 等组件的字号在 neuro-book 里是 14px、在 nb-story 里是 13px；neuro-book 为位移类写了封禁名单，nb-story、dev-panel 为此放弃了 Tailwind 的标准分层，坑 58 的图标尺寸也是这个机制。

原子类加 nb: 前缀（推荐）

组件里写 nb:flex，产物只有 .nb\:flex 这类类名，宿主的引擎不认，不会撞名；Tailwind 的主题变量也随之变成 --nb-*，不再和 nb-ui 自己的 --text-sm 等 token 同名。本机试编译过，行得通。用脚本一次改完全部模板，再比较改前改后的产物逐条规则，差异逐条列出（text-sm 这类原来靠 token 碰巧取到 13px 的要改成显式写 token）。

整个产物包进 @layer nb-ui

改动只有一行，但解决不了撞名：同名类时宿主无层的 .text-sm 总是赢过有层的规则，字号照样随宿主变；坑 58 的图标尺寸问题会回来（宿主的 width: 1em 无层，赢过 nb-ui 的尺寸）。

3. t04 改名后旧名留不留 待定

例如 ContextMenu 的 visible 改 open、AlertDialog 的 confirmText 改 confirmLabel、菜单项 shortcut 改 hint。现在各宿主的类型检查没开“未知属性”检查，改了名的属性会静默落成普通属性，查不出来；计划先单独一个提交把这项检查打开。

不留别名，调用方同一个提交改完（推荐）

调用方都在这个仓库里；打开未知属性检查后漏改的会报错。别名只会变成第二套写法。

保留一个版本的旧名别名

旧名照常工作并在开发模式下警告，下一轮再删；每个组件多一套映射代码。

4. Dialog 的浮动窗口用法要不要拆出来 待定

Dialog 一个组件承担模态对话框与可拖动、可缩放的浮动窗口两种用法（modal=false，设置窗口在用），约 30 个属性里一半只对其中一种生效；它还按“宿主有没有挂 request-close 监听”改变关闭行为，加一个日志监听就关不掉了。

拆出 FloatingWindow，Dialog 只做模态（推荐）

两者共用内部外框；窗口独有的缩放、最小尺寸属性只在 FloatingWindow 上。关闭行为改成显式属性，不再看监听器。

保留一个组件，只修关闭行为

改动小；属性表仍是两种用法混在一起。
