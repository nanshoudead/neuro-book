## 1. 级联键盘的“预约焦点”不会在子菜单已展开时消费，也不会被 reset / truncate 清掉，之后任意一次点开子菜单会把焦点抢进去

- **严重程度**：重要；**类别**：正确性 / 不变量
- **位置**：`packages/nb-ui/src/composables/useMenuCascade.ts:114-126`（`focusNewLevel` 与 watch）、`:143-147`（`expectOpen`）、`:199-202`（`reset`）、`:107-112`（`truncate`）
- **现象**：`expectOpen` 在父项上按右方向键、Enter、空格时把 `focusNewLevel` 置 true，只有 `watch(() => levels.value.length)` 在层数变多时才消费它。父项的子菜单已经展开（鼠标悬停 300ms 后展开、或点击展开）时再按这几个键，`open()` 用同样层数的新数组替换第 depth 级，层数不变，watch 不触发：焦点既没进子菜单，预约还留着。`reset()`、`truncate()` 也不清它。之后任何一次层数变多（例如用鼠标点孙级父项）就被这条过期的预约把焦点移进新开的那一级。
- **为什么是问题**：(1) 本来的右方向键对已展开父项无反应属原有缺陷；本次把右键菜单的 Enter、空格也并进同一个预约（计划第 2 节“有意统一”），把这个洞扩到了右键菜单。(2) 过期预约让“点击展开”这种本不该移动焦点的路径偷偷移动焦点，难以复现。(3) 计划与 README 没把“预约在什么时候作废”写成合同，只有卸载时清。
- **如何核实**：已在 happy-dom 里复现，脚本 `/tmp/t03/review-impl/scratch/stale.test.ts` 与对照 `control.test.ts`（两者只差中间多按一次 ArrowRight）。步骤：打开右键菜单，ArrowRight 展开“更多”，ArrowLeft 收起，对“更多”`click()` 展开；焦点仍在“更多”上时再按 ArrowRight，焦点仍是“更多”（没进子菜单）；然后 `click()` 子菜单里的“孙父”。有这次 ArrowRight 时焦点跳到“孙一”，没有（对照）时焦点留在“更多”。
- **建议改法**：把预约绑在一次具体的展开上，而不是全局布尔。例如 `expectOpen` 记下 `depth`（目标层 = 当前层 + 1），`open()` 完成该层的测量后（不管层数是否变多）直接判断“这一层是不是预约的那一层”并聚焦，然后清预约；`reset`、`truncate`、ArrowLeft 都清预约。这样已展开时按右方向键也会把焦点送进子菜单（与 reka 菜单原语的键盘一致）。补一例：子菜单已展开时按右方向键，焦点进第一项；预约不影响之后的点击展开。

## 4. `measureCascadePanel` 的缩放比例取自 `offsetHeight`（整数），面板高度不是整数时无 zoom 也会让位置偏几个像素，与“没有 zoom 时结果与改前逐项相同”不符

- **严重程度**：建议；**类别**：正确性
- **位置**：`packages/nb-ui/src/utils/popup-geometry.ts:16-21`（`rectScale`）、`:142-173`（对 `left`、`right`、`top`、窗口宽高都除以 `scale`）
- **现象**：`rectScale` 用 `getBoundingClientRect().height / offsetHeight`，而 `offsetHeight` 是四舍五入的整数。本次把它从“只在视口内部做相对换算”扩成“对绝对坐标（`anchor.left`、`parentRect.right`、`window.innerWidth`）整体除以比例”，比例的误差被坐标放大。我在真实 Chrome 里用独立页面量过：定位元素 `height: 90.4px`，`offsetHeight` 为 90，矩形高 90.390625，比例 1.00434，`left: 800px` 的元素被换算成 796.54（偏 3.5px）。
- **为什么是问题**：面板高度不是整数的时机真实存在：`.nb-menu-level` 对 `top/left/width/height` 做过渡，同级父项之间快速切换（`switching`）时面板仍在上一次高度过渡中，量到的是中间的小数高度；`wrap` 的换行项、非整数字号缩放也会给出小数。无 zoom 时 `scale` 不再恒为 1，横向间隙（6px）可被吃掉一半。注释写“这个比例只来自 zoom”，对小数高度不成立。静态整数高度（常见路径）不受影响，e2e 与 happy-dom（`offsetHeight` 为 0 时回退 1）都测不到。
- **如何核实**：脚本 `/tmp/t03/review-impl/scratch/frac.mjs`（用 playwright-core 加系统 Chrome 开独立页面，不起开发服务）。真实菜单里的复现由主会话在 `popup-scroll` 的 fixture 上做：同级父项快速来回悬停（间隔小于 `--motion-fast`），读 `.nb-menu-level` 与父级的水平间隙。
- **建议改法**：比例别用取整的 `offsetHeight`。zoom 引起的比例可以用 `parseFloat(getComputedStyle(panel).height)`（CSS 像素，不取整）对 `getBoundingClientRect().height`；或在 `rectScale` 里对接近 1 的比例（例如 `|scale - 1| < 0.02`）直接返回 1，因为真实的 zoom（0.8、1.25 等）不会落在这一区间。无论哪种，在 `popup-geometry` 加一例单测：高度为小数的面板不改变位置。

## 5. 新增的 Menubar 级联键盘测试只有一组菜单，没有覆盖 reka 的“右方向键切换到下一组”，真实多组菜单栏里右方向键展开子菜单会被同时切到下一组

- **现象**：reka 的 `MenubarContent` 在根上挂 `@keydown.arrow-right.arrow-left`，对不是 `data-reka-menubar-subtrigger` 的目标（nb-ui 的级联父项是普通 `MenubarItem`）会调用 `rootContext.onMenuOpen(下一组)`，不看 `defaultPrevented`。我在 happy-dom 里加一组“编辑”重放 Menubar 测试的步骤：对“导出”按 ArrowRight，子菜单展开且焦点进 `Markdown`，同时 `update:modelValue` 发出 `"edit"`（脚本 `/tmp/t03/review-impl/scratch/menubar2.test.ts`，输出 `updates ["edit"] focused Markdown levels 1`）。宿主绑了 v-model 时顶层菜单就切到“编辑”，而“导出”的级联面板还开着。

> 第 5 条更正（建议改法）：上面写的“在 `rootKeydown` 里 `stopPropagation`”不对。`rootKeydown` 挂在 capture 阶段的菜单内容上，在那里阻止传播会让事件到不了项本身，`MenuNodes.onKeydown` 也收不到。正确位置是 `MenuNodes.vue:52-58` 的 `onKeydown`（项上的监听，目标阶段）：处理完右方向键后补 `event.stopPropagation()`，让事件不冒泡到 reka 的 `MenubarContent` 根监听。该监听在项的祖先上，所以能被拦住。

## 6. 右键菜单父项上的 Enter、空格展开，与鼠标/键盘 click 的先后依赖“浏览器先 keydown 后 click”，且 Space 的 click 在 keyup 才来，预约期间焦点可被别的键改变

- **严重程度**：建议；**类别**：正确性
- **位置**：`packages/nb-ui/src/composables/useMenuCascade.ts:143-147`（`expectOpen`）、`packages/nb-ui/src/components/popup/MenuNodes.vue:79-82`（`onButtonClick`）
- **现象**：右键菜单的父项是原生按钮，Enter 在 keydown 阶段触发 click，空格在 keyup 才触发。预约（`focusNewLevel = true`）在 keydown 设置，真正展开在 click，二者之间的窗口对 Enter 是同一个事件，对空格是按住到松开。按住空格期间如果按了别的键、或指针移到别项触发 hover 展开（`hasOpenSibling`），层数在 click 之前就变多，预约被那次展开消费，焦点被抢进别的子菜单。第 1 条是同类，这里单列是因为空格路径是计划“有意统一”新增的。
- **为什么是问题**：窗口很短，影响小；但合同写成“预约焦点”而不是“这一次展开完成后聚焦”，是第 1 条的同一根因，修第 1 条时一并处理即可。
- **如何核实**：真实 Chrome，右键菜单，焦点在父项上按住空格不松，同时把鼠标移到同级另一个父项上（300ms 后展开），松开空格，看焦点落在哪一级。
- **建议改法**：并入第 1 条的改法（预约绑定到具体父项元素：click 时检查 `trigger === 预约的元素`才聚焦）。

> 第 6 条注：未在浏览器验证，从代码推断；与第 1 条同根，修第 1 条时顺带覆盖，单独不值得改。

## 未发现问题的方面（逐项仔细检查后）

- `useMenuCascade` 的 `rootLevel` 三个入口：DropdownMenu 取 `scroll.viewport`、Menubar 取打开着的那组的 `[data-menubar-level]` 视口、右键菜单取根里第一个 `.nb-menu-level-content`；三处条目都是该容器的直接子元素（`MenuNodes` 是 Fragment，分隔线与项直接落在容器里）。`:scope >` 在嵌套菜单里与原来的后代选择器等价，原因是每一级的面板都是 DOM 上的兄弟而不是嵌套，不存在更深层的 `[aria-expanded='true']` 可被后代选择器误命中。
- 右键菜单 `rootKeydown` 挂在外观层 `div[role=menu]`、`levelKeydown` 挂各级面板，二者是兄弟，事件不会处理两次；Tab、Escape 仍由 document 监听处理，`useMenuCascade` 不调 `stopPropagation`，`ContextMenu.test.ts` 新增“焦点在子菜单项上时 Tab、Escape”一例有效。
- `rootKeydown` 的 `.capture` 与 reka 的先后：预约只置位标志，不依赖 reka 先后；Enter、空格在 reka 的 `handleSelect` 里经 `click()` 触发，之后才展开，预约总在展开之前。除第 1 条所列的“已展开时不消费”外没有顺序问题。
- 卸载：`onBeforeUnmount` 取消悬停定时器并清预约；`open()` 在 `await nextTick()` 之后读 `openedPanels[depth]`，此时面板 ref 已置空，`measureCascadePanel` 不会被调用，没有别的待执行回调。
- `MenuNodes` 的 `rekaItems`：`v-for` 用下标当 key，同一下标始终对应同一位置的元素，增删项、分隔线切换时 ref 回调以 `null` 清理，不会对错；reka 的 `select` 事件确是只交给监听者、元素上没有派发（`node_modules/reka-ui/src/Menu/MenuItem.vue` 的 `handleSelect` 里 `emits('select', ...)`），所以必须自己取元素。
