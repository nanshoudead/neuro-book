- **现象**：计划里的“改动面”用工具 1 编译的是 neuro-book `src` 下的非测试源码。但迁移前 neuro-book 的 UnoCSS 经 Vite 模块图也会扫到 nb-ui 的 `.vue`（`uno.config.ts` 里的封禁名单注释就是证据），而且 `boot.ts` 里 `virtual:uno.css` 排在 nb-ui 产物之后，同名类 UnoCSS 那份赢。所以 nb-ui 组件在 neuro-book 里的实际外观是 UnoCSS(wind3) 的值。现在只剩 Tailwind v4 的值。我用同一份配置（`presetWind3 + presetIcons`）逐类生成 nb-ui 源码的 490 个类，与新产物对比，真正不同的有：

## 4. 滚动条 token 在 `:root` 上算出后继承下去，套了另一套配色的子树里的原生滚动条取到页面根的颜色（dev-panel 终端块是现成的复现点）

- **严重程度**：重要；**类别**：正确性
- **位置**：`packages/nb-ui/src/tokens.css` 的 `--scrollbar-thumb*`（`:root` 内，由 `var(--text-main)` 派生）；`packages/nb-ui/src/styles.css:33-41`；`packages/dev-panel/src/web/host/terminal-theme.ts:13`（`applyColorway(container, "nbook-dark")`）与 `packages/dev-panel/src/web/parts/TerminalView.vue:262`（`frameBox`：`overflow-auto bg-[var(--bg-main)]`，就是被套了暗色配色的滚动容器）
- **现象**：自定义属性里的 `var()` 在声明它的元素上就代入了，子孙拿到的是代入后的值。`--scrollbar-thumb` 声明在 `:root`，代入的是页面根的 `--text-main`。终端块被有意固定为暗色（页面是亮色时也是）：它的 `--text-main` 是浅色，但它里面的 `scrollbar-color: var(--scrollbar-thumb)` 取到的仍是页面根亮色的深色墨 32%。深色底上放深色滑块，几乎看不见。迁移前 dev-panel 写的是 `* { scrollbar-color: color-mix(… var(--text-muted) 55% …) }`，`var()` 在每个元素上各自代入，终端块跟着自己的配色。
- **为什么是问题**：README 与任务说明里“在 `:root` 上计算”被列为已有取舍，但这里能指出具体出错的地方：套子树配色是 `applyColorway(target)` 的公开用法（它还专门给 target 加 `.nb-ui-colorway` 宿主 class），终端块就是这么用的；这一条是相对迁移前的回退，而不是以前就有的限制。
- **如何核实**：我用 Chrome（`channel: "chrome"`）读了一个最小页面的计算样式，`/tmp/t02/review/scratch/sb.html` + `sb.mjs`：根 `--text-main:#111`，子容器内联 `--text-main:#eee`，规则同 `styles.css:33-36`。结果子容器的 `scrollbar-color` 与根完全一样，`color(srgb 0.0667 0.0667 0.0667 / 0.32)`（深色），而不是 `#eee` 的 32%。需要在真实页面上由主会话复核：亮色页面打开 dev-panel 的终端页，看终端块右侧滚动条。
- **建议改法**：把 `--scrollbar-thumb`、`-hover`、`-active` 也声明到 `.nb-ui-colorway`（`applyColorway` 加的 class，`styles.css` 里已有同名规则）上，让套了配色的子树自己重新代入；`:root` 里保留一份给没有宿主 class 的页面（缺省）。也可以不用派生值，改成 `scrollbar-color: color-mix(in srgb, var(--text-main) 32%, transparent) transparent` 直接写在 `:where()` 规则里（`var()` 在元素上代入），自绘滑块的三个组件同理写在各自的样式里；但这样“改一处统一调整”的目标要靠一个 `--scrollbar-alpha` 之类的数值 token 实现，取舍请开发者定。

## 6. README 与入口头注释给的“只要 theme 和 utilities”写法，照抄会得到不分层的原子类，或层序变成 `theme, utilities, base, components`

- **严重程度**：重要（只影响照文档接入的新宿主，但失败是无声的，正好是本 Task 想消灭的那类）；**类别**：文档
- **位置**：`packages/nb-ui/README.md` 的 “No preflight” 一条（`If you want only Tailwind's theme and utilities, import tailwindcss/theme.css and tailwindcss/utilities.css separately instead of tailwindcss`）；`packages/nb-ui/src/tailwind.css` 头注释第 5 行（“只要 theme 与 utilities 时拆开写 tailwindcss/theme.css 与 utilities.css”）；对照写对了的 `packages/neuro-book/src/web/tailwind.css:14-19`
- **现象**：neuro-book 之所以对，是因为它做了两件文档没提的事：开头先写一行 `@layer theme, base, components, utilities;`，并且两个 import 都带 `layer(theme)`、`layer(utilities)`。我用 `@tailwindcss/node` 的 `compile()` 编译了两种“照文档写”的变体（脚本 `/tmp/t02/review/scratch/tw-compile.mjs`）：
  1. 只写 `@import "tailwindcss/theme.css"; @import "tailwindcss/utilities.css"; @import "@notnotype/nb-ui/tailwind.css";`：输出里 `.flex` 在顶层（层深度 0），原子类是不分层的，又回到“谁赢看特异性与先后”，与 nb-ui 语义类在 `components` 层这件事互相打架；
  2. 加上 `layer(theme)`、`layer(utilities)` 但不先写层序语句：层名按首次出现排，nb-ui 入口里的 `@layer theme, base, components, utilities;` 来得太晚，实际层序是 `theme, utilities, base, components`，utilities 比 components 和 base 都低，调用方传的原子类反过来输给语义类。
- **为什么是问题**：整个 Task 的正确性靠层序，而这一条是对新宿主的唯一说明，两种照抄都不报错、样式表面正常，只是调用方传的类在个别属性上失效。
- **如何核实**：`bun run /tmp/t02/review/scratch/tw-compile.mjs`（输出两行 “层名序列” 与 “flex depth”：第一种 0，第二种 1 但层序不对）。
- **建议改法**：README 与入口头注释把完整可抄的三行写出来：
  ```css
  @layer theme, base, components, utilities;
  @import "tailwindcss/theme.css" layer(theme);
  @import "tailwindcss/utilities.css" layer(utilities);
  @import "@notnotype/nb-ui/tailwind.css";
  ```
  或者把 `@layer theme, base, components, utilities;` 的重要性单独成一条；neuro-book 的 `tailwind.css` 头注释里“@layer 先写”的原因也只写了 boot.ts 里，没写在 CSS 里。
