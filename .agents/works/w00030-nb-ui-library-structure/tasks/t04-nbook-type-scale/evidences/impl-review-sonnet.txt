## F1 [重要] 换算：Button / ToggleGroup 的 md、lg 在 nbook 与 macOS 下字号相同
- 位置：packages/nb-ui/src/components/controls/Button.vue:35-41；ToggleGroup.vue:48-50；Button.md、ToggleGroup.md
- 现象：Button sm/md/lg 原为 12/13/14px，现取 xs/sm/md。nbook 刻度 12/14/14（sm 与 md 同为 14px），macOS 刻度 11/13/13。lg 钮与 md 钮字号相同，只差高度与内边距。ToggleGroup 同样（12/13/14 变成 12/14/14 与 11/13/13）。
- 问题：换算规则“14→md”在 nbook 与 macOS 里 md 与 sm 同值，所以“字号随尺寸递增”的层次在这两个主题（其中 macOS 是被明确要求不变的）下丢了一档；同时 nbook 里 sm 档不涨（12→12）而 md 涨（13→14），一个组件内部涨幅不一致。macOS 下 Button sm 由 12 变 11，lg 由 14 变 13，ToggleGroup 同。
- 核实：对照 themes/nbook/vars.css:59-64、themes/macos/vars.css:30-35 与 Button.vue 的三档。
- 建议：接受并在 Button.md 写明“md 与 lg 字号相同”，或 lg 改取 `--text-lg`（nbook 16px，Button lg 高 42px 放得下）；至少在计划的“其它主题影响”里记一笔。

## F2 [重要] 活动栏：IconButton lg 随主题变高后，刚性的 48px 卡片宽与 38px 占位没跟着改，焦点光环被裁
- 位置：packages/neuro-book/src/plugins/workbench/web/shell/sizes.ts:50-51（`SHELL_ACTIVITYBAR_WIDTH = 48`，注释“38px 按钮加两侧余量”）；WorkbenchActivityBar.vue:87、102、109（`IconButton size="lg"`）、:154 与 :199-205（占位格写死 38px）；WorkbenchActivityBar.md:12、16、17；layout.ts:87
- 现象：S1 把 IconButton lg 的边长从字面 38px 改成 `--control-h-lg`。nbook 现在是 42px，macOS 是 40px。活动栏叶宽仍是刚性 48px：nbook 下按钮左右各只剩 3px（原 5px），而 nbook 的 `--focus-ring` 实色部分是 3.5px（vars.css:331-334），3px 余量切不下整圈，卡片外壳的裁切会把外扩光环切掉一截。没有命令的占位格仍是 `width/height: 38px`，与 42px 的按钮不再同占一格，列里的纵向节奏被打乱（一格 42、一格 38）。
- 为什么是问题：规范（ui-development-spec 检查表“外扩阴影防裁切”）明确要求“余量按主题 `--focus-ring` 的实色部分算（nbook、macos 是 3.5px）”，并用 `lab:shot` 机检；活动栏这几处的注释与 md 都建立在“38px 按钮 + 4px 余量”之上。计划的风险段只点名“活动栏可能放不下”，但没有核对这条与按钮高度的耦合；作者决定让 Button/IconButton 取 `--control-h-*`，这是它的直接后果。
- 核实：看 sizes.ts:51 与 WorkbenchActivityBar.vue:204-205；nbook 42px 的算式是 (48 - 42) / 2 = 3 < 3.5。workbench-views.e2e.ts:633 断言 nbook 活动栏宽 48，说明宽度被测试钉死。未起浏览器验证被裁（只读约束），按代码推断。
- 建议：二选一。(a) 活动栏按钮不吃主题高度：活动栏里给 IconButton 一个固定尺寸（例如 class 覆盖成 38px，或新增“定值档”），其余保持 38px；(b) 同步把 `SHELL_ACTIVITYBAR_WIDTH` 提到 `lg + 10`（52），占位格改成 `var(--control-h-lg)`，并改 layout.test/e2e/md。(a) 影响面小。IconButton.md 已把 xs/2xs 说成“给固定高度的标题行用，是定值”，lg 在固定宽度栏里同理。

## F3 [重要] e2e 断言“组件取 nb-ui 自己的字号”在新刻度下变成空断言
- 位置：packages/neuro-book/e2e/lab-nb-ui.e2e.ts:345-349
- 现象：原断言是 `fontSize === "13px"`，用来区分 nb-ui 的 `--text-sm`（13px）与宿主 Tailwind 默认的 `text-sm`（14px）：测试标题与注释（346 行“宿主的 text-sm（14px）改掉组件的字号”）说的就是 ADR 0028 的“两套原子 CSS 引擎并存时宿主的 text-sm 压过组件字号”。现在改成 `fontSize === getPropertyValue("--text-sm")`，nbook 的 `--text-sm` 恰好是 14px，与 Tailwind 默认 `text-sm`（0.875rem = 14px）同值：宿主引擎压过组件时计算值仍是 14px，断言照样通过。
- 为什么是问题：它保护的回归（宿主默认刻度盖掉 nb-ui 刻度）在 nbook 的 sm 档下不再可观察，测试从“能失败”变成“永远通过”，且注释里的“14px”也成了误导。
- 核实：对照 themes/nbook/vars.css:61（`--text-sm: 14px`）与 Tailwind 默认 `text-sm` = 0.875rem = 14px；`--text-xs` 同理（12px，与 Tailwind `text-xs` 同值）。
- 建议：换一个与 Tailwind 默认值不同的档来断：`--text-lg`（nbook 16px，Tailwind 默认 `text-lg` 是 18px）或 `--text-2xs`（Tailwind 没有这个名字），选一个 nb-ui 组件实际用到的场景；或切到 macOS 主题（`--text-sm` 13px 对 14px）。同时改掉 346 行注释。

## F9 [建议] token 扫描规则 8 的匹配式：几类写法漏报，一类可能误报
- 位置：packages/nb-ui/src/components/token-consumption.test.ts:91-92（`LITERAL_FONT_SIZE`）、:44-46（`LITERAL_FONT_SIZE_ALLOWLIST`）、:62-72（只收集 `.vue`）、:150-155
- 实测（scratch/re.ts，同一条正则）：
  - 命中：`text-[13px]`、`text-[length:13px]`、`text-[13px]!`、`sm:text-[11px]`、`text-[13px]/5`、`fontSize: 13`、`fontSize: '13px'`、`[font-size:13px]`、`style="font-size:13px"`。
  - 漏报：`font: 13px/1.5 sans-serif` 与 `font: 500 13px/1.5 var(--font-ui)`（简写，brief 点名的一类）、`[font:13px/1.5_sans-serif]`、`text-[.8rem]`（无前导 0）、`text-[calc(13px+1px)]`、`text-[clamp(12px,1vw,14px)]`、`text-[13PX]`、带引号的键 `"fontSize": 13`（应用里 `pages.ts` 的 `h("p", {"class": …})` 就是这种写法，nb-ui 里的渲染函数同理）。
  - 可能误报：`font-size: 0`、`font-size: 1em`、`font-size: 0.9em`、`text-[1.1em]`（相对字号，不是字面像素，却被同一条 `\d` 命中；现在 nb-ui 里没有，将来第一处要用 `em` 放大图标字形时只能加整文件豁免）。
  - 覆盖面：只扫 `components/**/*.vue`。不扫 `styles.css`（本次改过其中三处）、`.ts` 里的渲染函数、应用 `src/`、两个宿主包。
  - 豁免是按整个文件登记的（`controls/IconButton.vue`）：该文件以后再写任何字面字号都不会被发现；其它规则的豁免也是这个形状，但它们大多是单值，这里理由只对 2xs 一个 9.6px 成立。
  - 注释编号：文件头注释写“8.”，计划与提交说明写“规则 7”（规则 7 已是变量声明检查）。
- 如何核实：`bun scratch/re.ts`（见 scratch 目录）。
- 建议：正则加 `font\s*:[^;]*\d+(px|rem)\b`、放宽 `\.?\d`、对 `fontSize` 允许引号键；`em` 相对值从 `font-size` 一支里剔出（只拦 `px`、`rem`）；`styles.css` 加进扫描；豁免改成“文件 + 命中值”。

## F11 [建议] 菜单行行高写死 16px，14px 汉字下更紧
- 位置：packages/nb-ui/src/styles.css:296（`.nb-ui-menu-item { line-height: 16px }`）、:321（`padding-block: calc((var(--menu-item-h) - 16px) / 2)`）；:382（分组标题 `--leading-tight`）
- 现象：nbook 的菜单字号由 13px 变 14px，行高仍是字面 16px：比值 1.23 → 1.14；nbook 主题自己的注释说汉字要 1.5，1.35 都“贴得明显”。单行项行高 30px 内居中看不出，但允许换行的项（DropdownMenu 的 `wrap`，目前只在 Lab 里有）会按 16px 一行叠起来，汉字 14px 的两行几乎相贴。分组标题则改成 `--leading-tight`（nbook 12×1.3=15.6px、macOS 11×1.25=13.75px），出现小数高度，原来是整 14px。
- 建议：菜单项的行高也取 `var(--leading-tight)` 或按字号推出，并把 multiline 的内边距公式一起改；没有换行项需求的话，在 `.nb-ui-menu-item` 旁加一句“行高与字号无关，只管换行项”。
