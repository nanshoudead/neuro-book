# w00027 t03 设置窗口“插件”页 前端 UI 审查

审查对象：`packages/neuro-book/src/plugins/plugins/web/{PluginsPage.vue,PluginsPage.md,plugin.ts,PluginsPage.dom.test.ts}`（worktree `.worktree/w00027-t03-manifest-and-install`）。实验脚本与截图在 `/tmp/neuro-book/review-w00027-t03-ui/`。按影响排序。

### 1. 键盘切换开关后焦点丢到 body；对话框成功关闭后焦点也会落空

- 严重程度：重要
- 类别：可访问性 / 键盘与焦点
- 位置：`PluginsPage.vue:141-152`（`toggle` 期间 `busy=true`）、`:212`（`:disabled="busy || ..."`）、`:131`、`:137`、`:160`；`PluginsPage.md:27`
- 现象：聚焦 `example.hello` 的开关按 Space，请求进行中 `busy` 把这个开关自己停用，浏览器按焦点修正规则把焦点移到 `BODY`；请求结束后焦点不回来。实测输出：`focused: BUTTON switch 启用 example.hello` → `after disable, focused: BODY`。同一机制下（从代码推断，未在浏览器里做不可逆的安装、卸载）：安装成功后 `path` 清空，“安装…”变停用；卸载成功后该行“卸载”变停用；`Dialog` 关闭时把焦点还给“打开前的元素”，而它已停用，焦点同样落到 body。
- 为什么是问题：读屏用户每切一次开关就丢失位置，听不到结果；`PluginsPage.md` 交互一节写“对话框关闭后焦点回到打开它的按钮”，在两条成功路径上都不成立。ui-development-spec 第 4 节要求合同写清“焦点归还”。
- 如何核实：`node /tmp/neuro-book/review-w00027-t03-ui/scripts/focus.mjs`（对着 37729 服务禁用再启用 `example.hello`，脚本结束时已复原，`pending 0`）。
- 建议改法：进行中只停用“其它”写控件，正在操作的开关保持可聚焦（用 `aria-busy`/`aria-disabled` 表达，或在请求期间忽略重复的 `update:model-value`）；安装、卸载成功后显式把焦点放到稳定的落点（新插件那一行、该行的开关，或列表的组标题），并在 `.md` 里写明。

### 2. 读取列表失败时内置组写着“还没有安装第三方插件。”，没有重试；加载态不合页面级状态规范

- 严重程度：重要
- 类别：未处理的状态（加载、失败）/ 与同类页面不一致
- 位置：`PluginsPage.vue:110-119`、`:193-196`；`PluginsPage.md:48-50`
- 现象：
  1. `list()` 失败时 `loading=false`、`items=[]`，两组照常画出。第 196 行对任何空组都显示 `TEXT.noThirdParty`，于是“内置插件”标题下也写“还没有安装第三方插件。”；第三方组的这句话也不成立（不是没有，是没读到）。`.md` 状态一节却写“内置插件一组总有内容”“列表为空”。
  2. 失败只有一行危险色小字，没有“重试”。`.md` 说“之后的操作成功会重新读”，但列表空时没有行可操作，只剩安装能触发重读；用户实际只能离开分区再回来。
  3. 加载态是一行淡色字，没有指示、没有 `role="status"`/`aria-busy`、没有延时显示。
- 为什么是问题：ui-development-spec 4.1 规定页面级加载是“转动的指示 + 独立成立的说明”、带 `aria-busy` 与 `role="status"`，失败是“状态图标 + 原因 + 重试动作”、`role="alert"`；4.3 第 7 条要求加载延时约 200ms 不闪。同一窗口的 `SettingsPageFrame.vue:75-79` 就是这样画的（`Spinner` + `role=status aria-busy`；失败 `role=alert` + 按钮），本页刚过了外壳的加载占位，又出现第二种样式的加载。
- 如何核实：读第 194-196 行模板；让测试替身的 `list` 返回 `{ok:false, code:"registry-failed", ...}` 挂载即可看到两组都写“还没有安装第三方插件。”。
- 建议改法：把 `loading / failed / ready` 做成三态；失败时不画两组，原位画与 `SettingsPageFrame` 一致的失败块（原因 + “重试”调 `refresh()`）；加载态复用同一套指示与延时；空组说明只给第三方组。`.md` 状态一节同步。

### 3. 失败说明的文字：原因与详情重复，路由层失败只剩一个带括号的码，字符串详情被丢掉

- 严重程度：重要
- 类别：文字与交互清晰度 / 失败处理
- 位置：`PluginsPage.vue:43`、`:62-77`、`:99-108`；服务端详情来源 `src/backend/plugins/inventory.ts:66,67,142,150,173,252,257,264`、`src/plugins/plugins/backend/plugin.ts:20-24`
- 现象（按代码拼出的实际文字）：
  - `reserved-id`：“第三方插件的 id 不能以 nbook. 开头（reserved-id）：第三方插件的 id 不能以 nbook. 开头”——原因与详情逐字重复。
  - `uninstall-pending`：“插件正在卸载，重启后再操作（uninstall-pending）：example.x 正在卸载，重启后再安装”；`already-installed`：“已经安装了这个版本（already-installed）：example.x@1.0.0 已安装或等待重启后切换”；`builtin-fixed` 同样一句话说两遍。
  - `manifest-invalid` 的 files 分支：“插件的清单无效（manifest-invalid）：package.json 的 files 必须是字符串数组；files：必须是字符串数组”。
  - 没有文字的码（路由层的 `denied`、`not-provided`、`provider-error`、`invalid-input`、`target-gone`、`version-changed`、`cancelled`）：`reason` 为空，结果是一行“（denied）”，英文是“ (denied)”。路由层失败的 `detail` 是字符串（`nb-runtime/src/remote/protocol.ts` 的 `RemoteFailure.detail` 注释），`report()` 只取 `detail.detail`，这句说明被丢掉。
  - 另外：失败行插在安装区和列表之间，出现、消失都会把整列下推、上拉。
- 为什么是问题：用户读到的是“X（码）：X”的复读，或一个看不懂的英文码；格式 `{reason}（{code}）：{detail}` 把机器码夹在句中，读起来不通。ui-development-spec 5.8 要求提交后才知道的错误“写在一个固定位置”、不改变排版。
- 如何核实：对照 `inventory.ts` 各 `failure(code, detail)` 的文字与 `FAILURE_TEXT` 拼接；`denied` 等码不在 `FAILURE_TEXT` 里。
- 建议改法：详情与固定文字二选一——服务端已经给了完整中文句子的码只显示详情（或只显示固定文字），码放到末尾的淡色括注或 `title`；`problems` 用换行列出而不是“；”拼接；未知码给一句通用文字（“操作没有完成”）并显示字符串详情；失败行放在固定占位（例如安装行下方常驻一行高度），不推动列表。

### 4. 结果未知、列表过期的失败不重读列表，提示“刷新后再看”却没有刷新入口

- 严重程度：重要
- 类别：未处理的状态（进行中 / 结果未知）
- 位置：`PluginsPage.vue:76`、`:125-167`
- 现象：写请求帧发出后链路中断或超时，结果一律是 `unknown-outcome`（`nb-runtime/src/remote/protocol.ts:64-70`）；安装要复制整个插件文件夹，是最容易超时的一步。页面只显示“结果未知，刷新后再看”，不调 `refresh()`，页面上也没有刷新按钮。`not-installed`（Spec 失败码表写“调用方怎么办：刷新列表”）、`uninstall-pending` 同样不重读。安装 `unknown-outcome` 后输入框也保留原路径，用户再点安装多半得到 `already-installed`。
- 为什么是问题：用户看到的列表与登记表不一致，又没有可执行的下一步；“刷新”指的是哪一个刷新（页面？浏览器？）也不清楚，刷新浏览器会关掉设置窗口。
- 如何核实：读 `install`/`toggle`/`uninstall` 的失败分支，均为 `report(result); return;`。
- 建议改法：失败码为 `unknown-outcome`、`not-installed`、`uninstall-pending`、`already-installed` 时在报告失败之后调 `refresh()`；文字改成“结果未知，已重新读取列表”之类可独立成立的说法。

### 5. 卸载确认用普通 `Dialog`，确认按钮是主色蓝；行内“卸载”反而是实心红

- 严重程度：重要
- 类别：nb-ui 组件契约 / 注意力顺序
- 位置：`PluginsPage.vue:217`、`:237-249`
- 现象：卸载确认是 `Dialog` 的默认页脚，确认按钮固定 `variant="primary"`（`nb-ui/src/components/feedback/Dialog.vue:425`），即蓝色“卸载”；而每一行打开对话框的“卸载”是 `variant="danger"` 实心红（截图 `t03-shot/desk/page.png` 中两行各一枚红按钮，是整页最醒目的东西）。危险色用在了“打开确认框”这一步，真正执行不可撤销操作的按钮却是普通主色。
- 为什么是问题：`Dialog.md` 的“不支持”一节明写“替代 `AlertDialog` 做破坏性二次确认”；Button 的 `danger` 语义是危险操作本身。同仓库的列表行删除动作用中性的 `IconButton`（`examples/plugins/snippets/web/SnippetsEditor.vue:92`），不在每行放实心红按钮。
- 如何核实：看截图；读 `Dialog.vue:424-425`。
- 建议改法：行内“卸载”改 `secondary` 或 `ghost`（`size="sm"`）；确认框用 `Dialog` 的 `footer` 插槽放 `Button variant="danger" :loading="busy"`（`AlertDialog` 没有 busy，确认即关，不适合等待结算），或给 `AlertDialog` 补 busy 后改用它。

### 6. 组件放在 `web/` 根下而不是 `web/components/`，因此不进 Component Lab 索引，也绕过了场景登记门禁

- 严重程度：重要

### 7. 每行“卸载”按钮的可访问名称都是“卸载”，不带插件 id

- 严重程度：重要
- 类别：可访问性
- 位置：`PluginsPage.vue:217`（对照 `:213` 开关的 `aria-label`）
- 现象：开关的名称是“启用 {id}”，同一行的“卸载”没有 `aria-label`，按钮名只有“卸载”。实测 `page.getByRole("button", {name: "卸载"})` 命中 2 个（两个第三方插件）。
- 为什么是问题：读屏用户按 Tab 或按钮列表跳转时听到一串“卸载 按钮”，分不清是哪个插件；这是不可撤销操作的入口。e2e 与读屏按角色找按钮时同样无法区分。
- 如何核实：`node /tmp/neuro-book/review-w00027-t03-ui/scripts/focus.mjs` 输出第二行 `uninstall names 2`。
- 建议改法：`:aria-label="卸载 {id}"`（与开关同一种写法，两种语言各一条文字），可见文字保持“卸载”。

### 9. 安装确认框不区分首次安装、升级与降级，缺 Spec 输出 8.1 的降级提示

- 严重程度：重要
- 类别：Spec 符合度 / 文字
- 位置：`PluginsPage.vue:223-235`；`docs/specs/runtime/plugin-install.md` 输出 8.1、证据一节（“允许降级并提示”，开发者确认）
- 现象：确认框只写完全信任与路径；对一个已安装插件装另一个版本时，用户确认前看不到这是升级还是降级、从哪个版本到哪个版本，也没有“降级可能遇到新版本已迁移过的数据”的提示。合同只有一步 `install {path}`，页面在确认前拿不到要装的 id 与版本，所以现在也无法提示。依赖者受阻列表在 t03 计划第 26 行明确推迟到 t04，降级提示没有被列为不做。
- 为什么是问题：本页面声明实现 plugin-install 输出 1–4、7–9，输出 8.1 的确认界面要求在这里落地；降级是唯一可能损坏插件私有数据的路径，确认框是 Spec 写的“唯一告知点”。
- 如何核实：读合同 `shared/contracts.ts` 的 `install`；`PluginsPage.md` 的交互与“不支持”两节都没有提升级、降级。
- 建议改法：合同加一个只读的 `inspect {path}`（返回 id、版本、与已安装版本的关系），确认框据此显示“安装 X 1.0.0”“升级 X 1.0.0 → 1.1.0”“降级 X 1.1.0 → 1.0.0（提示数据）”；本轮不做就在 `.md` 的“不支持”与 Task 记录里写明并回指 Spec。

### 11. 每个插件一个描边圆角框，读起来像一排输入框；组标题样式与设置列表不一致

- 严重程度：建议

### 12. “没有登记”徽标的色调与文字：安全模式用危险红，“只加载了声明”说的是开发进度

- 严重程度：建议
- 类别：文字与注意力顺序
- 位置：`PluginsPage.vue:54-59`、`:205`、`:207`；详情来源 `src/backend/plugins/startup.ts:224,237`
- 现象：
  - 安全模式下每个第三方插件都挂一枚 `danger` 红色“安全模式未加载”，上方已有警告横幅。安全模式是用户主动选的状态，不是插件出错；一屏红色徽标会让人以为插件全坏了。
  - `entries-not-loaded` 徽标写“只加载了声明”，下面一行是服务端的“入口代码的装载尚未实现，本次只登记顶层声明”：这是产品开发进度，用户读不懂也无法处理。
- 为什么是问题：design-language 状态色只给状态语义；“错误”类红色应留给“清单无效”“不兼容”这种需要用户处理的情况。
- 如何核实：读第 205 行的 tone 三元式（只有 `entries-not-loaded` 是 neutral）。
- 建议改法：`safe-mode` 用 neutral 或 warning；`entries-not-loaded` 在 t04 之前改成用户能理解的说法（例如“界面与命令要等以后的版本才能用”）或干脆不显示，详情文字由页面按码给，不直接显示服务端的开发说明。

### 13. 卸载中的行：开关显示为“关”，确认框没说卸载不能撤回

- 严重程度：建议
- 类别：文字与交互清晰度
- 位置：`PluginsPage.vue:37`、`:211-212`
- 现象：卸载后 `state` 变成 `uninstalling`，开关值 `item.state === 'enabled'` 变成关、停用；而本次运行中插件照常在跑（Spec 输出 3）。确认框正文“卸载 {id}？重启后删除插件的安装目录，配置与私有数据保留。”没有说确认之后到重启之前不能撤回、不能再启停或重装（`.md` 第 25 行与 Spec“卸载与待切换版本不能撤销”都写了）。
- 为什么是问题：灰掉的“关”读起来像“已禁用”，与旁边“重启后卸载”徽标叠在一起意思含混；不可撤回是用户确认前最需要知道的一句。
- 如何核实：测试第 105-119 行的场景结束时开关 `aria-checked=false`。
- 建议改法：卸载中的行不画开关（只留“重启后卸载”徽标），或保持显示卸载前的值并停用；确认框补一句“重启之前不能撤回”。

### 14. 第一个控件之前堆了三层说明；“服务端上的路径”只写在占位文字里；路径框按 Enter 无反应

- 严重程度：建议
- 类别：注意力顺序 / 表单与无障碍
- 位置：`plugin.ts:28`；`PluginsPage.vue:24`、`:29`、`:180`、`:184-188`
- 现象：
  - 分区说明“从本地文件夹安装第三方插件，启用、禁用或卸载它们”（22 字，复述页面上的动作）+ 常驻横幅 + 安装区标签，三层说明后才到输入框。其它分区的说明在 10 字左右（`settings/web/plugin.ts:89`、`explorer/shared/settings.ts:15`）。分区说明的“本地文件夹”与占位文字的“服务端上”说法还不一致——服务端部署时，“本地”会被理解为用户自己的电脑。
  - “服务端上含有 package.json 的文件夹路径”只在占位文字里：开始输入后就消失；390px 下被截成“服务端上含有 package.json 的文”（`t03-shot/narrow/page.png`）。
  - 输入框不在表单里，按 Enter 不会打开确认框，只能鼠标点或 Tab 到“安装…”。
- 为什么是问题：ui-development-spec 5.4：区段标题下挂一句 20 字以上的灰色说明是最常见的违反形态，元信息走 tooltip 或 info 图标；占位文字不能代替标签与说明。
- 如何核实：看两张截图；读模板。
- 建议改法：分区说明缩短或删去（横幅已交代生效时机）；“服务端上的文件夹，需含 package.json”放进标签旁的 `InfoTip` 或标签文字（“服务端上的插件文件夹”），占位文字给示例路径；把安装行包成 `<form @submit.prevent>`，Enter 打开确认框。

### 15. 英文界面里混入中文标点与中文详情

### 17. 失败说明随 `v-if` 与 `role="status"` 一起插入，读屏可能不播报；同一失败第二次出现时文字不变也不播报
