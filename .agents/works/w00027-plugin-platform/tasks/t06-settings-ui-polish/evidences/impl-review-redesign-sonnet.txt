## F1 [重要] nb-ui Tooltip：悬停或聚焦时按 Esc 会吃掉下一次 forceOpen 强制显示
- 位置：`packages/nb-ui/src/components/feedback/Tooltip.vue:53-62`
- 现象：`onEscapeKeyDown` 无条件把 `escDismissed` 置真，而清除它的 `watch(forceOpen)` 只在 `forceOpen` 变为假时清。`forceOpen` 本来就是假时按 Esc（提示是悬停或聚焦开的），`escDismissed` 变真后没有任何“假”的变化来清它；之后 `forceOpen` 变真，`shown` 仍为假，提示不显示。
- 为什么是问题：`SettingsRow` 的原因图标用 `:force-open="controlFocused"`。用户悬停图标看提示、按 Esc 收起，之后 Tab 进控件，本该强制显示的出错原因不出现，键盘用户读不到原因（只有读屏文字）。与 `Tooltip.md` 写的“Esc 关掉之后要等 forceOpen 先变假再变真才再次强制显示”不是同一件事：这里 forceOpen 根本没开过。
- 核实：在 `reports/impl-review-sonnet/scratch/tooltip-esc.test.ts` 写了最小复现（`forceOpen:false`，focus 触发器显示，Esc 关，blur，`setProps({forceOpen:true})`，断言显示），跑出失败：`Expected "tip" Received "x"`。新增的 4 条 forceOpen 测试只覆盖 forceOpen 为真时按 Esc，没有这一条。
- 建议：`onEscapeKeyDown` 里只在 `props.forceOpen` 为真时置 `escDismissed`；并补这条测试。

## F2 [重要] 层警告在有未保存改动时“放弃”之后，焦点被左栏抢走，光标没有落在出错处
- 位置：`packages/neuro-book/src/plugins/settings/web/components/SettingsWindow.vue:196-211`（`onLeaveClosed`）与 `SettingsFileView.vue:225-245`（`locate`）
- 现象：点层警告、确认框里点“放弃”之后，`SettingsFileView.locate()` 读完文件会把焦点给文本框；但确认框 `closed` 事件（关闭动画与焦点栈释放之后才发）触发 `onLeaveClosed`，对 `kind: "file"` 走末尾的 `else focusCurrent()`，把焦点移到左栏“设置文件”这一项。
- 为什么是问题：Spec 输出 13 要求“光标放在出错处”；窗口里 DOM 测试只断言了 `selectionStart`（`SettingsWindow.dom.test.ts:1106-1109`），没有断言 `document.activeElement`；无确认的那条路径（1020 行）断言了 activeElement，所以只有确认路径漏了。用户点“放弃”后看到的是光标不在文本框里，键入的字不会进文本框。
- 核实：在 `reports/impl-review-sonnet/scratch/focus.dom.test.ts` 复现（页面报未保存、层文件有语法错误、点警告、点“放弃”、等文件读完与确认框消失），`document.activeElement` 是 `data-settings-nav="file"` 的左栏按钮，不是 `[data-settings-file-text]`，断言失败。
- 建议：`onLeaveClosed` 里 `kind === "file"` 且有待定位位置（或视图已经把焦点放进文本框）时不再 `focusCurrent()`；并在确认路径的测试里补 activeElement 断言。

## F3 [重要] 设置文件视图：切标签后文本框是新建的（滚动归零），行号列和出错行底仍停在旧的平移量上
- 位置：`packages/neuro-book/src/plugins/settings/web/components/SettingsFileView.vue:182-186`（`watch(() => props.layer)`）、`:292-294`（`onScroll`）；`scrollTop` ref 只在 `onScroll` 里写。
- 现象：`watch(layer)` 把 `state` 置为 `loading`，文本框随 `v-else` 卸载，读完后新建一个文本框（`scrollTop` 为 0），但 `scrollTop` ref 保留旧值，行号列继续 `translateY(-旧值px)`，行号与文本错位一整段，直到用户滚一下文本框才重新同步。出错行底（跟同一次平移）同样错位。
- 为什么是问题：设计里的“行号一行对一行”被破坏；窗口里用户和作品两层各有一份设置文件，在文件里滚动后切标签是常规操作。
- 核实：`reports/impl-review-sonnet/scratch/scroll.dom.test.ts`：Lab 场景 `file`，文本框 `scrollTop=42` 并派发 `scroll`，转换成 `translateY(-42px)`；`setLayer("project")` 读完后，新文本框 `scrollTop` 为 0（`same textarea: false`），行号列的 transform 仍是 `translateY(-42px)`。现有测试（`SettingsWindow.dom.test.ts:504`）只覆盖同一层内滚动。
- 建议：文本框重新挂载时（`state` 回到 `ready`，或 `load` 里在换文本前）把 `scrollTop.value` 复位为文本框的实际 `scrollTop`；补一条“切标签后行号列平移归零”的测试。
## F4 [重要] SettingsPageList 打开一项后焦点掉到 body；标题区的返回按钮读屏只念分区名，没有“返回”
- 位置：`packages/neuro-book/src/ui/settings/SettingsPageList.vue:93-119`（打开时不管焦点）；`packages/neuro-book/src/plugins/settings/web/components/SettingsSectionHeading.vue:59-62`（返回按钮的内容）
- 现象：
  1. 点（或 Enter）列表里的一行，这一行随列表一起卸载，`document.activeElement` 变成 `body`，没有任何地方把焦点放进详情或标题区的返回按钮。只有“返回”这一方向做了焦点处理（返回后回到那一行）。
  2. 窗口里（有通道时）返回按钮的文字是“‹ {分区标题}”，例如“模型服务”，没有 `aria-label`，也没有“返回”二字；而 `SettingsPageList` 自己的 `TEXT.back`（“返回”）只在没有通道时用。读屏用户听到的是一个名叫“模型服务”的按钮，与左栏同名的“模型服务”分区项重名，不知道是返回。标题 `h2` 随之变成详情名，没有 live region，也没有读出变化。
- 为什么是问题：Spec 输出 19 写了“返回回到列表、焦点回到这一项”，对称的“进去”没有写，键盘与读屏用户进去之后是失焦状态，第一次 Tab 的位置取决于浏览器的“顺序焦点起点”，不可预期；且任务重点第 2 条（返回、保存后的焦点去向）要求这些路径明确。
- 核实：`reports/impl-review-sonnet/scratch/open.dom.test.ts`（Lab `page-fill` 场景）：先 `row.focus()`，`row.click()` 后 `document.activeElement` 为 `BODY`；返回按钮 `textContent` 为“模型服务”、`aria-label` 为 null；标题区没有 `aria-live` 或 `role=status`。`SettingsWindow.dom.test.ts:664-683` 与 `SettingsPageList.dom.test.ts` 只断言了返回后的焦点。
- 建议：打开后把焦点放到详情的第一个可聚焦处或返回按钮（`SettingsPageList` 在 `opened` 变化后 `nextTick` 处理，同返回的写法）；返回按钮加 `aria-label`“返回 {分区标题}”（用与 `SettingsPageList` 一致的 `TEXT.back`）；补两条测试。

## F5 [建议] 出错原因在控件的 aria-describedby 里念两遍（字段自己的错误加行的“未保存：…”）

## F6 [重要] 标题区没有给长标题留余地：下一级页面的标题很长时压在页面级操作上、冲出窗口
- 位置：`packages/neuro-book/src/plugins/settings/web/components/SettingsSectionHeading.vue:119-137`（`__line`、`__title` 的 `flex-shrink: 0; white-space: nowrap`）与 `:171-176`（`__side` 的 `flex-shrink: 0`）
- 现象：说明可以截断，标题自己不缩也不截断；标题被 `SettingsPageList` 替换为用户给的名字（服务商名等自由文字）后，名字够长就越过 `__side`，盖在“测试连接”、删除按钮上，右端被窗口裁掉。
- 为什么是问题：被替换的标题是用户输入，不是分区名；Spec 输出 3 只要求“说明放不下时截断”，没规定标题，但它与页面级操作同一行，互相覆盖就是不可用（删除按钮被盖住点不到）。窄窗口（输出 16）更容易触发。
- 核实：真实浏览器（Chrome，Lab `SettingsWindow` 场景 `page-fill`，1600×1000 窗口）：打开一家服务商，把名称改成 40 多个字再 Tab 出来，测得标题 `h2` 的右缘 1577，标题区右缘 1203，操作区 1083–1203，即标题越出标题区 374px、压在操作区上；截图 `reports/impl-review-sonnet/shots/long-title.png`，脚本 `reports/impl-review-sonnet/pw/longtitle.mjs`。
- 建议：标题加 `min-width: 0; overflow: hidden; text-overflow: ellipsis` 并允许收缩（说明先收、标题后收，`Tooltip` 或 `title` 显示全文）；补一条用很长的标题打开详情的 e2e 或截图断言。

## F9 [建议] “整数行高、同奇偶”只在 nbook 主题下成立；macOS、editorial 主题下列表里的控件仍落在半像素上
- 位置：`packages/neuro-book/src/plugins/settings/web/components/SettingsListSection.vue:197-205`（`__group-title` 的 `line-height: var(--leading-ui)`）、`SettingsRow.vue:409-418`（`__override` 同）、`SettingsSectionHeading.vue`；规则写在 `packages/nb-ui/docs/design-language.md` 新增一节
- 现象：行内的文字块是 20+2+18 的整数高，但行与行、行与标题区之间的高度由 `font-size × --leading-ui` 决定。nbook 下 `--leading-ui` 为 1.5、`--text-xs` 12px，分组标题正好 25px，整页落在整数上；macOS 下 1.35 与 11px，分组标题 21.84px，之后每一行都偏 0.84px，后面再接 15px 高的覆盖提示又变成 .69。
- 为什么是问题：设计决定第 10 条要消除的就是“控件落在半像素、边框被抗锯齿糊开”；新增的 design-language 规则写成通用规则（“行内并排的文字块与控件同奇偶、行高取整数”），实现只在默认主题成立。用户设置里“主题”本身就在切 NeuroBook 与 macOS。
- 核实：真实浏览器里对 `SettingsWindow` 的 `user`、`other`、`project` 三个场景在 nbook、macOS、editorial、aurora 下，取每行第一个控件相对窗口根的 top 与 bottom（`reports/impl-review-sonnet/pw/halfpx.mjs`、`pw/heights.mjs`）：nbook 的分段控件、下拉、数字框、单行输入、列表全部为整数；macOS 的 `user` 3/3、`other` 7/7、`project` 1/1 行落在 .84 或 .69 上，editorial 同样（.39、.17、.78）。另外 nbook 与 aurora 的开关（nb-ui `Switch` 的 `h-5`）高 24.75px、24.13px，在 40px 的文字块里居中，top 为 .63 与 .94，也不是整数（开关无描边，只影响轨道边缘的清晰度）。
- 建议：分组标题、覆盖提示这类间隔用整数的 `line-height`（如 `calc(round(...))` 或固定像素）；或在 design-language 里写明“只对 nbook 主题成立”，并在自检清单里加上“其它主题下逐行核对”。
