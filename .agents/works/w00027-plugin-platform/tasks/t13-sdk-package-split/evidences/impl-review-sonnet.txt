现象：(a) browserHostModules 返回 Record<string, unknown>，8 项逐个手写。src/web/host/plugin-modules.ts 那张用 `satisfies Record<BrowserSharedModule, object>` 在编译期与档案同步，这张没有。SDK_ENTRIES 或 TYPEBOX_MODULES 增项时，档案自动变，真宿主表编译失败提醒，这张表静默落后——只有恰好有产物 require 新模块时才以“表外模块”失败。(b) 判定“产物只经宿主 require 取共享模块”靠执行：装载器先用这张表执行一次工厂，runFactory 再执行一次（模块顶层副作用跑两遍），`required` 只含工厂执行期间调用过的 id。产物里 activate 内才执行的懒 require（例如作者写 `await import("<外部包>")` 编译成的懒 require）不会出现。我用 scratch/artifact-mut.ts 对手写的登记外壳做了变异：顶层 require("@vue/shared") 与 require("typebox/schema") 都被拦（抛 module-not-shared）；把同样的 require 放进 exports.activate 里，registeredFactory 与 runFactory 都返回 OK、required 为 []，只有真的调用 activate 才抛“表外模块”。旧实现（正则扫压缩产物全文）看得到这类引用。

如何核实：bun /tmp/claude-1000/review-t13-impl/scratch/artifact-mut.ts（输出见上述 5 种情形）。
建议改法：(a) 给 browserHostModules 标注返回类型 Readonly<Record<BrowserSharedModule, unknown>> 并用 satisfies，漏项编译失败；或再加一条 `Object.keys(await browserHostModules()).sort()` 等于 BROWSER_SHARED_MODULES 的用例。(b) runFactory 里让 require 同时记录并在 `required` 之外导出“表内 id 清单”，或在 pack.test 里额外对产物全文做一次宽松的 `require("…")` 扫描作兜底；至少在注释里写明“只覆盖工厂执行期间的 require”。
