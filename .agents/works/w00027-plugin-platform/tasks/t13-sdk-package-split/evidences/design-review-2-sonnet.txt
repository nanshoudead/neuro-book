N1  [重要 / 接口与构建 / 档案分层]  “纯数据档案”和“惰性模块提供函数”被放进同一个文件 src/plugin-platform-profile.ts，会让 Node 类型检查和 SDK 构建同时失败
位置：design 3.4（“平台档案分两层”与“应用给出自己的档案 src/plugin-platform-profile.ts：上面的取值，加上提供模块的函数”）；plan 3 的 S2；
      src/web/boot.ts:60；src/backend/plugins/loader.ts:45；scripts/plugin-sdk/build-sdk.ts:213-220（第二次 rolldown，入口 build 与 cli）；tsconfig.json include 的 src/*.ts
现象：第 1 轮 R3 的处理是“分两层”，但 3.4 写的落点仍是一个文件。构建预设（plan 里进 build/）、作者命令（cli.ts、create-plugin.ts）都要导入数据层；
  数据层所在的文件若还含 hostModules，里面有对 nbook/sdk/browser、nbook/sdk/components 的动态导入（浏览器分支必须用 vue 与 nb-ui 的 .vue 组件）。
  实测两处：
  1) Node 的类型检查。在 /tmp/nb-review-t13-r2/ws 的拷贝里加一个 src/plugin-platform-profile.ts，内容只有 hostModules 的两个动态导入
     （nbook/sdk/browser、nbook/sdk/components），`tsc --noEmit -p tsconfig.json`：基线 0 个错误，加文件后 62 个错误
     （nb-ui/src/components/index.ts 的 `*.vue` 无导出成员等）。原因：tsconfig.json 的 include 里有 `src/*.ts`，把它纳入了没有 .vue 声明的 Node 程序；
     现在浏览器模块表在 src/web/host/plugin-modules.ts，只在 tsconfig.web.json 的程序里。
  2) SDK 打包。构建预设与 cli 是 build-sdk.ts 里 rolldown 的入口（无 Vue 插件）。用 /tmp/nb-review-t13-r2/rd 复现：入口只导入档案文件里的数据，
     档案文件里有一个未被入口使用的动态导入指向含 .vue 的模块，rolldown 报 PARSE_ERROR（Unexpected JSX expression，在 .vue 文件上）。
     就是说 build.js 与 cli.js 打不出来。
  另外服务端与浏览器共用 hostModules(location) 一个函数也有同样问题：浏览器分支进了服务端与项目子进程的程序，服务端分支进了浏览器的程序。
为什么是问题：不是静默通过，S2c 或 S4 的构建与类型检查会立刻红；但这是设计层面要先定的文件划分，S2a 就会碰到（搬家后的 backend/loader 要从档案取表）。
  同一点还决定浏览器首屏：boot.ts 现在用 `await import("./host/plugin-modules")` 保住懒加载，档案静态导入后，hostModules 必须只含动态导入，不能静态导入 sdk。
如何核实：见上两处实验；命令 `cd /tmp/nb-review-t13-r2/ws/packages/neuro-book && bunx tsc --noEmit -p tsconfig.json`；rd/run.ts。
建议改法：档案拆成至少三个文件，写进 design 3.4：
  (a) profile 数据文件（Node、浏览器、构建预设、作者命令都能导入，只含常量与纯函数，不导入 SDK、nb-ui、vue）；
  (b) 服务端/项目的模块提供函数（只导入 @vue/reactivity 与 nbook/sdk/index，放进 tsconfig.json 的程序）；
  (c) 浏览器的模块提供函数（放进 tsconfig.web.json 的程序，boot.ts 动态导入它，保住现状）。
  再加一条测试：构建 SDK 后 build.js、cli.js 的文本里不含 sdk 实现（例如不出现 Vue 或 nb-ui 的标记）。tsconfig.web.json 的 include 是逐个文件列的（src/manifest.ts 等），档案数据文件要补进去。
