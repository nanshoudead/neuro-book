F1  [重要 / 设计 / 中]  SDK 子路径的清单散在 10 处，其中 6 处之间没有任何一致性核对
位置：
  tsconfig.json:14-16、tsconfig.web.json:14-16、vite.config.ts:42-44、scripts/plugin-sdk/build-examples.ts:23-26、
  scripts/plugin-sdk/build-sdk.ts:36（ENTRIES）与 :311-316（package.json exports）、
  src/shared/plugin-modules.ts:15（BROWSER_SHARED_MODULES）、src/web/host/plugin-modules.ts:19-25（宿主模块表）、
  src/backend/plugins/loader.ts:44-47（serverHostModules）、src/architecture.test.ts:86（EXAMPLE_PACKAGES）。
现象：SDK 现在有 index、browser、components 三个入口，每多一个子路径（计划里已有“按所有者分子路径”的讨论），要同步改上面 10 处。
  其中 BROWSER_SHARED_MODULES、hostModules()、serverHostModules() 之间有类型或测试核对（Record<(typeof …)[number], …> 与 plugin-modules.dom.test.ts）；
  tsconfig 两份、vite 别名、build-examples 别名、build-sdk 的 ENTRIES 与 exports 这 6 处之间没有任何核对，漏改一处的表现是
  “仓库里能构建，发布包里缺文件”或“示例能跑、作者类型报错”。
为什么是问题：t05 为 components 子路径已经改过一遍这 10 处，可见这是实际的改动面；子路径发布后又是兼容承诺，漏一处就是发布事故。
建议改法：在 src/sdk/ 下放一张表 SDK_ENTRIES = {".": "index.ts", "./browser": "browser.ts", "./components": "components.ts"}（纯数据，无导入），
  build-sdk 的 ENTRIES 与 exports、build-examples 的别名、vite.config.ts 的别名、BROWSER_SHARED_MODULES 的 sdk 项都从它生成；
  tsconfig 的 paths 不能计算，加一条测试读两份 tsconfig 与这张表对照。这样新增子路径是改一张表加两份 tsconfig。
改动规模：中

  - tokensDoc（:222-252）用正则读 colorway-contract.ts 里的 nbColorwayVarKeys 数组，再写一段“把引号字面量去掉后剩下的是不是空”的残留检查（:228-229）；

  build-sdk.ts 回到 150 行上下。上游选择（nb-ui 不发布、没有导出名单的子路径）当初的理由是“包不外露”，现在 SDK 构建要读它的名单，这个理由已不成立。

F5  [重要 / 设计 / 小]  清单的“生成加校验”要调用方记得做两步，build-plugin 里写了两遍，描述字段还在内核之外拼
位置：scripts/plugin-sdk/build-plugin.ts:471-477（early）与 :520-528（final）；
  packages/nb-runtime/src/plugin-manifest/plugin-manifest.ts:531-538（manifestOf 的注释）。
现象：manifestOf 的注释写“结果还要经 readPluginManifest 校验”，这是靠约定；build-plugin 因此写成 manifestOf → readPluginManifest → 构建 →

F12 [建议 / 设计 / 中]  “贡献 id 必须以插件 id 开头”现在有两套写法：内核的 idPrefix 和 8 个内置校验器各自的 prefix 计算
位置：packages/nb-runtime/src/plugins/host.ts:858 与 contracts.ts:60（idPrefix?: "plugin"，t05 新增）；
  src/plugins/workbench/shared/{items.ts:66,85, views.ts:83, overlays.ts:29}、settings/shared/sections.ts:86、commands/shared/menus.ts:86、
  editor/shared/contracts.ts:106,148 里逐字相同的
  `const prefix = descriptor.plugin.startsWith("nbook.") ? "nbook." : `${descriptor.plugin}.`;`（8 处），旁边还各有一条 `/^[a-z][a-z0-9-]*(?:\.[a-z][a-z0-9-]*)+$/u`（5 处）。
现象：t05 为了让第三方贡献点能“登记时拒绝、原因可查”加了 idPrefix: "plugin"，pending-confirmations 已追认“内置校验带 nbook. 例外，不改用它”。
