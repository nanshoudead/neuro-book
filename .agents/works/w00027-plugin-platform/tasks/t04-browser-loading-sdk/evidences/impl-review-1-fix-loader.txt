一、逐条处理

1. Sonnet 3、14（等待表与全局登记对象）：成立，已改。
   - 核实：旧代码模块级 waiting 是 Map<URL, 单个等待者>，两个装载器同 URL 时后者覆盖前者；registry 绑在首个模块实例的闭包上。
   - 改法：全局登记对象（单例，冻结，全局属性仍不可写不可删）自己持有 Map<URL, Set<等待者>>，对象上有 register(url, factory) 与
     wait(url, waiter) => 撤回函数。register 把工厂交给该 URL 的每个等待者。装载器只经 registry() 取它；Vite 重新求值本模块后拿到的
     仍是同一个对象、同一张表。
   - 第 14 条的“共存”：保留不可写不可删（防插件代码换掉它），改为谁都不再直接写这个全局：registeredFactory 不写了，新测试只读。
     实测三个测试文件放在同一进程里跑（plugin-code.test.ts、build-plugin.test.ts、window.test.ts）46 通过。
     代价写在注释里：对象形状在页面一生里固定，开发时改了 PluginRegistry 的方法要刷新页面。
   - registeredFactory：改为 async，经 createPluginCodeHost 与按 PluginDocument 写的假页面取工厂。假页面的 append 在下一轮事件循环里
     执行产物文本（new Function("document", code)，document.currentScript 就是那个脚本元素），出错派发带文件名的全局 error 事件，
     然后 onload。装载器用宿主模块表执行一次工厂、核对导出了 activate；工厂本身经登记对象的 wait 取得（与装载器一样是同一 URL 的一个
     等待者，正是多等待者的设计），不写全局。每次调用用一个新的页面基址，避免全局登记表在同一进程里交错。

2. Sonnet 9（宿主模块表失败）：成立，已改。
   - 失败不缓存（取失败时清掉缓存的 Promise 再把失败交出去），下次激活重新调用 modules()。
   - 失败包成 PluginCodeError("code-load-failed")，detail “装载不了：宿主模块表没有取到（原始消息）”，带各自激活的插件、入口与 URL。
   - 没有新增失败码：对用户与内核来说是“取不到代码”一类，现有 code-load-failed 足够。
   - 为保留底层错误（TypeScript 规范“保留底层错误的 cause”），给 PluginCodeError 的构造参数加了可选 cause，传给 Error 的 options。
     这是 plugin-code-error.ts 的改动，不是新码，超出 brief 写的“需要新失败码时”，请主会话确认；不要可以改回只在 detail 里带消息。

3. Sonnet 15、omp 3（停止信号）：成立，已改。
   - activateOf 的模块表与工厂两路都与 signal 竞争（untilAborted），abort 时立刻以 signal.reason 失败，结算后撤掉挂在 signal 上的监听。
   - 每个装载器里同一文件的取回是一个 Loading，带还在等的激活数；激活离开（成功、失败或中止）时减一，最后一个离开且取回未结算时撤下：
     移除 <script>、全局 error 监听、计时器、登记对象上的等待者，onload/onerror 置空。之后迟到的登记没有等待者，不理会；下一次激活重新插脚本。
   - omp 3 建议的“结构化停止错误”没有采用：brief 定的是以 signal.reason 失败，内核按停止处理。

4. Sonnet 7（测试）：成立，已补。
   plugin-code.test.ts（11 个用例，结构化假文档，没有 mock、spy、假计时器，超时用注入的 timeoutMs，等待用 waitUntil）：
   - 两次激活得到不同的模块实例，模块顶层计数器从初始值开始，require 取到宿主表里那一份，脚本只插一次；
   - 并发激活同一文件只插一个脚本，两次都成功、各得一份实例；
   - 期限内没登记报 code-load-failed，脚本与全局 error 监听撤下；重试重新插脚本并成功；
   - 文件取不到报 code-load-failed，之后重试成功；
   - 全局 error 事件按文件名归属：本文件报 code-threw，另一个文件同时装载不受影响；

   - 同一文件两次激活中止一个：脚本留着，另一个照常拿到工厂；
   - 宿主模块表第一次失败：code-load-failed、带插件与入口、cause 是原始错误；第二次重新取并成功，modules 调用两次；
   - 同一页面两个装载器同时装同一 URL：都成功。
