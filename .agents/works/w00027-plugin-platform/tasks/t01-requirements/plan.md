# 实施计划：非内置插件规范与切片

2026-10-17 起草，待开发者确认。只覆盖 [t01](README.md) 的范围决定与切片顺序；各切的代码计划在对应 Task 的 `plan.md` 里写。

## 结论

1. **不新写一份《非内置插件规范》**。`docs/specs/runtime/` 下 7 份 `planned` Spec 已经是规范正文、且已 acceptance；新写一份会与它们分叉。本 Work 需要补的是：把其中的矛盾与实现顺序改清，再补**作者视角**的入口（包结构、构建、调试、安装、示例），并把规范逐片实现后晋升 `implemented`。
2. **按纵向切片推进**，每片都在真实宿主上可验收，不先做插件市场式的管理界面。
3. 先做**声明式第三方插件**（没有代码，只有设置项、菜单等顶层贡献）从目录安装并生效；它走通清单、安装、登记与贡献校验，不依赖代码装载。代码装载随后单独切片。

## 规范收口（S0，只改文档）

| 问题 | 处理 |
|---|---|
| 清单由谁生成 | 明确唯一方向：内置插件以 `plugin.ts`（`defineEntry`）为描述，构建时生成 `package.json` 清单；第三方用 SDK 构建预设在构建时生成同一格式的清单。手写清单与生成清单等价，校验用同一 schema；清单生成物是否入库、由哪个脚本生成写进 `plugin-manifest` |
| `api-docs` 与已实现的 Hono 整插件挂载不一致 | 改为：入口声明自己拥有的路由前缀，构建时从 Hono app 提取实际路由表生成文档；不再要求逐路由声明 |
| `plugin-install` 的“即时生效、页面不刷新” | 拆成两条：声明式贡献在登记后即时生效；含代码的入口要求装载与撤回能力。未实现装载前，安装含代码的插件的行为按 `planned` 子条目写清，不承诺 |
| SDK 边界 | SDK 是独立包（先 workspace 私有），只含类型、`defineEntry` 与少量纯函数；构建预设与纯度检查同包或同仓独立包，发布形态另定。`plugin-api` 写明依赖方向：插件 → SDK → 合同模块，不导入宿主内部模块 |
| 内置插件迁移 | `plugin-manifest` 已写“现有内置插件定义迁移到本清单格式”；本轮先做到“同一 schema 能表达现有内置插件”，不立即搬目录 |

作者入口（非规范正文）：SDK 包的 README 承担快速开始与构建说明，`packages/neuro-book/examples/README.md` 增加“外部插件”一节；两者都链接 Spec，不复制行为正文。

## 切片

### S1 清单与声明式第三方插件（最小端到端）

- nb-runtime：读取并校验 `package.json` 清单（字段、id 规则、`main` 边界、`engines.neurobook`、`pluginVersions`），产出与 `defineEntry` 相同的插件定义；补 `version-mismatch` 推导。
- 安装与发现：`<State Root>/plugins/` 目录布局与 `plugins.json` 登记表；启动时扫描已启用插件；安全模式（`NEURO_BOOK_SAFE_MODE=1`）跳过第三方。
- `nbook.plugins` 后端最小接口：`list`、`install`（本地文件夹路径）、`enable`／`disable`、`uninstall`；设置窗口里加一个插件页（列表、状态、安装路径输入、启停与卸载）。不做文件选择器。
- 验收：一个只有 `settings.properties` 与菜单／命令声明的插件，安装后设置项出现在设置窗口，禁用后消失，重启后保持；卸载清理登记与目录。

### S2 浏览器入口装载与 SDK 构建预设

- 宿主模块表、插件文件端点、登记工厂式 CJS、样式装载与失败边界；`enable/disable` 与窗口同步。
- SDK 构建预设：生成清单、纯度检查（不打包 Vue／nb-ui／SDK）。
- 验收：示例插件提供视图与命令，启用后出现在工作台，禁用后卸载；构建产物不含共享模块。

### S3 服务端入口装载与远程服务

- 服务端 ESM 装载（一代次一份模块实例）、远程服务的 `onRemote` 激活、卸载后的资源撤回。
- 验收：示例插件的服务端入口提供远程服务，被浏览器入口调用；禁用后调用得到 `unavailable`。

### S4 作者体验闭环

- 脚手架（一个命令生成可构建的插件目录）、作者文档、完整示例（设置项 + 命令 + 视图 + 远程服务 + 私有存储），从安装到卸载的 smoke。
- 验收：仓库外目录里按文档新建一个插件，安装进产品并使用。

### S5 插件管理界面与高级生命周期

- 影响预览、升级／回滚、热插拔撤回与在途结算、看门狗与安全模式恢复。按 S1–S4 的真实需求再拆。

### 与设置补齐（t02）的关系

t02 独立于插件装载，可并行。建议在 S1 之后做，因为声明式插件安装会让“插件声明的配置”第一次面向用户，密钥与通用编辑的价值随之出现。

## 风险

- 清单与代码定义两套描述并存，容易出现“清单对了、定义不同”的分叉；S1 必须用同一 schema 校验两边，并有往返测试。
- 浏览器装载依赖共享模块表与 CSP 现状，G1 已做一次性验证；实现时先跑一次真实窗口再排期。
- `nbook.plugins` 的安装输入是服务端路径；Desktop 的文件选择器不在本轮，界面只收路径，明确写给本机单用户使用。
