# 实施计划：非内置插件规范与切片

2026-10-17 起草，同日开发者确认（见文末“已确认”）。只覆盖 [t01](README.md) 的范围决定与切片顺序；各切的代码计划在对应 Task 的 `plan.md` 里写。

## 结论

1. **不新写一份《非内置插件规范》**。`docs/specs/runtime/` 下 7 份 `planned` Spec 已经是规范正文、且已 acceptance；新写一份会与它们分叉。本 Work 需要补的是：把其中的矛盾与实现顺序改清，再补**作者视角**的入口（包结构、构建、调试、安装、示例），并把规范逐片实现后晋升 `implemented`。
2. **按纵向切片推进**，每片都在真实宿主上可验收，不先做插件市场式的管理界面。
3. 开发者 2026-10-17 选择本轮包含**浏览器入口与 SDK**：先做清单与安装，再做浏览器入口装载、SDK 构建预设与带视图／命令的示例插件。声明式插件（没有代码）仍是第一片的验收载体，它先走通清单、安装、登记与贡献校验。

## 规范收口（S0，只改文档）

| 问题 | 处理 |
|---|---|
| 清单由谁生成 | 统一心智：作者写的是 TypeScript 定义（`plugin.ts` 与 `defineEntry`），`package.json` 清单是交付与安装格式。内置插件随应用打包、不经安装，**不生成清单文件**；由一个对齐测试把每个内置插件的描述与各位置定义转成清单格式，过同一套校验后再转回比对。第三方的清单可以手写（声明式插件），也可以由 SDK 构建预设生成；安装器只认带合法 `package.json` 的目录，两种来源同等有效。内置插件不改写为 JSON，原因：服务键与合同常量会退化成字符串、需另做一致性检查，且与 ADR 0026 的定义常量结构冲突；不执行代码即可算依赖图（据此惰性装载内置代码）目前不需要，需要时把入口元数据移进 `plugin.ts` 即可 |
| `api-docs` 与已实现的 Hono 整插件挂载不一致 | 改为：入口声明自己拥有的路由前缀，构建时从 Hono app 提取实际路由表生成文档；不再要求逐路由声明 |
| `plugin-install` 的“即时生效、页面不刷新” | 拆成两条：声明式贡献在登记后即时生效；含代码的入口要求装载与撤回能力。未实现装载前，安装含代码的插件的行为按 `planned` 子条目写清，不承诺 |
| SDK 边界 | SDK 是独立包（先 workspace 私有），只含类型、`defineEntry` 与少量纯函数；构建预设与纯度检查同包或同仓独立包，发布形态另定。`plugin-api` 写明依赖方向：插件 → SDK → 合同模块，不导入宿主内部模块 |
| 内置与外置的关系 | 开发者 2026-10-17 定：内置插件与外置插件能力相同，区别只有两点——内置插件随产品默认启用，版本跟随产品版本（描述的 `version` 引用 `PRODUCT_VERSION`）。宿主适配器 `nbook.diagnostics`、`nbook.http` 按 ADR 0026 是宿主的一部分，不在此列 |
| 信任 | 开发者 2026-10-17 定：信任所有插件，不做权限系统（讨论过“拥有者定义权限、清单声明、安装告知、内核在经手的边界核对”，复杂且没有实际使用场景）。删除代理允许清单，任何插件都可以声明 `remoteDelegates`；同步服务（内部服务）不再只限内置插件。部分取代 ADR 0022 的后果，另写 ADR 0027 |
| 内置插件迁移 | `plugin-manifest` 已写“现有内置插件定义迁移到本清单格式”；本轮先做到“同一 schema 能表达现有内置插件”，不立即搬目录 |

作者入口（非规范正文）：SDK 包的 README 承担快速开始与构建说明，`packages/neuro-book/examples/README.md` 增加“外部插件”一节；两者都链接 Spec，不复制行为正文。

## 切片

### S1 清单与声明式第三方插件（最小端到端）

- nb-runtime：读取并校验 `package.json` 清单（字段、id 规则、`main` 边界、`engines.neurobook`、`pluginVersions`），产出与 `defineEntry` 相同的插件定义；补 `version-mismatch` 推导。
- 安装与发现：`<State Root>/plugins/` 目录布局与 `plugins.json` 登记表；启动时扫描已启用插件；安全模式（`NEURO_BOOK_SAFE_MODE=1`）跳过第三方。
- `nbook.plugins` 后端最小接口：`list`、`install`（本地文件夹路径）、`enable`／`disable`、`uninstall`；设置窗口里加一个插件页（列表、状态、安装路径输入、启停与卸载）。不做文件选择器。
- 验收：一个只有 `settings.properties` 与菜单／命令声明的插件，安装后设置项出现在设置窗口，禁用后消失，重启后保持；卸载清理登记与目录。

### S2 浏览器入口装载与 SDK 构建预设

- 宿主模块表、插件文件端点、登记工厂式 CJS、样式装载与失败边界；`enable/disable` 与窗口同步。
- SDK 构建预设：生成清单、纯度检查（不打包 Vue／nb-ui／SDK）。
- 验收：示例插件提供视图与命令，启用后出现在工作台，禁用后卸载；构建产物不含共享模块。

### S3 服务端入口装载与远程服务

- 服务端 ESM 装载（一代次一份模块实例）、远程服务的 `onRemote` 激活、卸载后的资源撤回。
- 验收：示例插件的服务端入口提供远程服务，被浏览器入口调用；禁用后调用得到 `unavailable`。

### S4 作者体验闭环

- 脚手架（一个命令生成可构建的插件目录）、作者文档、完整示例（设置项 + 命令 + 视图 + 远程服务 + 私有存储），从安装到卸载的 smoke。
- 验收：仓库外目录里按文档新建一个插件，安装进产品并使用。

### S5 启停即时生效与高级生命周期

- 运行期启停与引用撤回（`plugin-hot-plug`，即启用／禁用不重启）、影响预览、升级／回滚、看门狗与安全模式恢复。
- 在此之前，S1–S4 的启用／禁用只写登记表、下次启动生效；界面必须写明“重启后生效”，Spec 保持 `planned`。

### 与设置补齐（t02）的关系

t02 独立于插件装载，可并行。开发者 2026-10-17 定顺序：插件平台之后做，先补**长文本／数组／对象的通用编辑**，密钥与设置内搜索随后。

## 风险

- 清单与代码定义两套描述并存，容易出现“清单对了、定义不同”的分叉；S1 必须用同一 schema 校验两边，并有往返测试。
- 浏览器装载依赖共享模块表与 CSP 现状，G1 已做一次性验证；实现时先跑一次真实窗口再排期。
- `nbook.plugins` 的安装输入是服务端路径；Desktop 的文件选择器不在本轮，界面只收路径，明确写给本机单用户使用。

## 已确认（2026-10-17）

- 切片落点：含浏览器入口与 SDK（本文件 S1–S4）。
- 设置补齐顺序：通用编辑优先。
- 启停生效时机：启用、禁用与安装下一次启动生效，`plugin-hot-plug` 留在 S5；设置页写明。
- 产品版本：应用版本定为 `0.1.0`，安装时用 `Bun.semver.satisfies` 真检查 `engines.neurobook`；0.x 期间插件 API 有破坏性改动时 minor 加一。
- 清单来源：见上文 S0 表“清单由谁生成”一行；内置插件不生成清单文件，以对齐测试保证同一 schema。

- 内置与外置能力相同；内置默认启用、版本跟随产品版本；信任所有插件、不做权限系统，删除代理允许清单，同步服务对第三方开放（见 S0 表）。
- 升级：本轮支持重启生效的升级（新版本复制到自己的版本目录，登记表记下待切换版本，下次启动切换并删除旧目录）；热升级移到 `plugin-hot-plug`。
- 插件页也列出内置插件，标“内置”，本轮不能禁用、不能卸载；哪些非核心内置插件可以禁用以后再定。
- 示例改为外置插件，按能力分批：t03 声明式样例；t04 S2 snippets；t04 S3 clock、notes、counter；t05 menu、file-menu 与全部示例经构建、安装、启用运行。进程内场景测试保留，另加安装后在真实宿主运行的 smoke。

以上确认后，本计划与 t03 计划获批。实施顺序：先写 t03 范围的 S0 规范（`plugin-manifest`、`plugin-install`）并给开发者看要点，再交 omp 审查规范、计划与原型 diff，处理完后回 worktree 实施 t03，再做 t04。
