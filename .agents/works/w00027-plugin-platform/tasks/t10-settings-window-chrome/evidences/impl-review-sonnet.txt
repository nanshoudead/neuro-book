## 1. 建议 | 正确性（交互）| 面板上的 pointerdown 一律 preventDefault，按在留白或标题区上不再让输入框失焦
位置：packages/nb-ui/src/composables/useFloatingWindow.ts `startDrag`（约 152-160 行的 `event.preventDefault()`）；packages/nb-ui/src/components/feedback/Dialog.vue 面板 `@pointerdown="floating.startDrag"`。
现象：焦点在输入框里时，按在窗口留白（面板内边距、正文自己的一圈）或任何 `data-dialog-drag` 区域（设置窗口的标题区、左栏顶上），焦点留在输入框里，不发 blur / focusout。
为什么是问题：改动前只有标题文字那一块能触发，现在是整个窗口的留白和设置页的标题区。nb-form 的文字、数字、JSON 控件靠 focusout 提交草稿（NumberControl.onFocusOut），用户在设置窗口里敲完数字去点标题区或空白处，草稿不提交，光标还在框里，之后按键仍进输入框。
如何核实：复刻实验 /tmp/claude-1000/review-t10-impl/exp/t.html（带 preventDefault，`document.activeElement` 在按下后仍是 input）对照 t2.html（去掉 preventDefault，activeElement 变 BODY），脚本 t.mjs、t2.mjs。同一个实验里两种写法在“从留白拖过正文文字”时选区都是空的（指针捕获在面板上），所以这个 preventDefault 对防选字没有额外作用，选字已由区域上的 `user-select: none` 和捕获挡住。
建议改法：去掉 `event.preventDefault()`，或只在真正拖动（位移超过几个像素）时才调用；如果要保留，按下时手动把焦点移到面板（面板本来就是 DialogContent，可聚焦）。改完在 e2e 的拖动用例里补一句：输入框有焦点时按标题区，输入框失焦。

## 2. 建议 | 正确性（交互）| 拖动区域里非 button/input/a/select 的可点元素，点击被指针捕获改投给面板，点不动
位置：useFloatingWindow.ts `inDragRegion` 的排除选择器 `"button, input, textarea, a, select, [data-interactive]"`；`startDrag` 把捕获设在面板上。
现象：区域内按下的是 `<span role="button" tabindex="0">`、`[role=tab]`、`summary` 这类没在选择器里的元素时，按下和松开不移动也会 setPointerCapture + preventDefault，随后的 click 被 Chrome 投给捕获元素（面板），元素自己的 click 处理器不触发。
如何核实：/tmp/claude-1000/review-t10-impl/exp/t3.html + t3.mjs，headless Chrome：`role="button"` 的 span 点击后 handler 未触发（log 为空）；`<label>` 包 checkbox 的点击仍然有效。
为什么是问题：区域从“标题文字那一块”扩到了整条标题栏（含 `header-extra` 插槽）、设置窗口标题区（含页面通过 `SettingsPageActions` Teleport 进来的任意操作）。文档说操作“要自己是按钮”，但 Dialog 的 `header-extra` 与 `data-dialog-drag` 是通用能力，没有这个约束。
建议改法：排除选择器补 `[role=button], [role=tab], [role=switch], [role=checkbox], [role=radio], [role=menuitem], [role=link], label, summary, [contenteditable], [tabindex]:not([tabindex="-1"])`，并把“排除哪些”写进 Dialog.md 的拖动区域一条；或者改成“先判断不拖，满足位移阈值后才捕获”，这样点击不受影响，同时也解决第 1 条。

## 3. 建议 | 测试缺口 | 正文滚动条排除（`onScrollbar`）没有任何测试，且对叠加式滚动条不成立
位置：useFloatingWindow.ts `onScrollbar`（用 `offsetX >= clientWidth`、`offsetY >= clientHeight`）；packages/nb-ui/src/components/components.test.ts 新增的拖动用例；e2e/settings.e2e.ts 新增拖动用例。

## 逐项核对（brief 重点）的结论

1. 拖动判定：面板自己、`data-dialog-body` 自己、`[data-dialog-drag]`；嵌套窗口靠 `closest("[data-dialog-surface]") !== element` 冒泡给内层，我读过逻辑没发现问题；缩放手柄的 pointerdown 冒泡到面板时 `inDragRegion` 返回 false（手柄不在区域内、`target.closest("[data-dialog-drag]")` 为 null），不会同时起拖和缩放；`touch-action: none` 放在面板上不继承，内层滚动容器（正文是 `overflow-y: auto`，touch-action 的求交只算到最近的滚动容器为止）里仍可触摸滚动，我没发现副作用。问题集中在第 1、2、3 条。
2. 角上关闭按钮：位置 8px/8px、26px 与 `--nb-dialog-close-room = 8*2+26 = 42` 对得上（IconButton `sm` 确为 26px，硬编码耦合，Dialog.md 已说明）；busy 时停用、可访问名称与标题栏版本一致；DOM 在正文之前，Tab 顺序里它排第一，Shift+Tab 从首个控件回到它，与原来标题栏里的关闭按钮排在正文之前一致；`closable` 缺省 false，目前只有设置窗口用 `showHeader=false`，没有别的调用方被意外加上按钮。圆角 14px 下按钮没被裁。
3. 让位：宽窗口 `100cqw`、多出的一截、600px 容器查询、fill 页面的公式我手算与布局相符（见第 5 条的算例）；容器是 `.settings-window`（`container-type: inline-size`），标题区在它里面，`cqw` 取的就是它；窄窗口由后写的同优先级规则把 `padding-right` 重置为 0。没有找到算错的情形，问题是没有测试守着。
4. SettingsRow：沿用时插槽拿 `shown`、`disabled` 只看 `blocked`，我读过没发现问题；`describedby` 把沿用标签放在最前，id 与 `v-if` 条件一致；`write-failed` 的 action 收窄后，调用方 `SettingsListSection`（忽略 action）、`SnippetsPage`（只取 code、detail）、`WorksSettingsPage`（同）都不受影响。
   误写本作品层的检查：沿用的行改控件即写本作品层，我追了 `SettingsListSection.write` -> `SchemaField` -> `scope.update`：`scope.update` 在 `Object.is(before, next)` 时直接返回，不发 `update:modelValue`，而 `before` 是 `shown(...)`（沿用值）。所以下拉选同一项（ChoiceControl 每次选择都 emit，但被去重）、开关以外的数字框敲回同一个数字、文字框改了又改回去，都不会写本作品层。仍会写的情形：列表、对象、JSON 控件产生了结构上相等但不是同一个引用的新对象时（例如在 JSON 框里敲一个空格再删掉）会写入内容相同的值，这是用户明确改过，可以接受。没有找到“值没变也发改值”的复现方式。
5. 示例：SnippetsPage.vue 的讲解注释与 .dom.test.ts 与新画法一致（除第 8 条里场景 6 的注释）；`SnippetsEditor` 在沿用时 `disabled=false`，各处理函数都是用户动作触发，不会在挂载或沿用值变化时自己写。
6. 测试：新增的 SettingsWindow.dom.test 用真实控件点击已选项和另一项，断言本作品层是否被写、用户层不变，测到了行为；components.test.ts 的拖动用例用真实冒泡事件，覆盖留白、正文、标题栏空白、区域内文字、区域内按钮和输入框；没有测到滚动条（第 3 条）、嵌套窗口、`touch-action`。e2e 新增拖动用例点位合理（标题区右端点离按钮左缘 2px，纵向也错开，不会误点到按钮）；plugins.e2e 的改动与新画法一致。无 mock、spy、假计时器、固定等待。
