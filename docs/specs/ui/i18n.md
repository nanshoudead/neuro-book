# 界面文字的值、翻译端口与宿主引擎

## 目标与非目标

给宿主、插件与共享包一套共同的界面文字写法：文字值有几种形态、怎么翻译成当前语言、找不到时怎么回退、参数怎么约束、写错怎么发现。方案依据 [《界面文字的消息目录》](../../proposals/i18n-message-catalogs.md)（2026-10-27 接受）。

不承诺：

- 目录文件怎么交付与登记（见 `runtime/plugin-manifest.md`、`runtime/plugin-code-loading.md`、`runtime/browser-host.md`）；
- 各贡献点的短名与补哪些字段（见各贡献点 Spec 的“约定键”；本 Spec 只写通则）；
- 失败文案的码与参数（见各错误域的 Spec）；
- 语言包、伪语言、翻译平台接入；
- 服务端翻译 `TextRef`：服务端只解析字符串与 `LocaleMap`。

## 术语与参与者

- **文字值（`Text`）**：要显示给用户的一段文字，形态见“输入与前置条件”。
- **目录**：一个命名空间（插件 id 或包名）在一种语言下的键到文字的对象。
- **翻译端口（`TextPort`）**：把文字值翻成当前语言字符串的接口，由宿主或共享包的缺省实现提供。
- **最小实现**：nb-ui 自带、不依赖 i18next 的端口实现，只支持插值与 `_one`、`_other` 复数。

## 输入与前置条件

文字值有三种形态：

```ts
/** 不翻译的字面文字，或下面两种。 */
type Text = string | TextRef | LocaleMap;

interface TextRef {
    readonly kind: "text";
    /** 命名空间；声明里不写，由宿主在登记时补上。 */
    readonly ns?: string;
    /** 键，用 `.` 分层；不含 `:`。 */
    readonly key: string;
    readonly params?: Readonly<Record<string, string | number>>;
}

/** 语言标签到文字；键必须是合法的语言标签。 */
type LocaleMap = Readonly<Record<string, string>>;
```

翻译端口：

```ts
interface TextPort {
    readonly locale: Readonly<Ref<string>>;
    t(text: Text): string;
    /** 同一段文字在各语言的写法，给搜索比对用。 */
    variants(text: Text): readonly string[];
}
```

nb-ui 从两个子路径提供：`@notnotype/nb-ui/text`（纯数据层，不引 Vue，服务端可用）与 `@notnotype/nb-ui/text-port`（注入键与 `useText()`）。

### 目录与键

- 目录是一个 JSON 对象，可以嵌套；键路径用 `.` 连接各层（`{"commands": {"say": {"title": "打招呼"}}}` 的键是 `commands.say.title`），叶子是字符串。复数形写成同层的 `<键>_<类别>`（`files_one`、`files_other`），引用写不带后缀的 `<键>` 加参数 `count`。
- 代码里构造引用用 `@notnotype/nb-ui/text` 的 `textRef(key, params?, ns?)`。插件用 SDK 的 `/text` 子路径的 `pluginText(插件 id)`（纯函数，各运行位置可用）：得到绑定了命名空间的构造函数；写成 `pluginText<typeof 源语言目录>(插件 id)` 时，键按源语言目录的类型核对（`CatalogKey`：嵌套展开成点号路径，复数形归到不带后缀的键），写错编译不过；参数名推不出来，由下面的“目录检查”与测试环境的抛错补上。
- 声明里的文字引用可以不写命名空间，登记时补上（见下一节）；运行期交出的文字（状态栏条目的 `text()`、`tooltip()` 这类）不经登记，不补命名空间，必须自己带，所以用 `pluginText`。
- 插件的组件经 SDK 的 `/text/browser` 子路径取文字：`usePluginText<源语言目录的类型>(插件 id)` 返回 `(键, 参数) => 当前语言的字符串`，`useText()` 与 `TextPort` 是 nb-ui 的同名接口。插件运行时这个子路径由宿主模块表给出宿主那一份（[`runtime/plugin-code-loading`](../runtime/plugin-code-loading.md) 的“宿主模块表”），注入键与窗口根上提供端口的是同一个值，所以插件组件拿到的就是窗口的端口。

### 约定键

带文字的贡献点在宿主登记声明时补全文字，结果交给贡献点的校验、贡献的消费者与 `declarations.list`；内核的检查视图仍给作者写下的原样（[`runtime/plugins`](../runtime/plugins.md) 的贡献点 `complete`）。

- **补命名空间**：声明里没写 `ns` 的文字引用补上贡献方插件 id。配置项的 `schema`、`default` 与命令的参数 schema、命令引用的参数不是界面文字，不进去补。
- **补约定键**：贡献点的必填文字字段没写时，补成贡献方插件命名空间下的 `<短名>.<本地 id>.<字段>`。本地 id：贡献 id 以 `<插件 id>.` 开头时去掉这段前缀，否则用完整 id（工作台插件 `nbook.workbench` 的命令 `nbook.view.toggle` 取 `commands.nbook.view.toggle.title`）。列表字段（视图的动作、配置项的选项、分区的小组）里每一项的必填文字字段同样补，键在 `<短名>.<本地 id>.<列表字段>.<项的段>.<字段>`。可选的文字字段省略就是没有，不补键。
- **写了的原样保留**：字符串是不翻译的字面文字，语言映射照常按语言取，写了键的文字引用按写的键取；只有没写命名空间的引用补上命名空间。
- **只补、不核对**：补全是纯函数、不看目录。服务端、项目与浏览器登记同一份声明，结果必须相同，而内置插件的目录只在浏览器的构建里。键在目录里缺不缺由“目录检查”里的声明测试报出，窗口里缺的键按输出 4 显示键名并上报，不在登记时拒绝声明。

## 输出与可观察行为

1. **判别**：先看 `kind === "text"` 判为 `TextRef`；再看字符串；其余对象，所有键都是合法语言标签时判为 `LocaleMap`，否则不是文字值。`kind` 不是合法语言标签，所以 `TextRef` 不会被判成 `LocaleMap`。
2. **`LocaleMap` 的解析**：取当前语言；取不到取 `en-US`；再取不到取第一项（按对象自身的键序）；空对象得空字符串。这条在纯数据层，服务端与浏览器结果相同。
3. **参数整理**：值只能是字符串或有限数字。字符串超过 500 字截到 500 字并加省略号；其它类型（`undefined`、对象、`NaN`、无穷）不传入翻译。每种整理都上报一次诊断（经端口提供方给的上报函数），不静默丢弃。
4. **`TextRef` 的翻译**：在 `ns` 命名空间里按回退链取键：当前语言 → 该命名空间的源语言 → `en-US` → 键名本身。落到键名时上报一次诊断；测试环境下改为抛错。
5. **复数**：参数 `count` 是有限数字时，按当前语言的复数规则取 `<key>_<类别>`，没有时取 `<key>_other`，再没有时取 `<key>`。`count` 不是有限数字时不走复数，按第 3 条上报。
6. **插值**：`{{name}}` 换成参数值，不做 HTML 转义（交给 Vue）；`{{name, number}}` 按当前语言格式化数字（千分位等，两个翻译器相同）；目录里没有对应参数时，测试环境下抛错，其它环境原样留着 `{{name}}` 并上报。
7. **不跨命名空间**：键里的 `:` 不当命名空间分隔；目录值里的 `$t(` 不展开。
8. **缺省端口**：没有宿主注入时，`useText()` 得到 nb-ui 的缺省端口：语言固定为 `zh-CN`，目录是 nb-ui 自带的目录，翻译用最小实现。共享包的缺省端口只含自己的目录（以及它依赖的 nb-ui 目录）：包内组件没有宿主时只翻得出本包的键，别的命名空间的引用显示键名；组件的缺省文案（未传属性时的读屏名称、空态文案等）取自本包目录，调用方显式传属性时以属性为准。
9. **最小实现与宿主引擎一致**：对只用插值（含 `number` 格式）与 `_one`、`_other` 的目录，同一组输入两者输出相同。
10. **`variants`**：字符串得它自己；`LocaleMap` 得它的全部值；`TextRef` 得这个键在所有已登记语言下的文字（去重）。
11. **插件目录进入引擎之前已检查**：插件的目录以插件 id 为命名空间、以清单 `l10n.source` 为源语言登记（`runtime/browser-host.md` 输出 8）。SDK 构建、安装与窗口登记前都按 `runtime/plugin-manifest.md` 输出 12 检查目录，第 7 条的 `:` 与 `$t(` 在那里就被拒绝，不进入引擎。
12. **省略的标题按约定取键**：贡献点的必填文字字段没写时，消费者拿到的是贡献方插件命名空间下的约定键（“约定键”）；同一份声明在三个运行位置补出的结果相同。

### 目录检查

仓库里的目录在提交前由 `governance:check` 查（`scripts/ci/message-catalogs.ts`，也可以单独运行，有问题时退出非零并逐条写出）：

- 查哪些目录：带 `l10n` 的插件清单列出的目录（作者目录的 `package.json` 只写 `l10n.source` 时，取 `locales/` 里的文件，与构建预设相同），加上脚本里登记的、不经清单的目录（宿主与内置插件的目录随前端构建，不写清单；作者模板的清单名是 `_package.json`，也登记在这里）；登记了但仓库里没有的目录不查。`packages/` 下没登记的 `locales/*.json`、清单列了但不存在的目录文件、目录里有清单没列的语言，各报一条。旧应用、归档文档与 `.agents/` 下的文件不查。
- 每组目录以源语言为准：各语言的缺键与多余键（复数形按不带后缀的键比）；同一个键在各语言的占位符集合相同；每种语言按自己的复数规则（`Intl.PluralRules`）要有的复数形都在，英文因此要有 `_one` 与 `_other`；值不含 `$t(`、键不含 `:`；给了闭合错误域的码表时，源语言目录的 `errors.<码>` 恰好覆盖全部码。
- **声明测试**：装载全部内置插件的定义，按各贡献点的补全算出每条声明的约定键与显式写的键，逐个核对在所属插件源语言目录里存在（复数键认 `_other`）；命名空间不是插件 id 的引用（共享包的目录）不在这里核对。缺键与没有目录的命名空间逐条报告。

## 状态与转换

- 当前语言变化后，在渲染期调用 `t()` 的组件不重新挂载就得到新语言的文字。
- 目录登记与注销：同一命名空间再次登记前先注销旧目录（不做浅合并）。

时序与寿命：

- 端口在宿主创建 Vue 根时注入，寿命与该根相同。
- 宿主的当前语言在设置插件激活前取本地记录，激活后跟随它的 `locale`（见 `runtime/browser-host.md`）。

## 副作用与数据

无持久化。诊断经端口提供方的上报函数发出，同一类问题对同一键只上报一次。

## 失败与恢复

| 情况 | 结果 |
|---|---|
| 键不存在 | 显示键名，上报；测试环境抛错 |
| 参数类型不对 | 不传该参数，上报 |
| 目录值缺插值参数 | 原样保留 `{{name}}`，上报；测试环境抛错 |
| 插件某种语言的目录取不到或不合规则 | 这种语言不登记，文字按回退链显示；窗口的插件问题里有一条（`runtime/browser-host.md` 输出 8） |

## 边界与兼容

- 公开接口：`@notnotype/nb-ui/text` 的类型与纯函数，`@notnotype/nb-ui/text-port` 的注入键、`TextPort` 与 `useText()`。第三方插件经 SDK 的 `/text`（文字值的类型与 `pluginText`）与 `/text/browser`（`usePluginText`、`useText`、`TextPort`）使用，nb-ui 不发布（[`runtime/plugin-api`](../runtime/plugin-api.md) 的“SDK”）。
- 现有的 `LocalizedText`（`{zh-CN, en-US}`）是 `LocaleMap` 的特例，迁移期照常有效。
- **体积预算**：宿主窗口启动时把所有已安装插件、共享包与宿主的目录按两种语言都装进引擎（回退链要用源语言）。2026-10-29 实测，内置插件与宿主的 JSON 目录每种语言约 66 到 70 KB（gzip 约 19 到 21 KB），四个共享包的 `.ts` 目录合计约 45 KB（两种语言），两种语言合计 gzip 约 40 KB 加共享包部分。触发拆分的条件：任一语言的 JSON 目录 gzip 后超过 100 KB，或支持第三种宿主语言。到那时改成只取“当前语言加命名空间的源语言”，当前语言变化时再取新语言；现在不做。

## 验收与 Smoke

1. **切换语言不重挂载**：Given 宿主端口与一个渲染 `TextRef` 的组件；When 切换当前语言；Then 组件文字变成新语言，组件实例不变。
2. **回退链**：Given 一个源语言为 `en-US` 的命名空间只有英文目录；When 当前语言为 `zh-CN`；Then 显示英文，不显示键名。
3. **约定键进入消费表**：Given 内置代码、SDK 辅助函数与手写清单各声明一条不写标题的命令与配置项；When 真实服务端实例登记它们；Then 命令表与配置服务给出的标题是各自插件命名空间下的约定键；各贡献点补出的键与“约定键”表一致，写了的文字只补命名空间。
4. **目录检查**：Given 缺键、多余键、占位符不一致、英文缺 `_one`、值含 `$t(`、闭合码缺文案、闭合码多文案的目录各一份；When 运行检查；Then 每份各报一条，命令行退出非零；合格的目录与仓库里的目录通过。Given 内置插件的定义与目录；When 运行声明测试；Then 没有缺键。

5. **第三方插件经 SDK 取文字**：Given 用生成的 SDK 包在仓库外写、构建的插件，带自己的 `locales/*.json`，组件从 `/text/browser` 取文字；When 产物经宿主模块表执行，组件挂在注入了宿主端口的根上，再切换当前语言；Then 组件显示插件目录里当前语言的文字，切换后原位换成新语言，组件状态不丢；产物经 `require` 取这两个文字子路径，不打进自己。

Smoke：`packages/nb-ui` 的 `src/text/` 与 `src/text-port/` 测试；`bun run governance:check` 含目录检查。

## 实现合同

- 公开入口：`@notnotype/nb-ui/text`（`Text`、`TextRef`、`LocaleMap`、判别、`resolveLocaleMap`、参数整理）、`@notnotype/nb-ui/text-port`（`TEXT_PORT_KEY`、`TextPort`、`useText()`）、`@notnotype/nb-ui/text/minimal`；各共享包的 `./locales`；SDK 的 `/text`、`/text/browser`。
- owner 与依赖方向：纯数据层在 nb-ui，不依赖 Vue 与 i18next；宿主引擎（`createTextEngine`、i18next）在应用 `web/host/`，只在浏览器；插件目录经清单 `l10n` 进入引擎，服务端只校验、不翻译 `TextRef`。
- 维护者必须知道、且有测试锁定的不变量：
  1. 最小实现与宿主引擎对同一目录输出相同（输出 9），改任一方的复数或数字规则要两边一起改；
  2. 切换语言不重挂载：`t()` 只在渲染期或 computed 里调用；
  3. 目录进入引擎前已检查，引擎不再防 `:`、`$t(`（输出 11）；
  4. 约定键只在宿主登记一处补出，三个运行位置结果相同（输出 12）；
  5. 同一命名空间再次登记前整个注销，不做浅合并。
