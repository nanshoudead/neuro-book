# 剧情图谱：内置问答

## 目标与非目标

用户问书库里某本小说的问题，nb-story 自己调用模型回答：按“读到哪里”不剧透，答案带结论类型与出处，出处都是这一问读过的原文。一问由一个 Agent 从头答到尾：它用 [`story.queries`](queries.md) 的查询当工具查图、搜索、读原文，最后用作答工具交答案，程序校验答案、不合格就退回让它改。引擎跑在 [`agent.harness`](../agent/harness.md) 上；第一个入口是命令行 `nbstory ask`，以后的网页问答页与 NeuroBook 插件共用同一个引擎与同一份问答记录。

明确不承诺：

- 没有网页问答页：留给后续 Task，那时再改 [`story.viewer`](viewer.md) 的“不做问答”。
- 不保证答对：图是自动抽取的，模型也会错；答对率只由“验收与 Smoke”的回归门槛约束。
- 不限制一问的步数与退回次数（[`agent.harness`](../agent/harness.md) 不设步数上限）；只限制读原文的章数（输出 5）与“没交答案”的提醒次数（输出 10）。
- 不做中文分词与按相关度的检索排序：`search` 只按词拆开、按命中词数排序（[`story.queries`](queries.md) 输出 15）。
- 不接 NeuroBook 的模型角色与密钥接口：单独使用时读自己的配置文件。
- 外部 Agent 的用法（[`story.cli`](cli-skill.md) 的 Skill）不变，Skill 不引导外部 Agent 调 `nbstory ask`。

## 术语与参与者

- **阅读位置**（P）、**出处**、**一代**：见 [`story.queries`](queries.md#术语与参与者)。
- **一问**：一个问题在一本书、一个阅读位置、一种做法下的一次回答；对应一次问答记录。
- **作答 Agent**：一问里调用模型的那个 Agent，用 Profile `story-qa` 运行。
- **做法**：**图当目录**（`graph`，默认）由 Agent 自己查图、搜索、读原文；**全读**（`full`）第一条消息就带上 P 以前的全部原文。
- **读过的原文**：这一问里经 `read` 工具返回过的段落；全读时是 P 以前的全部段落。
- **退回**：作答工具校验不通过，以工具错误结果告诉 Agent 哪里不对，这一问继续。

## 输入与前置条件

### 命令

| 命令 | 用途 |
|---|---|
| `nbstory ask <问题> [--at <章或章.段>] [--mode graph\|full] [--book <书>] [--config <文件>] [--json]` | 问一个问题 |
| `nbstory qa [<记录 id>] [--book <书>] [--json]` | 不给 id：列出这本书的问答记录，新的在前；给 id：显示这条记录 |
| `nbstory qa rm <记录 id> [--book <书>]` | 删除一条问答记录 |

- 不给 `--at` 时读到全书已抽取的最后位置，同 [`story.queries`](queries.md#阅读位置的规则)；`--book` 的省略规则相同。
- 三条命令都接受 `--library <目录>`。

### 配置

配置文件默认在 `$XDG_CONFIG_HOME/nbstory/config.json`（未设置时为 `~/.config/nbstory/config.json`），`--config` 可另指定。只有 `ask` 读它。

```ts
type QaConfig = {
    model: {
        baseUrl: string;            // OpenAI 兼容的服务地址
        id: string;                 // 模型名
        apiKeyEnv: string;          // 存密钥的环境变量名；密钥本身不写进配置
        contextWindow?: number;
        maxTokens?: number;
        thinking?: "low" | "medium" | "high"; // 不写时用模型的默认档
        price?: {input: number; output: number; cacheRead?: number; currency: string}; // 每百万 token；不写时费用未知
    };
    qa?: {
        maxChapters?: number;       // 图当目录一问最多读几个不同的章：1 到 20 的整数，默认 20
        fullReadMaxChars?: number;  // 全读的原文上限（字数），默认 300000
    };
};
```

- 全读的上限按字数算，不按 token。字数在上限内不保证放得进模型的上下文窗口：放不进时这一问以 `model_failed`（`context_overflow`）失败。
- 字段类型不对、`maxChapters` 不是 1 到 20 的整数、`fullReadMaxChars` 不是正整数，都按缺少必填字段处理（`qa_unconfigured`）。

## 输出与可观察行为

### 一问

1. **一问一个 Agent。** `ask` 为一问新建一个会话（Profile `story-qa`、生效工具集见输出 3），把问题作为第一条用户消息运行，直到作答工具交出通过校验的答案（输出 8）、失败或被取消。
2. **阅读位置由程序固定。** P 在一问开始时定下，所有工具都按 P 与这本书的同一代查询；工具参数里没有 `book` 与 `at`，模型改不了。支持视角的工具可以带 `perspective`。
3. **查询工具。** 工具与 [`story.cli`](cli-skill.md#输入与前置条件) 的查询命令同名，参数是对应查询方法（[`story.queries`](queries.md#方法清单)）的参数去掉 `book` 与 `at`（例如 `read` 的 `from`、`to` 是 `{chapter, paragraph}`），结果是该命令给人读的文字输出（不附查看器地址；续页提示写成 `cursor` 参数）：

   | 工具 | 对应命令 |
   |---|---|
   | `info`、`chapter` | 目录、某一章的变化 |
   | `find`、`card`、`knowledge`、`statements`、`appearances` | 对象与人物卡 |
   | `ties`、`between`、`relations` | 关系 |
   | `knows` | 秘密矩阵 |
   | `ledger`、`track`、`questions`、`timeline`、`episodes`、`arcs` | 数值、悬念、时间线、情节 |
   | `search`、`read`、`para` | 搜索、原文、引用某段的记录 |

   查询失败（例如 `entity_ambiguous`、`entity_not_found`）以工具错误结果返回错误码、说明与候选，这一问继续。
4. **原文只到 P。** `read` 只返回 P 以前（含 P）的段落：P 所在章里 P 之后的段落不返回（比 [`story.queries`](queries.md) 输出 14 严，那条例外不适用于问答）；请求的范围整个在 P 之后时是工具错误。
5. **图当目录读原文的章数上限。** 一问里 `read` 返回过段落的不同章，至多 `maxChapters` 个。已经读过的章可以再读；一次调用裁到 P 以后涉及的新章会让总数超过上限时，整次调用是工具错误，写明上限与已读的章，不返回任何段落，也不计入已读。同一条模型消息里的几次 `read` 依次处理，合起来同样不超过上限。全读时没有这条上限。
6. **全读。** 第一条用户消息先给 P 以前的全部原文（每行“章.段 正文”），再给问题；工具照样可用。P 以前的原文超过 `fullReadMaxChars` 时，`--mode full` 在发出任何模型请求之前失败（`full_read_unavailable`）。
7. **作答工具 `answer`。** 它是这一问的收尾工具（[`agent.harness`](../agent/harness.md) 的收尾工具），参数：

   ```ts
   type Answer = {
       conclusion: string;                                  // 先给的结论
       conclusionType: "明说" | "推断" | "解读" | "无法确定";
       knowledge?: {                                        // “谁知道什么”的题：一行一人
           who: string;
           state: "知道" | "怀疑" | "不知道" | "原文没有表明";
           how: string;                                     // 怎么知道的
           refs: Ref[];
       }[];
       points?: {text: string; refs: Ref[]}[];              // 其他题：分点
       explanation: string;                                 // 展开说明
       evidence: Ref[];                                     // 依据出处
       coverage: string;                                    // 覆盖了哪些范围、可能漏了什么
   };
   ```

8. **校验与退回。** 程序校验 `answer` 的参数，全部通过才算交卷，这一问以答案结束；有一条不通过就退回，工具错误结果逐条写出问题，Agent 改了再交。校验项：
   1. 参数符合上面的形状，`conclusion` 不为空；
   2. 每个出处写法正确（“章.段”或“章.段—章.段”），在全书范围内，且不晚于 P。出处包括 `evidence`、`knowledge[].refs`、`points[].refs`，以及各段文字（`conclusion`、`how`、`text`、`explanation`、`coverage`）里写成“章.段”或“章.段—章.段”形状的内容；文字里的数字碰巧是这个形状时同样校验，退回理由会说明，Agent 可以改写；
   3. 每个出处的段落都是读过的原文（范围出处要求范围内每一段都读过）；
   4. `knowledge` 里 `state` 为“知道”或“怀疑”的行至少有一个出处；
   5. `conclusionType` 不是“无法确定”时，`evidence` 至少有一个出处。
9. **作答规则。** Profile 的系统提示词包含作答规则 v5，另加三条：答案按 `answer` 的结构写（先结论，“谁知道什么”的题给一行一人的表）；角色靠自己猜测、或按当时情境能推出的，写成“推断他知道”并给出段落；交卷前逐条核对每个“知道”都指得出段落。
10. **没交答案就停下。** 一次运行以“停止”或“输出到上限”结束、却没有通过校验的答案时，程序在同一会话里再发一条固定的提醒（要求用 `answer` 交卷），至多提醒两次；第二次提醒后仍没有交卷，这一问失败（`no_answer`）。以出错结束的运行不提醒，按 F2 失败；被取消的按输出 13 处理。作答被退回发生在一次运行之内，不算提醒。
11. **结果。** 一问结束时给出：答案（输出 7 的结构）、读过的章（按章号排序）、用量（各次运行相加，输入、输出、缓存读写的 token；配置了单价时给费用，否则费用为空；任一次运行的用量不完整时标为不完整）、用时、模型名、做法、P 与记录 id。

### 命令行

12. **`ask` 的输出。** 进度逐条写到标准错误：调用了哪个工具（例如“查人物卡：苏天晴”“读 37.1—37.96”）、作答被退回（附原因）、交卷。成功时标准输出给人读的答案：结论与结论类型、表或分点、展开说明、依据出处、读过的章、用量与费用、用时、记录 id；`--json` 时标准输出只有 `{"ok": true, "data": <结果>}` 或 `{"ok": false, "error": {"code", "message", "kind"?}}`（`kind` 只在 `model_failed` 时给出），进度仍写到标准错误。
13. **取消。** `ask` 运行中收到中断信号（Ctrl-C）时取消这一问：停止模型请求与工具调用，写下状态为“中断”的记录，退出码 130。
14. **退出码。** 在 [`story.cli`](cli-skill.md#输出与可观察行为) 的 0、1、2 之外：问答失败（失败码 F1 到 F4）为 4；取消为 130。查询类失败（书不存在、阅读位置不合法）在调用模型之前报出，退出码 1；`qa` 命令的 `qa_record_not_found`、`qa_record_broken`（F5、F6）也是 1。用法错误（未知选项、`qa` 的位置参数组合不对）一律为 2，不随书库内容变化。

### 问答记录

15. **每问一条记录。** 一问结束时（交卷、失败或中断）写下一条记录：问题、书、这一代的代号、P、做法、状态（已答、失败、中断）、答案（只在已答时）、失败码与错误归类（只在失败时）、读过的章、用量、用时、模型名、开始时间。中断与失败的记录没有答案，不留半条答案。
16. **查看与删除。** `nbstory qa` 列出这本书当前一代的记录（id、时间、状态、问题、P），新的在前；`nbstory qa <id>` 按 `ask` 的格式显示一条；`nbstory qa rm <id>` 删除它。别的一代的记录不列出、不能显示（`qa_record_not_found`）。读不成记录的文件（损坏）列在最后、标为损坏，不影响其余记录；显示它得到 `qa_record_broken`，可以用 `qa rm` 删除。
17. **密钥不落地。** 密钥只从配置指定的环境变量读出交给 HTTP 客户端，不出现在记录、会话日志、标准输出与标准错误里；模型服务的错误正文回显了密钥时也一样（错误归类与状态码照常保留）。

## 状态与转换

一问的状态：

| 状态 | 进入 | 记录 |
|---|---|---|
| 运行中 | 读完配置、解析书与 P、全读检查通过之后 | 还没有记录，`nbstory qa` 不列出 |
| 已答 | `answer` 通过校验 | 写下，带答案 |
| 失败 | 模型请求失败、`no_answer`、本机错误 | 写下，带失败码 |
| 中断 | 收到中断信号 | 写下，不带答案 |

时序与寿命：

- 记录与会话日志在一问结束时一起写成，对其他读者原子可见：`nbstory qa` 要么看不到这一条，要么看到完整的一条。运行期间书库里没有这一问的任何文件；进程被强行结束（不经中断信号）时什么都不留下。
- 同一本书上可以同时跑几问（几个 `ask` 进程），各自写各自的记录，互不影响。
- 一问固定在开始时的那一代上回答。运行中这本书被删除、或删除后又以同 id 导入时，这一问照常答完、输出答案，但记录不保存（结果里说明），不会重新造出书目录，也不会出现在新一代的列表里。
- 记录写盘失败（例如没有写权限、磁盘满）时，这一问的结果不变：已答的照常输出答案，结果里说明记录没有保存与原因。
- 读过的原文与章数上限只在一问之内计；一问结束后作废。

## 副作用与数据

- **落点**：`<书库>/<书 id>/qa/<记录 id>.json` 是记录；`<书库>/<书 id>/qa/<记录 id>.session.jsonl` 是这一问的会话日志（[`agent.harness`](../agent/harness.md) 的日志格式），一问结束时与记录一起写下。删除记录同时删除会话日志。
- 问答记录随书的这一代：删除书时一起删除。书库格式版本不变（版本 1 的读者忽略 `qa/`）。
- 写入只经 `qa/` 目录；不改书的信息、图与阅读状态。`qa/` 只在书目录已存在时创建，不会凭空造出一个书目录。
- 书库或这本书的格式版本不认识时，按 [`story.queries`](queries.md#副作用与数据) 只读不写：`ask` 照常回答但记录不保存（结果里说明），`qa rm` 得到 `unsupported_format`，`qa` 列出与显示照常。
- 模型请求只发往配置里的服务地址，内容是 Profile 渲染出的系统提示词、问题、工具结果与（全读时）P 以前的原文。

## 失败与恢复

| 编号 | 码 | 含义 | 调用方怎么办 |
|---|---|---|---|
| F1 | `qa_unconfigured` | 没有配置文件，或缺少必填字段（服务地址、模型名、密钥环境变量名） | 按“配置”写好配置文件 |
| F2 | `model_failed` | 模型请求失败；`kind` 取 [`agent.harness`](../agent/harness.md#失败与恢复) 的错误归类（`auth` 含密钥环境变量没有设置，另有 `quota`、`rate_limit`、`network`、`context_overflow`、`provider`、`local`） | 按 `kind`：设好密钥、等额度或限流恢复、重试；`context_overflow` 时改用图当目录或调小上限 |
| F3 | `full_read_unavailable` | P 以前的原文超过全读上限 | 改用图当目录，或调大 `fullReadMaxChars` |
| F4 | `no_answer` | 提醒两次后仍没有交出通过校验的答案 | 重问 |
| F5 | `qa_record_not_found` | 记录不存在、已删除，或属于别的一代 | 用 `nbstory qa` 查 |
| F6 | `qa_record_broken` | 记录文件损坏，读不成一条记录 | 用 `nbstory qa rm <id>` 删除 |

查询类失败（`book_not_found`、`book_ambiguous`、`position_out_of_range` 等）沿用 [`story.queries`](queries.md#失败与恢复) 的码，在调用模型之前报出。

## 边界与兼容

- **公开接口**：`ask`、`qa` 命令与参数、`--json` 的输出形状、退出码、配置文件格式、问答记录的字段。新增可选字段不算破坏兼容。
- **引擎**：`ask` 与以后的网页问答页、NeuroBook 插件调用同一个问答函数；Profile `story-qa` 与工具随包提供。
- **信任边界**：模型只经工具读书库，工具只读；模型的输出在作答工具处校验，不经校验的内容不进记录的答案。

## 验收与 Smoke

“确定性”的场景在 100 章样例书上跑，不调用真实模型；“回归”用真实模型。

1. **防剧透（确定性）。** P = 38.57：模型调 `read 38.50-38.81`，只得到 38.50—38.57；调 `read 39.1` 得到工具错误；交卷引用 38.60 被退回，理由是晚于阅读位置。
2. **章数上限（确定性）。** `maxChapters` 设为 2：读第 3 个新章是工具错误、不给段落；再读已读的章照常返回。已读 1 章时，同一条模型消息里同时读两个新章：恰有一次成功，总数为 2。跨章请求 `37.90-39.1`（P = 38.57）在已读 1 章时整次被拒、不计入已读。
3. **退回后交卷（确定性）。** 第一次交卷引用了没读过的段落、`explanation` 里写了一个晚于 P 的出处、且“知道”的一行没有出处，工具错误逐条列出这三处；Agent 读了那一段、改掉正文、补上出处再交，这一问以答案结束，记录状态为已答。分两次读完 `38.1-38.20` 与 `38.21-38.40` 后引用 `38.1—38.40` 通过；少读其中一段则被退回。
4. **提醒（确定性）。** 模型连续三次运行都不调 `answer`（其中一次以输出到上限结束）：程序提醒两次后以 `no_answer` 失败，退出码 4，记录状态为失败、没有答案。第一次运行以模型出错结束时不提醒，直接以 `model_failed` 失败。
5. **全读（确定性）。** P = 100 时把 `fullReadMaxChars` 设得小于原文字数，`--mode full` 在没有任何模型请求的情况下以 `full_read_unavailable` 失败；设得足够大时第一条用户消息含 P 以前每一段原文，交卷引用任何 P 以前的段落都不因“没读过”被退回。
6. **取消（确定性）。** 模型请求进行中向 `ask` 进程发中断信号：进程以 130 退出，`nbstory qa` 列出一条状态为“中断”、没有答案的记录。
7. **记录与一代（确定性）。** 问一问 → 删除这本书 → 同 id 重新导入：`nbstory qa` 不列出那条记录，`nbstory qa <id>` 得到 `qa_record_not_found`。一问运行期间：只删除书；删除后同 id 重新导入；重新导入后另一问先在新一代写下记录。三种情况下这一问都照常交卷，记录都不保存，书库里没有这本书时也不会多出书目录，新一代只列出另一问的记录。
8. **密钥（确定性）。** 用一个可辨认的假密钥跑场景 3（请求发往本机的 OpenAI 兼容端点）：端点收到这个密钥，而记录、会话日志、标准输出与标准错误里都没有它。端点回 401、错误正文里带着这个密钥时：以 `model_failed`（`auth`）失败，记录、会话日志与输出里仍没有它。
9. **回归（真实模型）。** 作答模型 gpt-6-luna，判分用判分器 v2 的一审，题与标准答案用两步法评测时的版本，每题按它要求的阅读位置提问，前两批做法为图当目录：
   1. 第 21 到 100 章的 56 题各答 3 次，共 168 份，一审答错不超过 33 份（基线 33/168，约 19.6%）；
   2. 知情、身份 16 题各答 3 次，一审答错不超过 11/48；
   3. 全读答知情、身份 16 题各一次，只记录结果，不设门槛；
   4. 每题记下读过的章数、被退回的次数、用量与费用；
   5. 三批都要完整：任何一份没答、没判分，或答案没有出处、提到阅读位置之后的内容，这次回归不算通过。

Smoke：在真实书库上用 100 章样例书与真实模型跑 `nbstory ask` 一问（图当目录），答案带出处、记录可以用 `nbstory qa` 列出与显示。
