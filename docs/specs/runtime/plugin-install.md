# 插件安装、卸载、升级、兼容与安全模式

## 目标与非目标

用户从本地文件夹安装第三方插件，不修改 NeuroBook 源码、不重新构建。安装、卸载、升级与启用、禁用都写入插件登记表，在下一次启动时生效；运行中即时生效（含热升级）由 [`runtime.plugin-hot-plug`](plugin-hot-plug.md) 在本能力之上提供。不兼容或损坏的插件不影响其它插件；插件拖垮启动时可以用安全模式恢复。

明确不承诺：

- 不做插件市场、在线分发、签名与权限；信任所有插件（[ADR 0027](../../adr/0027-builtin-and-third-party-plugins-are-equal.md)）。
- 内置插件不可安装、卸载、单独升级，也不能启用或禁用；它们随 NeuroBook 升级（NeuroBook 升级需要重启）。
- 不回滚插件自己迁移过的数据；升级后新版本激活失败时不自动回到旧版本。
- 不支持多个用户各自安装插件：服务端部署时插件集合对整个实例生效。

## 术语与参与者

- **产品版本**：NeuroBook 应用的版本，semver。`engines.neurobook` 按它检查；内置插件的版本等于它。
- **安装目录**：`<State Root>/plugins/<插件 id>/<版本>/`，一个版本一个目录。
- **插件登记表**：`<State Root>/plugins/plugins.json`，记录每个已安装第三方插件的 id、当前版本、待切换版本（没有时为空）与用户状态（已启用、已禁用或卸载中）。未出现在表中的第三方插件为“未安装”。内置插件不进入登记表。
- **待生效变化**：已写入登记表、要到下一次启动才生效的变化：重启后启用、重启后禁用、重启后升级到某版本、重启后卸载、重启后安装。
- **插件管理接口**：内置插件 `nbook.plugins` 经远程服务（[远程服务与 RPC 协议](plugin-channel.md)）提供的接口：列表、安装、启用、禁用、卸载。命令行 `nbook plugin …`（[`runtime.cli`](cli.md)）离线做同样的操作、用同样的失败码，不经服务端。
- **插件所有者**：启用认证时为 `admin` 角色的用户；未启用认证时（本机单用户）为本机访问者。
- **安全模式**：本次启动不加载任何第三方插件代码的启动方式。
- **升级**：已安装插件换到另一版本（含降级），下一次启动生效。

## 输入与前置条件

- 列表对已登录用户可见；安装、启用、禁用、卸载与升级只允许插件所有者执行，其它用户得到 403。操作对整个实例生效。
- **安装的输入**是服务端可读的一个本地文件夹路径，文件夹根目录有插件清单 `package.json`。Desktop 由本机文件选择器取得路径；服务端部署时路径位于服务器上。
- 复制范围：清单有 `files` 字段时按 npm 的规则复制：每项是相对插件文件夹的 glob，命中目录时递归包含其全部内容，`!` 开头的项排除；npm 总是包含的文件照样包含（`package.json`、根目录的 README、LICENSE 或 LICENCE、`main` 与 `bin` 指向的文件）。不支持 npm 的扩展 glob（例如 `+(dist|lib)`），写了时安装以 `manifest-invalid` 拒绝。没有 `files` 时复制整个文件夹。两种情况都排除 `node_modules` 与 `.git`。复制后必须包含全部入口文件，以及清单 `l10n.locales` 列出的全部消息目录 `locales/<语言>.json`（[`runtime.plugin-manifest`](plugin-manifest.md) 输出 12）。
- 路径边界：`files` 中的项必须是相对路径且不越出源文件夹；复制范围内的任何路径（包括路径中间的目录）是符号链接时安装被拒绝，被排除项剪掉的路径不在范围内；源文件夹不得位于 `<State Root>/plugins/` 之内。
- 插件 id 已安装、版本不同时，安装请求按升级处理；版本与当前版本或待切换版本相同时拒绝（“已安装相同版本”），开发者需要提高版本号，或先卸载、重启后再安装。插件处于卸载中时，安装同一插件被拒绝，提示先重启。
- 安全模式由环境变量 `NEURO_BOOK_SAFE_MODE=1` 开启；`nbook start --safe-mode` 以它启动（[`runtime.cli`](cli.md)）。

## 输出与可观察行为

1. **列表。** 返回全部内置与第三方插件：id、版本、来源（内置或第三方）、用户状态、待生效变化、汇总运行状态与原因（见 [`runtime.plugin-manifest`](plugin-manifest.md)），以及不登记的原因：`manifest-invalid`（清单无效）、`entry-missing`（安装时有的入口文件不见了，与安装时同一个码）、`unreadable`（读不了安装目录）、`incompatible-engine`（不兼容）、`safe-mode`（安全模式未加载）。内置插件标为内置，不提供启用、禁用与卸载操作。
2. **安装。**
   1. 校验清单（[`runtime.plugin-manifest`](plugin-manifest.md) 的全部规则）与 `engines.neurobook`；第三方 id 以 `nbook.` 开头时拒绝。清单有 `l10n` 时，预览与安装都按 [`runtime.plugin-manifest`](plugin-manifest.md) 输出 12 检查源文件夹里的每份消息目录，有问题时以 `catalog-invalid` 拒绝，详情逐条列出文件、键路径与原因；安装在复制完成后再检查一次复制结果，所以 `files` 漏了目录文件时安装以 `catalog-invalid` 拒绝（预览只看源文件夹，看不出这一种）。启动时不再检查目录：安装之后目录坏了或不见了，插件照常登记，问题由取目录的窗口报告（[`runtime.browser-host`](browser-host.md) 输出 8）。
   2. 安装确认界面必须说明完全信任的后果：插件可以访问全部作品、服务器与本机资源。命令行安装时打印同一句说明，执行命令本身算确认；降级或有插件会受阻时要 `--yes`（[`runtime.cli`](cli.md)）。
   3. 用户确认后复制（不链接）到安装目录，写入插件登记表为已启用。本次运行中插件不登记、不激活；下一次启动时登记并按激活事件激活，声明层在服务端与所有窗口出现。
3. **卸载**（只限第三方插件）。确认界面让用户选择是否同时删除插件的私有存储、配置与密钥（默认保留）。确认后登记表把插件标为卸载中，并记下是否删除私有数据；本次运行中插件照常。下一次启动时不加载它，删除安装目录与（按记录）私有数据，最后移除记录；依赖它的入口以 `missing-service` 受阻。
4. **启用与禁用。** 写入登记表，下一次启动生效：重启后启用的插件登记并按激活事件激活；重启后禁用的插件不登记，依赖它的入口以 `missing-service` 受阻。内置插件的启用、禁用请求被拒绝（`builtin-fixed`）。
5. （已删除：热升级移至 [`runtime.plugin-hot-plug`](plugin-hot-plug.md) 输出 10。重启生效的升级见第 8 条。）
6. **不兼容与无效插件。** 不登记，原因可在列表中查询；其它插件与内置插件照常。NeuroBook 升级后变得不兼容的已安装插件在启动时不登记，用户状态保持不变，重新兼容后自动恢复。
7. **安全模式。** 第三方插件的代码与声明都不加载，在列表中显示为“安全模式未加载”；用户可以在安全模式下禁用或卸载它们（写入插件登记表，下一次启动生效），但不能激活。界面持续显示“安全模式”标识。内置插件照常运行。
8. **升级。**
   1. **准备：** 新版本复制到自己的版本目录，与旧版本并存；校验清单与 `engines.neurobook`。确认界面列出重启后会新受阻的插件与原因，与重启后内核的判定一致：依赖它的插件在 `pluginVersions` 中声明的范围不接受新版本；新版本不再在依赖方的运行位置提供它要的服务；依赖成环；以及经这些插件传递受阻的。升级禁用的插件不列（重启后它仍不登记）。版本低于当前版本时，确认界面另外提示降级可能遇到新版本已迁移过的数据。
   2. **记下：** 用户确认后登记表记下待切换版本，用户状态不变；本次运行中旧版本照常。待切换期间再安装另一个版本时，它取代原待切换版本：登记表先改记它为待切换版本，之后才删除原待切换版本的目录。
   3. **切换：** 下一次启动时，先把登记表改指新版本，再按新版本的清单登记；旧版本目录在切换后删除。已禁用的插件只切换文件与登记，不激活。
   4. **数据：** 私有存储、配置与密钥跨版本保留。数据格式的迁移由插件自己完成；激活时 SDK 提供上一次成功激活的版本号（首次安装为空，[`runtime.plugin-api`](plugin-api.md)）。
9. **生效时机可见。** 插件管理界面写明安装、卸载、升级、启用与禁用在下一次启动后生效；有待生效变化时，列表在对应插件上显示它，并提示重启。
10. **显示名与问题。** 列表的每一项另带清单的显示名与说明（`displayName`、`description`，内置插件与没写的为空），以及服务端实例此刻的问题：入口激活失败（阶段、原因与错误消息）、入口受阻（原因与缺的服务）、贡献被拒（贡献点、贡献 id、原因与说明）。浏览器一侧的问题由各窗口经 `window.plugins.problems()` 查本窗口的（[`runtime.browser-host`](browser-host.md)）。插件页在 id 旁边写显示名、下面写说明（内置插件的名称与说明由插件页按界面语言给出），有问题的插件标出问题数并逐条列出原因（服务端的是打开页面时的快照，本窗口的随变化更新）；没有的不占位。作者装上插件后不开控制台就能看到“为什么没出现”。

## 状态与转换

| 当前用户状态 | 事件 | 下一状态 | 说明 |
|---|---|---|---|
| 未安装 | 安装成功 | 已启用 | 下一次启动时登记并按激活事件激活 |
| 未安装 | 安装相同 id 与版本 | 不变 | 拒绝 |
| 未安装 | 安装校验失败或用户取消 | 未安装 | 不留下任何文件或登记表记录 |
| 已启用、已禁用 | 卸载 | 卸载中 | 下一次启动时删除并移除记录，之后为未安装 |
| 已启用 | 禁用 | 已禁用 | 下一次启动时不登记 |
| 已禁用 | 启用 | 已启用 | 下一次启动时登记 |
| 已启用、已禁用 | 升级（安装另一版本） | 保持原用户状态，记下待切换版本 | 下一次启动时切换 |
| 任意 | 启动时不兼容或清单无效 | 用户状态不变，不登记 | 原因可查询 |

- 同一插件的安装、升级、卸载、启停请求串行执行；执行中收到的同一插件的新请求等待前一个完成。
- 在同一次运行中，启用与禁用互相覆盖：例如禁用后再启用，重启后为已启用。卸载与待切换版本不能撤销，要撤回只能重启后再操作（卸载后重新安装、升级后安装旧版本）。
- 插件登记表的写入是原子的：读者只看到完整的旧表或新表。服务端运行时命令行（`nbook plugin`）同时修改登记表，各自的修改都保留，不互相覆盖；一个进程正在准备、尚未提交的安装不会被另一个进程当作残留删除。
- 每个操作有一个提交点，重启后以登记表为准：

| 操作 | 提交点 | 提交前中断，重启后 | 提交后中断，重启后 |
|---|---|---|---|
| 安装 | 复制与校验完成后写入登记表 | 未安装；残留目录删除 | 已安装并按用户状态登记 |
| 升级 | 新版本复制与校验完成后，登记表记下待切换版本 | 旧版本；新版本目录作为残留删除 | 按“升级”第 3 步切到新版本 |
| 替换待切换版本 | 登记表改记新的待切换版本 | 原待切换版本保留；新版本目录作为残留删除 | 新的待切换版本；被取代的目录作为残留删除 |
| 启动时切换版本 | 登记表改指新版本 | 仍有待切换版本，重新切换 | 新版本；旧版本目录作为残留删除 |
| 卸载 | 登记表把插件标为卸载中，并记下是否删除私有数据 | 保持原状态 | 不加载该插件，继续删除安装目录与（按记录）私有数据，最后移除记录 |

## 副作用与数据

- 写入 `<State Root>/plugins/<插件 id>/<版本>/` 与 `<State Root>/plugins/plugins.json`。
- **运行中的版本目录。** 一个状态根只跑一个服务端（[`runtime.server-host`](server-host.md) 的“实例认领”）。运行中的服务端只用登记表里各插件的 `version`，它只在启动时切换；运行期间的安装、升级与卸载只写登记表与新的版本目录，不删、不改在用的目录（被取代的待切换版本从未被加载过）。所以服务端运行期间按需装载入口代码、经文件端点读文件不会找不到文件。
- 插件的私有存储、配置与密钥的位置与格式归 [`runtime.plugin-api`](plugin-api.md)；卸载时按用户选择删除。
- 插件写入作品的内容属于用户数据，任何操作都不删除。
- 安装、卸载、升级、启动时切换版本各写一条诊断记录（插件 id、版本、结果、原因）。

## 失败与恢复

插件管理接口的业务失败码。每个方法只返回自己的那一组：列表只有 `registry-failed`；预览与安装是 `manifest-invalid`、`catalog-invalid`、`incompatible-engine`、`already-installed`、`uninstall-pending`、`path-rejected`、`entry-missing`、`copy-failed`、`registry-failed`；启用、禁用与卸载是 `builtin-fixed`、`not-installed`、`uninstall-pending`、`registry-failed`。

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `manifest-invalid` | 清单不存在、不是合法 JSON 或不符合 [`runtime.plugin-manifest`](plugin-manifest.md)（包括第三方 id 用了保留的发布者 `nbook`），详情给出出错字段 | 修改插件清单后重试 |
| `catalog-invalid` | 清单 `l10n` 列出的消息目录缺失、不是合法 JSON 或内容不符合 [`runtime.plugin-manifest`](plugin-manifest.md) 输出 12，详情逐条给出文件、键路径与原因；已复制的部分已删除 | 修改目录文件或 `files` 后重试 |
| `incompatible-engine` | `engines.neurobook` 不接受产品版本 | 换兼容的插件版本 |
| `already-installed` | 同一 id 与版本已安装或待切换 | 提高版本号，或卸载、重启后再装 |
| `uninstall-pending` | 插件处于卸载中 | 重启后再安装 |
| `path-rejected` | 源文件夹不存在、位于 `<State Root>/plugins/` 之内、`files` 越出源文件夹或复制范围内的路径含符号链接 | 修正路径或插件内容 |
| `entry-missing` | 复制范围内缺少入口文件 | 检查 `files` 与构建产物 |
| `copy-failed` | 复制中途失败（磁盘满、权限、源文件被移除），已复制的部分已删除 | 排除原因后重试 |
| `not-installed` | 操作的第三方插件未安装 | 刷新列表 |
| `builtin-fixed` | 对内置插件执行启用、禁用或卸载 | 无 |
| `registry-failed` | 插件登记表读不了、结构不符合，或写入失败（含拿不到写入锁）；本次操作没有生效，已复制的目录已删除 | 查看服务端诊断，排除原因后重试；登记表结构损坏时修复或移走它 |

- **登记表写入失败**：本次操作失败，已复制的目录删除，登记表与运行状态回到操作前。
- **进程在安装、升级、卸载或启动时切换中途崩溃**：按上表的提交点恢复；登记表中没有记录的版本目录视为残留并删除；登记表指向的版本目录缺失或清单无效时，该插件以“清单无效”不登记，用户可以卸载。
- **新版本在启动后激活失败**：按 [`runtime.plugins`](plugins.md) 的失败处理，不自动回到旧版本；用户可以安装旧版本（降级）。
- **安全模式外的启动被第三方插件拖垮**：用户以安全模式启动后禁用或卸载该插件；反复卡死时的自动进入见 [`runtime.stall-watchdog`](stall-watchdog.md)。

## 边界与兼容

- **owner**：runtime（加载器与安装）。清单规则归 `runtime.plugin-manifest`，运行中即时生效归 `runtime.plugin-hot-plug`，代码装载归 `runtime.plugin-code-loading`。
- **信任与授权**：信任所有插件，安装即授予插件完全信任；安装确认界面是唯一的告知点，不可跳过。服务端部署时只有插件所有者（部署者的 `admin` 身份）能安装与管理插件。
- **路径**：安装只接受服务端本地路径，不接受 URL，不从网络下载。
- **兼容**：`<State Root>/plugins/` 的目录布局与 `plugins.json` 是持久格式，变化时需要迁移说明。第三方 id 不得以 `nbook.` 开头，保证内置插件的命名空间。产品版本的兼容承诺见 [`runtime.plugin-api`](plugin-api.md)。
- **迁移**：现有 State Root 没有 `plugins/` 目录，首次需要时创建；不影响现有用户数据。

## 验收与 Smoke

1. **从本地文件夹安装。** Given 一个位于产品源码之外、已构建的示例插件文件夹；When 安装并确认；Then 重启前列表显示“重启后安装”，插件的声明不出现；重启后出现其命令菜单、视图、Agent 工具与设置项；`<State Root>/plugins/<id>/<版本>/` 中没有 `node_modules`。
2. **拒绝不合格插件。** 清单无效、`engines.neurobook` 不兼容、id 以 `nbook.` 开头的文件夹安装失败，得到对应失败码，不留下目录与登记表记录。
3. **卸载。** 卸载后重启：插件的全部声明消失，安装目录被删除；选择保留数据时私有存储仍在，重新安装并重启后插件读到原数据。
4. （已删除：热升级成功移至 [`runtime.plugin-hot-plug`](plugin-hot-plug.md) 场景 12。）
5. （已删除：热升级回滚移至 [`runtime.plugin-hot-plug`](plugin-hot-plug.md) 场景 13。）
