# 剧情图谱（暂名）第一版：查看器、问答、命令行与 Skill

开发者看过要点后同意本设计，并定了第七节的六件事（见第八节决策记录）。实现前还要写 `planned` Spec；本文不能作为当前行为的依据。

数据来自 [V9 小说记忆图](novel-memory-v9.md)：第一版直接用 w00005 t34 已经抽好的前 100 章，不做抽取。

## 一、问题

V9 图已经能自动抽出来，但只有开发用的东西能看它、用它：

- 查看器（t28）是一个开发工具：9 个页签平铺，数据整份塞进页面，没有搜索，出处只是编号；书一长页面就装不下。
- Agent 用它要靠评测脚本把图导出成一堆文本文件，再在 Linux 沙箱里跑 grep；换一台机器、换一个 Agent 都用不了。
- 问答的两种做法（全读、图当目录）只在评测脚本里，普通用户没有入口。

开发者 2026-10-13 的要求：

1. 先不做抽取，用现有已经抽好的 100 章数据。
2. 要能单独使用，也要能作为插件集成进 NeuroBook；要有命令行和网页。
3. 这一版要做的：查看器（看图和数据，用起来要顺手）；命令行加 Skill，给 Agent 用；问答界面（和查看器是网页里的同一套）。抽取和管理先不做；做成 NeuroBook 插件后给 Agent 提供工具，也是以后的事。

## 二、目标与非目标

目标：

- 一份核心，四个入口：命令行、网页查看器、网页问答、Agent Skill。以后加第五个入口 NeuroBook 插件时，核心、接口和网页页面都不用重写。
- 所有入口都按“读到哪里”显示：只给出读到这个位置为止的内容，不剧透后文。
- 每条记录都能一步回到原文核对。
- 长书也能用：网页按需向服务取数，不把整本书和整张图塞进页面。

非目标（这一版不做）：

- 抽取、重新抽取、导入新书的抽取流程；书库管理（改名、删除以外的操作）。
- 人工修正图里的记录。
- NeuroBook 插件本身（清单、入口、视图贡献、Agent 工具贡献）。
- 打包发布：第一版只从仓库运行，不进 Product、Desktop 发布产物。

t34 的结论决定了问答的做法：100 章以内全读最准；放不进一次请求时用“图当目录、读整章”，按记录补章时不补秘密记录的出处章（提案第十二节 12.10 小节）。作答规则用 v5：t34 第四轮在 16 道知情、身份题上，v5 让图当目录的答错从 41.7% 降到 25.0%，和全读持平，全读的变化在波动之内；v5 对靠猜测或情境推断知道的情况偏保守，规则要补一句，随问答回归一起测（提案第十二节 12.11 小节）。

NeuroBook 这边（master）：插件系统的 Spec 已经写好、大部分还是 `planned`，分三个阶段实施。插件用 `package.json` 声明服务端和浏览器两种入口；浏览器入口经“插件通道”调本插件的服务端，通道是一份 zod 写的方法清单，HTTP 形式是 `POST /api/plugins/<插件 id>/rpc/<方法名>`（master 上的 `docs/specs/runtime/plugin-manifest.md`、`plugin-channel.md`）。仓库里已有一个“核心库加命令行加网页”的先例：开发者面板 `packages/dev-panel`（命令 `nbdev`，Bun 服务，Vue 3 加 nb-ui 的页面）。

## 四、方案

### 1. 产品形态：一份核心，四个入口

| 入口 | 给谁 | 用来做什么 | 第一版 |
| --- | --- | --- | --- |
| 命令行 `nbstory` | 人和 Agent | 查对象、称呼、谁知道什么、数值、悬念、时间线、原文；提问；启动网页 | 做 |
| 网页：查看器 | 人 | 浏览图，拨“读到哪里”防剧透，点出处回原文 | 做 |
| 网页：问答 | 人 | 提问，看答案、依据和读了哪些章 | 做 |
| Skill | Claude Code、Codex 等 Agent | 教 Agent 用命令行查图、按“图当目录”答题 | 做 |
| NeuroBook 插件 | NeuroBook 用户和产品 Agent | 工作台里的查看器、问答两个视图，Agent 工具 | 以后 |

单独使用时：`nbstory serve` 启动本机服务，打印一个登录链接，浏览器打开就是查看器和问答。

### 2. 架构

```text
                    接口合同（方法清单，每个方法的参数和结果都有 schema）
                 ┌──────────────────────┴───────────────────────┐
                 │                                              │
   网页页面（Vue 3 + nb-ui）                           以后：NeuroBook 插件
   只经 client.call(方法, 参数) 取数                    服务端入口 ctx.channel.handle(同一份合同)
                 │                                     浏览器入口复用同一批网页页面
                 ▼
   独立服务（Bun，nbstory serve）
   POST /api/rpc/<方法>，托管网页产物
                 │
                 ▼
   核心库：书、按阅读位置查询、搜索、本章变化、问答引擎（模型经注入的端口调用）
                 ▲
                 │
   命令行 nbstory（直接调核心库，不经 HTTP）  ◀──  Skill（教 Agent 调命令行）
```

五层的规矩：

1. **核心库**：纯 TypeScript，只用 Node 兼容的接口，不碰界面，也不读密钥文件。模型调用经注入的端口，谁装配谁给模型（单独使用时是命令行和独立服务，以后是插件）。
2. **接口合同**：一份方法清单，网页只经它取数；独立服务按它提供 HTTP；以后插件通道按它提供 `ctx.channel.handle`。独立服务的错误格式也照插件通道的 `{code, message}`，网页换宿主时不用改。插件重构分支（w00017，`refactor/w00017-runtime-foundation`，即将合入 master）里的示例插件用 typebox 写合同，经 `@notnotype/nb-runtime/remote` 的 `defineRemoteService` 声明；本合同在 w00017 合入后照这个写法，不另起一套。
3. **独立服务**：只监听本机，启动时生成带口令的登录链接（照 nbdev 面板的做法），托管网页产物，按合同回答。
4. **命令行**：直接调核心库；只有 `serve` 才加载服务代码。默认输出给人读，加 `--json` 给程序和 Agent。
5. **网页**：Vue 3 加 nb-ui，Vite 构建，和 NeuroBook 用同一套组件。页面组件不自己发请求，只用注入的 client；单独使用的外壳负责路由和 client，以后插件的浏览器入口复用同一批页面组件，只换 client。

建议放在一个新包里（暂名 `packages/nb-story`），目录照 dev-panel：`src/core`、`src/contract`、`src/server`、`src/cli`、`src/web`、`skill/`。核心库的类型检查单独一份配置，挡住 Bun 专有接口和界面代码。以后插件要单独引用核心库时，再把核心拆成独立的包。

### 3. 数据：书库和“读到哪里”

一本书是一个目录：

```text
<书库>/<书 id>/
  book.json     书名、章数、图的数据版本、来源（第一版写 t34 run-med-100）
  graph.json    编译好的 V9 图，含原文
  qa/           问答记录，每问一份
```

- 书库默认放在用户数据目录（Linux 是 `~/.local/share/nbstory/`），也可以用 `--library` 指定。第一版用 `nbstory import <dataset-v9.json> --title <书名>` 把 t34 的数据收进书库。以后在 NeuroBook 里，书放在 Project 的数据目录。
- 原文和图是本地文件，不进仓库。
- **读到哪里**：所有查询都带一个位置参数 `at`（第几章，或第几章第几段），不给就是读到最后。过滤在核心库里做，网页和 Agent 拿到的结果已经不含后文，不靠页面自己隐藏。

### 4. 接口合同里的方法（第一版）

| 组 | 方法 | 返回什么 |
| --- | --- | --- |
| 书 | `books.list`、`book.info` | 书库里的书；书名、章数、来源、各类记录的数量 |
| 本章 | `chapter.digest` | 这一章的情节概括、新出现的对象、揭晓的秘密、数值变动、新提出和被解答的悬念 |
| 对象 | `entities.list`、`entity.card` | 名册（按出场次数排序，可按类别和名字筛）；人物卡：全部称呼和首次出现、读者此时知道的同一身份、他知道和不知道的秘密、参与的情节、相关数值、关于他的说法 |
| 秘密 | `secrets.matrix` | 秘密乘以人物（含读者）的表，每格是知道、怀疑、不知道或没有记录，附依据段落 |
| 数值 | `ledger.tracks`、`ledger.track` | 每个数值的逐章余额和逐笔流水，原文给出余额处的核对结果 |
| 悬念 | `questions.list` | 未解、部分解答、已解答，以及从提出到解答的过程 |
| 时间线和情节 | `timeline`、`episodes` | 按故事先后的时间点（标出回忆、补叙）；按章的情节、在场者、和前情的连接 |
| 原文 | `source.read` | 指定章段的原文和前后文，以及每段对应的记录 |
| 搜索 | `search` | 按名字、称呼、说法、原文搜，结果分类给出 |
| 问答 | `qa.ask`、`qa.progress`（订阅）、`qa.history`、`qa.get` | 见下面的问答一节 |

每个结果里的出处都带“章.段”编号；网页把编号做成可点的链接，命令行在 `--json` 里给出编号和查看器链接。

### 5. 查看器：怎样做到用起来顺手

t28 是给开发者核对设计用的：9 个页签平铺；名册按首次出现排序，舍友、导购员和主角并列；秘密是一张表接一张表；出处只是编号；没有搜索，没有链接地址。产品版按下面几条重做（首页、默认收起、问答位置、尺寸、沿用的机制已在 w00024 t01 第 1 轮评审里定下，见该 Task 的 README）：

1. **防剧透放第一位**：顶栏常驻“读到第几章”（下拉选章、拖动条、上一章和下一章），默认读到最后；所有页面、搜索和人物卡只显示到这里。
2. **以人物为中心**：任何地方出现的名字都能点开人物卡，人物卡在右侧抽屉里打开，不离开当前页面。
3. **原文随手可查**：任何出处编号（例如 37.8）点开，右侧显示那几段原文和前后各几段，名字带底色。
4. **先看重要的**：名册按出场次数排序，主要人物在前；路人收进“次要”一栏，默认折叠。
5. **每个画面都有地址**：复制链接就能回到同一本书、同一页、同一个人物、同一个阅读位置；命令行和 Agent 也能给出这种链接。
6. **像 IDE 一样的面板**：左侧导航、主区、右侧抽屉之间可以拖拽改变宽度，也可以收起；用 nb-ui 的嵌套 grid 和分隔条搭，规则照 NeuroBook 工作台外壳。
7. **回到上次的界面**：再次打开一本书时回到上次的页面、人物和阅读位置；第一次打开进入全书总览。

页面布局（示意）：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 书名               读到 [第 37 章 v]  < ━━━━━━━●━━━━━ >      [搜索人物、称呼、说法、原文] │
├────────────┬───────────────────────────────────────────┬─────────────────────┤
│ 本章       │                                           │ 右侧抽屉（可关）       │
│ 人物       │                主区域                       │ 人物卡，或出处原文     │
│ 秘密       │                                           │                     │
│ 数值       │                                           │                     │
│ 悬念       │                                           │                     │
│ 时间线     │                                           │                     │
│ 情节       │                                           │                     │
│ 原文       │                                           │                     │
│ ────────   │                                           │                     │
│ 问答       │                                           │                     │
└────────────┴───────────────────────────────────────────┴─────────────────────┘
```

各页：

- **全书总览**（第一次打开时的首页）：主要人物、秘密矩阵、未解悬念数、数值余额。
- **本章**：读到的这一章发生了什么，新出现了谁，揭晓了什么，数值怎么变，哪些悬念被提出或解答。读完一章回顾时看这里。
- **人物**：名册（人物、化身和代号、组织、地点、物品分组）加人物卡。
- **秘密**：一张矩阵，一眼看出谁知道什么；点格子看依据段落。

  ```text
  秘密（读到第 71 章，示意）      读者   苏天晴   南小风   花铃   南嘉鱼   林沐瑶
  风信子就是南小风                知道   知道     ——      知道   不知道   知道
  心月狐就是苏天晴                知道   ——      不知道   ……
  ```

- **数值**：每个数值一条随章变化的折线（例如神典石余额），下面是逐笔流水。
- **悬念**：未解、部分解答、已解答三栏，每条可以展开看从提出到解答的过程。
- **时间线**、**情节**：沿用 t28 的内容，改成可筛选的列表。
- **原文**：阅读器，名字可点，段落旁标出这一段有几条记录。

图是自动抽取的，会有错（提案第十二节 12.11 小节列了实例）。页脚常驻一句“自动抽取，以原文为准”，标了“推断”的记录照样显示标记。“说明与统计”页沿用（开发者 2026-10-13 定）。这一版不做改错。

### 6. 问答

流程：

1. 用户输入问题；阅读位置默认取顶栏的“读到哪里”，也可以单独改。
2. 两种做法都可以选，默认“图当目录”（开发者 2026-10-13 定）：挑章 Agent 在图里找出至多 20 章，不补秘密记录的出处章，再只凭这些章的原文作答。用户可以改选“全读”：把读到的原文整段放进一次请求，更准也更贵；原文超过上限（可配置，默认约 20 万 token）时这一项不可选。
3. 进度分步显示：在图里找相关记录（列出找到的）、读第几章、作答中。
4. 答案显示结论和展开、依据编号（点开看原文）、结论类型（明说、推断、无法确定）、读了哪些章、费用和用时。
5. 每本书保存问答历史，每条有链接地址。

和实验相比要改的一处：评测里的挑章 Agent 是在 Linux 沙箱里跑真实 shell（grep、sed），只能在 Linux 上用，产品里也不该让模型执行命令。产品改成进程内的只读工具：按名字查对象、在图里搜记录、按章段读原文、在原文里搜关键词。工具变了，挑章的表现可能跟着变，要用 t34 的题回归：一审答错不比 t34 第三轮去掉秘密章后的 19.6% 差。

模型：单独使用时，配置文件写模型服务地址、模型名，以及保存密钥的环境变量名；密钥只由程序读出交给 HTTP 客户端，不写进书库、日志、页面和问答记录。以后在 NeuroBook 里，改用 NeuroBook 的模型角色和插件的配置与密钥接口。

### 7. 命令行与 Skill

```text
nbstory books                                   列出书库里的书
nbstory import <dataset-v9.json> --title <书名>  把抽好的图收进书库
nbstory chapter <章>                            这一章的变化
nbstory find <名字或称呼> [--at 37]              找对象：全部称呼、身份、首次出现
nbstory card <对象> [--at 37]                    人物卡
nbstory knows [<对象>] [--secret <秘密>] [--at 37]  谁知道什么
nbstory ledger [<数值>] [--at 37]                数值和流水
nbstory questions [--open] [--at 37]             悬念
nbstory timeline [--from 30 --to 40]            时间线
nbstory search <文字> [--at 37]                  搜说法和原文
nbstory read <章.段[-段]>                        读原文
nbstory ask "<问题>" [--at 37] [--mode index|full]    提问，默认 index（图当目录）
nbstory serve [--port <端口>] [--open]           启动网页，打印登录链接
```

- 书库里只有一本书时不用写 `--book`；所有命令都支持 `--json`。
- 命令行和网页调的是同一个核心库，同一个问题、同一个阅读位置，结果一样。

Skill（`skill/SKILL.md` 加参考文件）写给 Agent：

- 什么时候用：用户问书库里某本小说的剧情、人物、谁知道什么、数值、悬念。
- 怎么跑：`bun <skill 目录>/bin/nbstory.ts <命令>`，照 llmlint Skill 的写法。
- 答题步骤：先 `find` 查清对象的全部称呼；按题型用 `knows`、`ledger`、`questions`、`timeline` 找线索；再 `read` 读相关章段核对；答案引用“章.段”。谁知道什么的题按作答规则 v5：旁白点破、读者读到的内心只说明读者知道；角色知道要写出他在场看到、被告知、看到消息或视频、或自己推断的段落。
- 提醒：图是自动抽取的，结论以原文为准；用户说了读到哪里，就一律带 `--at`，不剧透。

### 8. 以后接入 NeuroBook

| 插件里的部分 | 对应本设计的什么 |
| --- | --- |
| 服务端入口（`channel: true`） | 把同一份接口合同交给 `ctx.channel.handle`；书放在 Project 的数据目录 |
| 浏览器入口 | 贡献“剧情图谱”“问答”两个视图，复用网页页面组件，client 换成 `ctx.channel` |
| Agent 工具贡献 | `find`、`card`、`knows`、`ledger`、`questions`、`read`、`ask` 一一对应 |
| 模型和密钥 | NeuroBook 的模型角色；插件 API 的配置与密钥 |

NeuroBook 的插件系统大部分 Spec 还是 `planned`，插件接入要等它落地。本设计只保证接口合同和页面组件可以直接搬过去。

### 9. 备选方案和取舍

- **查看器继续做成单个离线页面（t28 的路子）**：最省事，但整本书和整张图都要塞进页面，100 章已经 2.9 MB，书再长打不开；问答也要服务端。不取。
- **网页用原生脚本或另一套框架**：做出来快，但以后要嵌进 NeuroBook 得重写。用 Vue 3 加 nb-ui，和 NeuroBook、dev-panel 一致。
- **命令行经 HTTP 调独立服务**：Agent 每次查询都得先启动服务。命令行直接调核心库，只有网页需要服务。
- **一开始就拆成核心包和应用包**：边界更硬，但现在只有一个使用方，先放一个包、分目录、类型检查分层。

## 五、数据、接口、安全、迁移、发布与回滚影响

- 新增一个包，不改 NeuroBook 主应用、数据库和现有 Spec。
- 数据是本地文件；小说原文、图和问答记录都在书库目录，不进仓库。
- 独立服务只监听本机，凭登录链接里的口令访问。
- 模型密钥只从配置指定的环境变量读出交给 HTTP 客户端，不进命令行参数、日志、页面、问答记录和错误正文。
- 第一版只从仓库运行，不发布；没有迁移，回滚就是删掉这个包。

## 六、对 Spec 的预期改动

接受后新增几份 `planned` 规范：书与按阅读位置的查询（核心库和接口合同）、查看器、问答、命令行与 Skill。master 的 `docs/specs/` 现在没有记忆相关的分区，放在哪里待定。验收：

- 核心库：同一位置的查询不含后文（按 t28 的做法拨回阅读位置核对），命令行和接口结果一致。
- 查看器：自动浏览器检查页面报错 0、联网请求 0、窄屏可用，加开发者人工试用。
- 问答：用 t34 的题回归，一审答错不比 19.6% 差；其中知情、身份 16 题一审答错不比 22.9% 差（t34 第四轮，规则 v5）。
- Skill：一个 Agent 只按 Skill 回答几道题，答案带出处、不剧透。
